# 0008 Concurrency + durability model
Status: accepted (principles); storage engine details -> ADR 0021
Date: 2026-10-09
Context: Scale-out: hundreds+ concurrent clients per OSD. Must scale across cores and NVMe queues without locks, without data loss, without ordering bugs.

Concurrency (lock-free by ownership, not by locking):
- Ceph semantics only require ordering per object (PG primary serializes per object; per-client order by tid per connection). No global order.
- Unit of ownership = PG. Each PG pinned to exactly one core (0006); all PG state (pg log, object contexts, in-flight ops, metadata) touched only by that core -> no locks, no atomics, no shared mutable state.
- Parallelism = many PGs x many cores x one NVMe qpair per core. Requires PGs/OSD >> cores (check pg_num/autoscaler; doc in ops guide).
- Within PG: ops pipelined; per-object in-flight state machine (writes on same object ordered, non-conflicting objects fully parallel, reads not blocked by unrelated writes). Implemented as plain single-threaded data structures.
- Cross-core: connection core != PG core -> message via SPSC ring, zero-copy buffer handoff (ownership transfer, no shared refcount).
- PG split/merge/remap between cores: explicit quiesce + handoff message; rare path, correctness over speed.
- Hot-PG risk (one PG saturates one core): measure first; no premature intra-PG sharding.

Durability:
- Ack (sub-op reply / client reply) only after data + metadata + pg log entry durable on media.
- Require NVMe with power-loss protection (Identify VWC = no volatile cache) -> write completion = durable, no flush on hot path. mkfs refuses non-PLP devices (override flag for lab only -> then FUA on every commit write).
- Every replicated/EC sub-op transaction atomic across crash (all-or-nothing: data, attrs, pg log). Never overwrite live data in place without a committed record. Mechanism (log-structured / COW / journal using NVMe atomic write unit) = ADR 0009.
- End-to-end checksums (crc32c per block, HW-accelerated) verified on read; mismatch -> EIO + let EC reconstruct + scrub repair.
- Metadata space partitioned per core/PG; allocator partitioned per core (per-core extents) -> no cross-core allocator contention.

Verification:
- Deterministic simulation tests of PG/op state machines (seeded, single-threaded = possible because of ownership model).
- Crash-consistency tests: kill -9 / power-cut emulation at random points, then verify vs expected (client-acked data must survive).
- Interop under load: hundreds of concurrent librbd/fio clients, failures injected, checked with data verification (fio verify).

Amendment 1 (VWC override, implemented): with `--allow-vwc` (device reports a volatile write cache) every durable write and write-zeroes carries the NVMe FUA bit (`nvme::write_io_flags`, `SpdkDev::submit_inner`); completion then means stable media, no separate flush path needed. PLP devices: flags 0. FileDev reports vwc=false (fdatasync per write batch). Unit test `volatile_cache_forces_fua_on_writes`; SPDK side asserts the bit value at C compile time.

Amendment 2 (send-first replicated client writes, 2026-10-15, implemented; dataflow-review-20261015 finding 5): a fresh replicated client write whose op hopped to its PG core (`XMsg::Op`) sends its repops before its local txn is queued. Mechanism: `Engine::on_op` opens a window (`Env::send_first`) around the one `process` call (its `submit_write` is its last store access); `PgEnv::run_submit` holds back a batch shaped `[Send+, Persist]` (`late`), `pg_run` ships the sends (`pg_exec`) and parks the txn in `PgHost::late`; `rt::XPort::pump` (via `Osd::on_xmsg_send_first`) moves the outbox to the rings, then `Osd::apply_late` queues it. Invariant: the store reflects every submitted write before anything else reads or writes it: `settle_late` runs at the start of `pg_run`, `pg_exec`, `on_xmsg`, `poll_store`, `on_timer`, `pump`, on any later run_actions/submit in the same env, before `copy_poll` work (`Env::settle`), and whenever the call produced non-send actions. Drivers without the window (tests calling `on_xmsg`, same-core client ops) keep the inline order. Ack unchanged: client reply needs local durable + all replica commits. Replica order unchanged (sends keep their order; local txns stay FIFO). Failure: a held-back txn the store refuses (`Rejected`, a bug: client txns are validated before logging) after its repops left fail-stops the OSD (`store_failed`, as adr 0066 / a classic primary whose apply asserts): nothing acked, replicas hold the entry, the interval change lets them serve it, the restarted primary recovers it by peering. The inline path keeps fail-closed + withdrawing the sends. `Failed` = store_failed as before. Gain: translate + tree apply + WAL/data submit (Mac ~4.3 us, x86 ~10 us) leave the primary's pre-send critical path; CPU per op unchanged (w4k Mac interleaved min of 6, loaded host: primary 13.05 -> 13.16, replica 6.63 -> 6.67, noise). Tests: `xcore_tests::send_first_*` (refusal after send, pipelined appends), all xcore tests run through the window (harness = XPort order).

Amendment 3 (send-first on every placement, 2026-10-26, doc/perf/bdir-commit-20261025.md): am. 2 only reached ops that hopped, and `pump()` settled the held txn before the driver could flush. A same-core client op (connection core == PG core) never held its txn back, and a repop whose peer link core equals the PG core waited in the local queue until the end of the iteration, so the primary's and the replica's store txns ran one after the other instead of in parallel. Decision: (1) `Osd::set_local_send_first(true)` (driver opt-in; knet core loop and `core_loop.rs` set it) makes `on_bytes` open the window (`pg.late_ok`) around its `pump()`; `pump()` does not settle the held txn inside the window. (2) The driver closes the window right after `net.poll` (and in `XPort::pump_with` for hop ops): outbox to the rings, own-core link frames out (submit only if frames were queued), then `Osd::apply_late`, on every placement and every load. (3) Every PG entry point still settles before it touches the store, so ordering and refusal handling are unchanged (am. 2 fail-stop rule). Reason: the replica's store txn runs in parallel with the primary's. Known cost: about 0.4 extra ring enters per op at QD16 (+4-5 % CPU/op on 4 KiB writes). Rejected: closing once per receive pass (invalid: the engine reads the store for every op, so each held txn must apply before the next op, read-your-writes order); a cost-based close (apply cost against enter cost: the rule fires for 4 KiB txns anyway, it does not remove the CPU). Counters `late_held` / `late_driver` (debug perf), `knet_enters_sf` (window-close enters). Drivers that do not opt in keep the inline order.
