# 0088 Owned secure messenger runs and authenticated receive storage
Status: accepted
Date: 2026-10-13
Context: performance finding 8. Secure TX copied message bodies into a contiguous ciphertext buffer; owned RX copied authenticated segments out of the decoder. Lossless sessions must keep plaintext for reconnect replay, but lossy messages are disposable.

Decision:
- Only disposable lossy secure messages use owned TX encoding. Consume their front/middle Vecs and reclaim unique Bytes data through `try_into_mut`. Drop the unused CRC hint's ownership first. Shared data is copied into private ciphertext storage and never mutated. Lossless replay keeps its existing plaintext and encoding path. Small messages keep the existing path.
- Stream each existing GCM region across disjoint owned runs using the same AWS-LC implementation already linked by aws-lc-rs. A keyed AES-128-GCM EVP context is allocated once at secure TX setup and freed on drop. All mutations require exclusive access. Use the same 12-byte nonce from `Gcm::take`, empty AAD and 16-byte tag; v2.0 seals the whole frame once, v2.1 seals preamble/inline header, optional header remainder and the combined body as before. No per-run nonce or tag, algorithm or padding change. Output is committed only after all seals succeed.
- Secure RX authenticates every required tag before owned delivery. Large frames split their receive BytesMut into immutable segment views; unread wire bytes remain in a disjoint mutable view. Frames below 8 KiB or with a backing allocation more than four times their wire size copy their segments, avoiding disproportionate retained storage. Track the original allocation across splits, not just the tail's capacity.
- Reserve known secure-frame sizes early to avoid copying an almost-complete body during late growth. Reset the size hint after owned delivery. When `BytesMut::try_reclaim` confirms reuse without allocation, expose only previously initialized tracked bytes without zeroing them again. New/untracked storage is initialized normally. This safety proof relies on the locked bytes 1.12.1 implementation: reclamation moves initialized live bytes and does not allocate/deallocate or deinitialize tracked storage. Audit this assumption when updating that dependency.
- Frame bytes, authentication failures, nonce exhaustion, session ordering, replay, CRC mode and store durability are unchanged. Retained RX storage and small TX runs add ownership metadata; these are not total RSS limits.

Validation: existing frozen frame/replay vectors, NIST GCM known-answer tag through the streaming backend, owned/reference byte equality across header/padding boundaries and both revisions, shared plaintext immutability, real lossy sends in both directions, lossless reconnect replay, authenticated RX pointer retention, growth followed by authentication failure, small-frame backing bound and reclaimed-storage initialization. Native msgr2/OSD/runtime and local Linux msgr2/kernel-runtime suites; measurements in `../perf/codex-perf3-2026-10-13.md`.
