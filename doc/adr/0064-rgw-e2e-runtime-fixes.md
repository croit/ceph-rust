# 0064 Runtime behaviour found by the RGW e2e: replica reservation pools, sliced PG deletion, wall clock, pool_stat
Status: accepted
Date: 2026-10-12
Context: RGW e2e (lab/docker/rgw/e2e.sh, mixed cluster, OSDs added under load) showed: all RGW requests stalled behind one long backfill (one replica slot, no preemption); OSDs marked down after backfills (a 150k-object PG deleted inside one call); versioned-bucket anomalies (wall stamps lagged real time up to 1 s); `ceph df` STORED/USED 0 for croit-flashstore-osd pools.
Decision:
- Replica reservations (`peering::pgset::Reservers`): two pools, backfill = `osd_max_backfills` (split over cores, >= 1 per core), log-based recovery = 4x that (>= 4). Priority ordered, FIFO within, no preemption (replication.md 7.3 minimal). A release or a raised max (runtime config, applied at the next 1 s tick) grants every free slot. Classic shares one reserver and preempts; separate pools give the same outcome (short recovery never waits behind a long backfill) without REVOKE logic. Primary side has no local reserver (unchanged).
- PG deletion: `RemovePg` sets the durable REMOVE marker and queues the PG; the core loop deletes in slices (`step_removals`, ~2 ms per pass, >= 1 batch). A PG being deleted is invisible (list_pgs, orphan writes). Anything that brings the same collection back (CreatePg, split child, merge source/target, migration import) first finishes the queued deletion synchronously (rare). Restart: marker -> `resume_removals` at mount (blocking, before boot). Commit errors are sticky store failures.
- Wall clock: drivers set `wall_from_clock`; `Osd::start` anchors unix ns = SystemTime - monotonic now; every wall stamp = origin + monotonic (monotonic in-process, ns precision). Not re-anchored on NTP steps (open: 90-open-questions).
- MPGStats `pool_stat`: per pool, data = bytes the store holds for the PG collections (EC shard ~1/k, partial backfill target real), omap = PG-stat `num_omap_bytes`; `allocated = data_stored = data`, `omap_allocated = omap` (the mgr adds omap to STORED and USED itself, divides by the raw-used rate).
Consequences: + no RGW stall behind backfill, no heartbeat loss on PG deletion, correct `ceph df`; - an OSD may run more concurrent recoveries than classic (4x slots); - re-creating a PG whose deletion is still queued blocks the core for the rest of that deletion; - deletion slices add up to 2 ms latency per loop pass while a deletion runs (no duty cycle yet); - replica omap bytes come from PG stats (may lag), no per-pool allocation info.
Alternatives: classic preemption (REVOKE + re-request): more state, deferred to primary-side reservations (replication.md 8, M5); background deletion thread: violates thread-per-core (adr/0006).

## Amendment 1 (2026-10-12): local reserver, wall re-anchor, deletion pacing (open question 21 a, b, d)
- Primary-side LOCAL reserver (`PgSet.local`, classic `local_reserver`): a PG that wants log-based recovery or backfill first asks the local reserver (`ASt::WaitLocalRecoveryReserved` / `WaitLocalBackfillReserved`, state bits unchanged: recovery_wait / backfill_wait) and sends the remote REQUESTs only on the grant. Same two pools as the replica side (backfill = `osd_max_backfills`, recovery = 4x, per core, applied at the next tick), priority ordered (inactive > degraded > clean for backfill, inactive > normal for recovery), FIFO within. Local before remote and ordered remote acquisition: a PG that waits for a local slot holds nothing, so no wait cycle with classic peers in either role.
- Release: every `release_*_reservations` emits `LocalRelease` (idempotent); safety net `local_check` after each PG's actions gives back any slot the PG state (`Pg::local_resv_needed`) does not justify (interval reset, flag hold, removal), `forget_pg` releases (grants delivered at the next collect/tick). A grant for a vanished or re-targeted PG is passed on.
- Preemption REFUSED: classic preempts a lower-priority backfill/recovery slot (replica sends REVOKE to the primary, primary re-queues). We never send REVOKE (it is replica -> primary only; sending it as primary would be a different message role) and a local slot is never taken away; separate recovery pool means short recovery never waits behind a long backfill (the reason for preemption). A classic replica's REVOKE is handled as before.
- Wall clock: every 1 s tick, per core, `reanchored_origin`: if the system clock is ahead of `origin + monotonic` by > 100 ms the origin moves forward to it (log line); behind = ignored, so stamps stay monotonic. Injectable `Osd.sys_clock`. The mon session's cephx clock (MonClient: rotating-key refresh, ticket expiry, cluster-log stamps) is NOT forward-only: the control core re-anchors it to the system clock every tick in both directions (`MonClient::set_wall_origin`), as the classic MonClient reads the real clock; rotating-key expiry is the mon's wall time (test `tick_reanchors_mon_clock_both_ways`).
- PG deletion pacing: `StoreAdapter::set_removal_gap`: after a slice the next one waits a gap. Gap = `osd_delete_sleep` s if > 0, else `osd_delete_sleep_ssd` s if > 0 (both default 0 here; classic ssd default 1 s would take hours for 150k objects), else `flashstore_delete_slice_gap_ms` (default 10 ms: slice <= 2 ms, <= ~17 % duty). Applied with the other runtime config.
- Deletion NoSpace: a deletion txn that fails with NoSpace halves the slice (down to 1 object, doubled back on success); if one object fails the PG waits 1 s (note, no store failure, deletion stays queued and durable-marked); the synchronous re-create path halves but propagates the error at 1.
Consequences: - recovery/backfill start one tick-free round trip later (local grant is immediate when a slot is free); - an OSD never runs more PGs per pool than the limit as primary (replica side unchanged); + no AB-BA with classic.
Tests: peering scenarios `local_reservations_*` (bound = 1 holder, classic stand-ins both roles, primary killed holding a slot, no leaked slot), classic model unchanged; osd `reanchored_origin_*`, `tick_reanchors_wall_forward_only`; storeadapt crash `pg_removal_retries_smaller_on_nospace_*`, `pg_removal_slices_are_paced`.
Review (2026-10-12): local reserver: a repeated LocalRequest of a PG that only WAITED (queued) was answered as a grant (remote requests without a slot, the real grant then released the held slot); now a held slot is granted again, a queued place keeps its position with the new priority (classic update_priority). Grants are delivered only for slots the reserver holds, once, and only to a PG in the matching WaitLocal state (else passed on); `local_check` runs after the PG's action batch (final state) and also re-queues a PG that waits without a queue place. A merge source left the set (parked) holding its local slot: released now (`local_forget`, like `forget_pg`). `dump_recovery_reservations` local part = the local reserver (held, queued with priority). Wall re-anchor reached only the PgSet: `set_wall_base` now pushes the config to the loaded PGs (stats/scrub stamps), the cephx clock follows at once. Deletion: the driver hook reports no work while paused (core loop idles), empty queue = no clock read; NoSpace knob behind storeadapt feature `test-knobs` (dev-dependency only). Classic parity checked: classic also waits for a local slot before every recovery (WaitLocalRecoveryReserved), local before remote, ascending remote order.

## Amendment 2 (2026-10-25): deletion pacing replaced
`StoreAdapter::set_removal_gap`, the slice gap (`osd_delete_sleep*`, `flashstore_delete_slice_gap_ms`) and the "~2 ms per pass" slice are gone. Deletion is `StoreAdapter::step_removals(bound_ns)` on the core loop: one queued txn in flight, batch bounded by the learned per-object cost (EWMA) within one drain slice, no gap or duty-cycle constants. See adr 0524.
