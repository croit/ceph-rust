# 0057 copy-from / copy-from2 / copy-get
Status: accepted
Date: 2026-10-11
Context: `rados cp/cppool`, RGW copy, CephFS copy_file_range need server-side copy; classic does it with a temp object fed by chunked copy-get reads issued through the OSD's own objecter. Spec: spec/copy.md. Constraints: sans-IO engine per PG, PG owned by one core, no locks, atomic dest (one txn/log entry), never crash, mixed acting sets.
Decision:
1. Source side = a normal READ op `copy-get` in the executor (cursor + byte budget, wire byte-exact with goldens). No special path: per-object ordering, snap resolution, ENOENT guard, cold-page parking all come for free.
2. Dest side in the engine (`engine/copy.rs`): before executing a message with a copy op, fetch the source chunk by chunk (a source of one chunk is kept in memory; a bigger one is staged in a temp object, see am. 1), then run the original message once with the fetched object (`Msg.copy`); one transaction, one log entry, atomic with the other ops of the message. NO temp object / rename (classic needs them to stream; ours would add a store op + recovery of leftovers). Memory bound = 2 chunks per running copy, <= 16 concurrent per PG, others queue; OSD-wide budget (1 GiB, waiting copies keep their destination blocked = back-pressure; spec copy.md 4.6). Deviation documented.
3. Dest object is blocked for other ops while fetching; source reads of copies bypass the block (deadlock-free).
4. Source in the same PG: engine loopback through its own `on_op` (pseudo conn `COPY_CONN`), so ordering against queued writes of the source is the standard one. Other PG: `Out::CopyRead` + `Engine::on_copy_reply`; the OSD routes (osd/src/copy.rs): same OSD (any core) via XMsg with a pseudo connection id, re-sent on EAGAIN/backoff/drop; other OSD: step 5.
5. Other-OSD sources: OSD-to-OSD client link (public messenger, osd.N entity, MOSDOp read + MOSDOpReply + MOSDBackoff ACK, re-send on link loss / map change; spec copy.md 5.3). Sim-tested (two-OSD harness) and run live against classic OSDs both directions (am. 1).
6. user_version of dest = the SOURCE user_version (classic: copy-from is not a user-modify op, finish_copyfrom sets it; other modifying ops of the message bump it as usual; review fix, the first impl bumped). Deviations: no extra_reqids/reqid_return_codes; cache-tier flags ignored; digests of dest cleared.
Consequences: + `rados cp`, copy_file_range, RGW copies work on all-croit-flashstore-osd clusters (same-OSD sources); + engine/exec changes small (one op each side); + dest atomicity trivial. - whole source in RAM (<=128 MiB + omap) per running copy; - cross-OSD link is new transport code (live validation pending); - memory use bounded per OSD by the copy budget (+ omap overshoot).
Alternatives: stream into a temp object + rename (rejected: needs store rename + recovery of temp leftovers, more code on the durability path); implement copy inside the store txn across PGs (rejected: PGs live on different cores/OSDs); fail cross-PG copies (rejected: rados cp is mostly cross-PG).
- Amendment 1 (2026-10-12, oq 16 live run on lab-f, classic osd.0-2 + croit-flashstore-osd.3-5): the cross-OSD link, cephx (OSD ticket), tid echo, BLOCK/UNBLOCK pacing and a classic replica taking a 128 MiB MOSDRepOp all worked live, but two limits of decision 2 did not: (a) one 128 MiB copy = ONE store txn: refused with -EMSGSIZE once the free space was fragmented (data extents of one txn <= device queue depth - 34), and a classic-source object with 500 k omap keys (55 MB) never fit one txn either (tree pages budget); (b) 16 parallel 128 MiB copies peaked at 2.5 GB RSS on one OSD (fetched source + txn copy + wire blob + the same on the replicas) against a 1 GiB "budget". Fix = classic's shape with our own mechanics: a source that does not fit ONE chunk (first copy-get answer not complete) is written chunk by chunk into a TEMP object of the destination PG and the original message renames it into place. Steps: (1) first chunk: `Remove temp; Create temp; xattrs; data; omap` as an UNLOGGED write (`WriteReq` without entries + `new_temp`): `Pg::submit_write` applies it locally and sends a MOSDRepOp with an empty log (`logbl` = empty vector, `new_temp_oid`) to EVERY peer, backfill targets included (whether the final object lies in their range is only known to the renaming write); it takes a tid, no version, and completes like any repop. Classic does the same for its own copy temps (replica `do_repop` tracks `new_temp_oid`), so classic replicas need nothing. (2) each later chunk is another such write, issued when the previous one is durable everywhere (sequential: read RTT + write RTT per 8 MiB). (3) at the end the message runs with `CopySrc.staged = temp`: `[clone-before-write] Remove dest; TryRename temp -> dest; oi/snapset attrs` in the ONE logged txn (`MOp::RenameFrom`), carrying `discard_temp_oid` so replicas stop tracking the temp (a backfill target beyond its range gets an empty txn plus `discard_temp_oid` = the temp is removed there). (4) temps are tracked in `Pg.temps` on primary and replicas and removed at the next interval change; leftovers of a crash are found at PG load (`PgStoreOps::list_temps`) and removed with the first interval (this also fixes the same leak of recovery temps). A failed copy (source error, digest mismatch, ENOSPC via `write_room`, timeout) or a final message that does not consume the temp (failing op, precheck error, fenced client) removes it with an unlogged write. Sources that fit one chunk (<= 4 MiB data + the omap of that answer; the common RGW/CephFS/RBD case) keep the in-memory single-txn path: no extra round trip. Memory per running copy = 2 chunks (`COPY_RESERVE` = 8 MiB: chunk as received + txn built from it) against the same 1 GiB OSD-wide `CopyBudget` (128 copies); no `grow` to the whole source size, no 256 MiB omap cap (omap streams too), data still <= osd_max_object_size (EFBIG before more is pulled). Atomicity unchanged for readers and for the log (one entry, one txn at the end); what is visible before it is a temp object in the temp pool namespace that listings, scrub and backfill skip. Deviation from the in-memory design stays documented, the temp-object alternative of the original "Alternatives" is now the chosen path for big sources. Tests: opexec/tests/copy.rs (`a_copy_bigger_than_one_chunk_is_staged_and_stays_atomic` with a store txn limit below the object, omap flag clearing, failing chunk, digest mismatch, failing message, ENOSPC), peering/tests/temp_write.rs (unlogged write reaches all shards without a log entry, rename consumes the temp everywhere, unconsumed temp removed at the next interval, crash leftovers removed after restart), osd xcore_tests `copy_from_a_big_object_across_osds_is_staged` (real store, other OSD as source, 9 MiB + omap), lab/docker/mixed/12-copy.sh (live).
- Amendment 2 (2026-10-12, same live run): chunk = 4 MiB, not 8. The first staged run wedged the 1-PG test pool: a REPLICA's store refused one 8 MiB chunk write (`TooLarge`: its free space was fragmented, so the write needed more data extents than one txn may carry = device queue depth - 34, while the primary's own `check_write` had passed on its own less fragmented allocation); the replica drops such a txn and closes the sender link (`pg_exec` Rejected), never acks, the primary keeps the repop (and, completing strictly in tid order, every later write of the PG) waiting until the next interval. 4 MiB = 1024 blocks can only exceed 990 extents on a fully 4 KiB-fragmented replica, the same bound every RBD object write has. The replica-side hang itself (any write, not only copies) is open: 90-open-questions 23.
- Amendment 3 (2026-10-12, review of am. 1-2): (a) the replica-side TooLarge that wedged the PG is fixed at the root by adr 0066 (no data-extent limit in the store; a refused PG txn = fail-stop). The chunk stays 4 MiB: halves the per-copy reserve (`COPY_RESERVE` 8 MiB, 128 copies per 1 GiB budget); a classic or croit-flashstore-osd 4 MiB RBD object (no omap) still comes in ONE answer (data budget only, attrs do not count) = in-memory path. (b) Temp object = classic temp shape: head (`snap = NOSNAP`, was 0), empty key/nspace, pool `-2 - pool`, the destination's hash. (c) EC destination (croit-flashstore-osd EC primary, adr 0049): a source bigger than one chunk fails with EOPNOTSUPP before anything is staged (EC sub-writes have no unlogged temp writes; half-staged temps would leak on classic shards); <= 4 MiB sources (RGW heads, CephFS objects) keep working. (d) `list_temps` (PG load) lists only the temp range (temps sort before every object of the PG: same shard, smaller pool), not the whole PG (boot time / RAM with millions of objects). Checked, no change: classic replicas track `new_temp_oid` and remove tracked temps at `on_change` exactly like ours (`PGBackend::on_change_cleanup`); `discard_temp_oid` with an empty txn removes the temp on a backfill target beyond its range (classic `do_repop`); the empty log is 4 bytes (classic asserts `logbl.length()`); `version` = log head (classic sends 0'0 for simple_opc temp writes; both only feed `roll_forward_to`, no-op); temp writes are not logged so a crash of the primary mid-copy leaves temps that the interval change (live peers) or PG load (restarted peers) removes; the engine is reset (`pg_engine_sync`) before any WriteDone of the old interval is handled, so a cancelled copy never writes into a temp the interval change removed; list_temps runs only at load (no live copy exists), later removals only at an interval change (which cancels every copy); temps are skipped by listing, scrub, backfill scans, split/merge and stats (stats come from exec of the final message). Tests: storeadapt/tests/temps.rs. (c) is superseded by adr 0095: only a stripe width over 4 MiB fails with EOPNOTSUPP.
