# 0053 Kernel TCP tier over io_uring ("runs on any NIC")

Status: accepted (current state; amendments: see map)
Status note: Partly superseded by adr/0682-remove-afxdp-dpdk-networking.md (2026-11-06): the `dpdk|afxdp` tiers and their analogues is history; the rest stays valid.
Date: 2026-10-11
Consolidated 2026-10-19 and 2026-10-26; pre-consolidation texts: git show 60868596d:doc/adr/0053-kernel-tcp-tier-io-uring.md, git show f4f9a413d6:doc/adr/0053-kernel-tcp-tier-io-uring.md
Measurements/profiles: doc/perf/adr-0053-history.md (doc not in the source snapshot).

## Context

DPDK (adr 0005/0011/0038) and AF_XDP need NIC cooperation. Many hosts cannot or must not give a NIC queue to userspace: bonded/LACP ports, VLAN trunks, routed/firewalled setups, NICs without a PMD, hosts where the OSD must be reachable from the host kernel (adr 0046), no VF/hugepage budget. The kernel-probe driver (adr 0015 am.) is lab-only (one blocking thread, `std::net`).

## Decision

croit-flashstore-osd has a production tier `kernel`: per core one io_uring over kernel TCP sockets, same sans-IO OSD, same core-loop shape. NVMe stays SPDK.

### Selection and code
- `--net dpdk|afxdp|kernel`, conf `flashstore_net` (every `flashstore_<k>` conf key becomes `--<k>`, hence not `ms_flashstore_net`). `dpdk` = own stack on a PMD (parked, explicit opt-in; compilation retained), `afxdp` = same code with `net_af_xdp` (port name default `net_af_xdp0`), `kernel` = this ADR and the default even when DPDK is built in; dispatch and RDMA validation use one effective tier. Cargo feature `knet` (Linux), combinable with `dpdk`; a `knet`-only build needs no libdpdk/EAL (SPDK env initialised standalone for `--dev spdk:`).
- Code: `rt::knet` (`KNet`, `KCore`, `listen`, `bufring`, `KPlace`, `spread`), `rt::netaddr`, bin `kprod.rs`; `mcommon.rs` = OSD construction shared with `multi.rs`. Feature-gated, separate loop type, static dispatch; `Core`/`OsdNet`/`Nic` unchanged.
- Kernel floor is not gated by version (adr 0098: capability probe at start, clear error on a missing opcode).
- Host io_uring policy (am. 11): a refused `io_uring_setup` (EPERM/EACCES/ENOSYS) fails startup with one line naming the cause and the exact fix (crate `uring-access`, shared with the kernel store, adr 0169): `kernel.io_uring_disabled=2` (RHEL 9 default) -> `sysctl -w kernel.io_uring_group=<gid of ceph> kernel.io_uring_disabled=1` or `kernel.io_uring_disabled=0`; `=1` without the OSD group -> `kernel.io_uring_group=<gid>`; policy allows -> seccomp profile / LSM. The OSD never changes the sysctl; hwcheck `os.io_uring` plans the same fix for the OSD user `ceph` (adr 0056, no CAP_SYS_ADMIN) and `croit-flashstore-tool host-tune --apply` applies it. No non-io_uring fallback.
- Capability tests are never fatal for an optional feature: a failing test selects the next path and prints one loud startup line naming the failure. Fatal only when the minimum is missing (EXT_ARG, the opcodes, multishot accept, multishot recv with provided buffers in either mode); the error names every failed mode.

### Ring, sockets, semantics
- Per core: own io_uring, best setup mode the kernel accepts: `SINGLE_ISSUER | DEFER_TASKRUN | TASKRUN_FLAG` (completion task work runs only inside the core's own enters; `kick` enters on the `TASKRUN` flag), used only where a startup test sees the kernel raise `TASKRUN` for deferred work (socketpair receive, synchronous, no timing); else `SINGLE_ISSUER | COOP_TASKRUN`, `COOP_TASKRUN`, plain (`io_uring_setup` EINVAL = next mode). Startup `describe` line: `ring=<mode> missing=[<flags>]`. own `SO_REUSEPORT` listener per OSD port, multishot accept, multishot recv into provided buffers (512 x 64 KiB per core, returned the same iteration): a registered provided-buffer ring (`IORING_REGISTER_PBUF_RING`, user memory) where the startup multishot test passes with it, else classic `IORING_OP_PROVIDE_BUFFERS` (same pool, same buffer group; returned ids are queued as one entry per run of consecutive ids, `CQE_SKIP_SUCCESS` where the kernel has it; a rejected entry is counted in `provide_errs` and its ids given again). Mode in the startup `describe` line (`bufs=ring|classic:NxSIZE`) and the hwcheck `os.io_uring` row (WARN in classic mode), connect from the owning core (`IORING_OP_CONNECT` + linked 5 s timeout), `TCP_NODELAY` everywhere.
- Same semantics as DPDK `OsdNet`: `on_accept/on_connected/on_dial_failed/on_closed/on_bytes`, `IoCmd::Dial/Close`; output polled from the OSD only when a connection has nothing in flight (backpressure stays in the OSD, never dropped/reordered); `Close` graceful (queued output, FIN, 5 s cap); own close not reported back; peer EOF/error once.
- Send: one `SENDMSG` in flight per connection, up to 32 runs as iovecs (msgr2 payload by reference), `MSG_WAITALL`, partial completions resubmit. Batches >= `zc_min` use `SENDMSG_ZC` (runs held until the notification CQE, matched by a per-send sequence in `user_data`; `EOPNOTSUPP` falls back for good). Daemon default `--knet-zc-min` = 256 KiB (batches with runs >= 16 KiB on average; the copy path zeroes + copies every page); `KCfg::zc_min` library default 0. Fixed-buffer `SEND_ZC` not used (needs the adr 0033 shared payload pool).
- Port safety: a plain bind probes each port before `SO_REUSEPORT` binding (a stale ceph-osd of the same uid would silently join the port group).
- PCI safety: every SPDK/DPDK env init carries an explicit PCI allow-list (`pci_allowed` / EAL `-a`) of ONLY the configured NVMe (+ NIC ports in the DPDK tier); empty list refused, startup logs it (`nvme::pciallow`).
- Addresses as classic: `--public-addr/--cluster-addr`, else conf `public_addr/cluster_addr`, else the local address inside `public_network/cluster_network` (mixed CIDR lists; one address per family enabled by `ms_bind_ipv4`/`ms_bind_ipv6`, order by `ms_bind_prefer_ipv4`, a requested family without a match = startup error; `public_addr` also in `v2:IP:port/nonce` and `[v6]:port` form), else `--ip`, else the address the kernel routes to the first mon; cluster defaults to public. Heartbeat front on public, back on cluster; ports: the first free ones of `ms_bind_port_min..ms_bind_port_max` (6800..7568) per listener, pairwise distinct, taken ports skipped (plain-bind probe, retried on a lost race), the whole search repeated `ms_bind_retry_count` times every `ms_bind_retry_delay` s (then `WARNING TIMEOUT bind listener ports`, exit 1); `--port-base N` / conf `flashstore_port_base` = explicit override: exactly `N..N+3`, start fails if taken (`osd::portsel`). The bound ports go into MOSDBoot. Address families (IPv4, IPv6, dual-stack) are governed by adr 0659-ip-address-families; one port per listener kind is shared by its families.

### Listener distribution and placement
- `--steer hash` (default): kernel hash over per-core `SO_REUSEPORT` listeners. `--steer cpu`: classic-BPF program (`SKF_AD_CPU`, no privileges) sends a SYN to the listener of the core pinned to the processing CPU; with NIC IRQ affinity queue i -> core i a flow stays on its core and the mesh hop disappears. Outbound connections: owning core, kernel picks the source port.
- Accept-time balance (`--knet-balance on|off`, default on; ignored with `--steer cpu`): with `--steer hash` and > 1 core a public (client) connection accepted on core A is handed, before anything is read, to the core with the fewest connections (`KPlace`: per-core atomic `owned` + `transit` counters; `OwnedFd` via `mpsc`; ties stay, scan starts after the accepting core). Cluster/hb connections stay where they land (peer sessions: adr 0054). Load = connection count.
- Softirq colocation (always on): `KPlace::pick` skips the core pinned to the accepted public connection's `SO_INCOMING_CPU` when another core exists (`group_on(n, cpus)`; stat `placed_off_rx`). Reason: a stream whose softirq (NIC driver + GRO + TCP input, 0.39-0.56 cyc/B, one RSS queue) runs on the core that also receives it (copy + crc + recvmsg, 0.59-0.66 cyc/B) saturates one core at ~2 GB/s.
- DPDK path has no such option (RSS decides before software sees the SYN); the equivalent is an `rte_flow` 4-tuple rule per flow (untested, OQ 11).

### 4M receive path (KCfg; env for lab A/B)
- `bigshot` (`NV_KNET_BIGSHOT=N`, default 8, 0 = off): after a direct receive (adr 0061) the connection's next N ring receives are one-shot `RECV` + `BUFFER_SELECT`; a completion whose decoder wants a big segment starts the direct receive at once (no multishot cancel round trip); N one-shots without one return to multishot. 4K-only connections never leave multishot.
- Receive spread (`NV_KNET_SPREAD=<min bytes>` = `spread_min`; the DPDK tier analogue is `NV_RX_SPREAD`; default 256 KiB, 0 = off): the rest of a big crc data segment of a colocated stream (one `getsockopt(SO_INCOMING_CPU)` per big direct segment; peer links and `--steer cpu` included) is handed (`knet::spread`, `RecvJob` = fd + lent `DirectRx`, SPSC job/done rings per core pair, <= 16 out per helper, eventfd pokes) to another OSD core whose ring receives it piecewise and computes block crcs; the connection issues no receive while the job is out (`Rx::Away`, `inflight`). Non-colocated streams spread nothing. Direct receive piece = 256 KiB const. Single-stream limit after bigshot is the flow softirq core: host tuning (IRQ placement off the OSD cores, rx ring > 1024 when `rx_out_of_buffer` grows) is deployment guidance, not code.
- Stats in the core exit line: `direct_starts/cqes/bytes`, `spread_jobs/served/bytes/full`, `bigshots`, `rx_coloc`, `placed_off_rx`; startup line `direct=MIN/CHUNK spread= bigshot=`.
- io_uring zcrx is a supported receive path, probed per queue, copy path as fallback (adr 0464, doc/spec/knet-zcrx.md); a lab needs a queue-API NIC with HDS (doc/lab-requirements.md). Not available: hardware GRO on CX-4. Not cut on copy queues: kernel copy, crc (~0.07 cyc/B with VPCLMUL), hardened-usercopy checks, per-skb recvmsg cost. After this, the single-stream limit is the flow's softirq core: host tuning (IRQ off OSD cores, rx ring > 1024) is deployment guidance.

### Send spread (am. 12)
- A copied send batch larger than `spread::SEND_SPREAD_MIN` (256 KiB = the direct receive piece) leaves the connection's core as a `SendJob` (fd + the connection's `SendState` box, its runs = the iovecs; the connection gets a spare box) to the OSD core with the fewest send jobs counted (shared atomic per core; ties round robin, the submitting core included). That core issues the whole batch as one `SENDMSG` (`MSG_WAITALL`) on its own ring (the kernel copy runs there), repeats the rest of a short send, then returns the job through the SPSC done ring of the core pair (or locally); the connection's core accounts the bytes and pulls the next output (`send_finished`, the continuation of a local send). Mesh = the receive-spread mesh (`KSpread`, built whenever the OSD has > 1 core; `NV_KNET_SPREAD=0` disables only the receive side).
- Ordering: one send per connection at a time as before: `Conn::sending` stays set while the job is out, `inflight` holds the slot and fd (teardown's shutdown ends the job's send with an error, the job returns, the slot is freed only then). Errors: `EAGAIN`/`EINTR` repeat; any other result (or 0 bytes) returns the job failed -> `conn_dead`.
- Not spread: batches up to `SEND_SPREAD_MIN` (a copied send costs the kernel ~0.5 ns/B on the lab hosts, copy + `init_on_alloc` page zeroing: <= ~130 us, about one loop slice, less than a hop plus lost locality is worth), zero-copy batches (no kernel copy; pages stay pinned until the notification on the connection's ring).
- Why: an inline 4 MiB copied send holds the link core ~2.2 ms. During it the link core can neither decode and route the connection's next request (the conn -> PG core hop waited up to 2 ms at p99) nor run ops of the PGs it owns (reads whose PG core was the other connection's link core waited x2.5). Moving the send to the core with the fewest send jobs keeps the link cores free for the request path and never stacks two big sends on one core while another core has none.
- Whole batch per `SENDMSG`; no slicing of copied sends (am. 14). Sending in pieces (one slice per request, the executing core's loop between them, on both send paths) was measured twice and rejected: shared-image cells ops -15 % (doc/perf/blk-tail-20261031.md); per-image r4mj2q2 ABBA 256 KiB slices ops -22 %, p99 +34 %, CPU/op +36 %, 1 MiB slices no gain beyond noise at CPU/op +6 % (doc/perf/r4m-tail-20261102.md). The reply is on the client's critical path (one send per connection at a time), so every gap between pieces lengthens it by more than the bounded wait saves the other work of that core. The executing core is chosen without regard to ops waiting on it (29 % of 4 MiB copies started on a core with waiting reads while another core was free); a key (send jobs, client ops waiting on the core, published per loop iteration) was measured and rejected, no effect (am. 15).
- Stats: `send_jobs/served/served_bytes/full` in the core exit line.

### Receive under input pressure
- A connection whose input the OSD does not take (lane FIFO, cross-core queue full, store admission, ingress window) keeps draining into hold storage and pauses only when that is full; budget = sum over connections of max(`SO_RCVBUF`, `tcp_rmem` max) (stat `rx_hold_budget`). The rest of a lent direct segment is never paused (its buffer is already lent). Sibling `osd_net` (DPDK/AF_XDP): the rest of a lent spread segment is placed although the OSD takes no input. Crc and secure take the same path. Reason: a paused connection fills rcvbuf -> kernel drops (`PROTO_MEM`) -> window retraction -> mutual stall until RTO.
- Hold storage is owned by the socket (`Conn::held`, released with it; am. 13): held bytes reach only that socket's decoder, never a later socket under the same connection id (msgr2 redials a lossless session under the same id; an id-keyed hold queue fed the old stream's tail into the new one: desync, a wrapped hold count, a link that stopped reading, lab case 23). Bytes held by a socket that is gone were never decoded, so they are unacknowledged and the resumed session replays them. One resume pass delivers each admitted connection's held bytes in stream order. An id dialled while its old socket still delivers = `ERROR knet: connection id .. reused` (debug assert), old socket silenced.
- Host contract (both tiers, croit-flashstore-osd and BlueStore): data NIC IRQs/softirq on NIC-local housekeeping CPUs, never on an OSD core (doc/lab-requirements.md, `lab/baremetal/env.sh irq_hk`); `hwcheck` warns on overlap (effective affinity) and reports `rx-gro-hw`.
- Diagnostics: perf `flashstore_core_N.hold_{why}_{n,us,max_us}` (input hold time per cause: fifo, xout, store, ingress) and `knet_enters_{poll,submit,wait}` (io_uring_enter per site; `cell-sum.sh` per op); per-poll longest completion/iteration phase, pause histogram.
- Per-flow pacing (fq qdisc) is not a default (option for classic clusters, doc/lab-requirements.md).

### Idle and busy poll
- Deep idle (`--knet-wake on`, default): eventfd poke of sleeping cores on mesh sends (announce, fence, re-check inbox: no lost wake). A core whose store is quiet (`PgStoreOps::io_quiet`) and mesh backlog empty sleeps in its ring at once, cap 1 ms (store sweep, asok, adopted sockets). Store busy (polled completions): poll for one measured wake latency, then timer sleeps of 10 % of the wait's age (at least the wake latency, at most 1 ms; no fixed constants, doc/perf/large-io-20261021.md "OSD wake overhead"); `--idle spin` = pure busy poll. A host with 10-24 OSDs must not burn all cores (adr 0032).
- No busy poll in knet. Socket `SO_BUSY_POLL` (`--knet-busy-poll-us`, default off, never adopted; same cost profile) and io_uring NAPI busy poll (`--knet-napi-us`): measured, not adopted, options and code removed. NAPI 50 us A/B: QD1 write p50 only, CPU per op 1.3-4x, idle ~0.5 core per OSD (doc/perf/kernel72-features-20261026.md); spinning cores (`--idle spin`): QD1 p50 -50..-100 us at 3.6-5x CPU per op (doc/perf/stage-profile-20261016.md). A duration derived from measured wake cost is not built.
- Kill switches: `--knet-wake off`, `--knet-zc-min 0`, `NV_KNET_BIGSHOT=0`, `NV_KNET_SPREAD=0`.

### Not done
`DEFER_TASKRUN` on the kdev store ring (its completions wake the knet loop through a ring-fd poll, which deferred task work does not trigger: needs an eventfd wake, adr 0169), registered ring fd / fixed files, per-connection dirty list in `flush_out` (O(n) as `OsdNet`), IPv6, SQPOLL (steals a core).

## Rationale

- Works with any NIC/bond/VLAN/route/firewall; host kernel reaches the OSD like a classic one; no VF/hugepages for networking; the lab stops depending on kernel-probe.
- io_uring multishot + provided buffers + batched sends minimize syscalls; per-core rings keep thread-per-core (adr 0006).
- Optional features never block startup: distro kernels carry backports and regressions that no version number describes (Ubuntu noble 6.8.0-132.. rejects every valid provided-buffer-ring registration); the probe picks the working path, the startup line says which.
- `DEFER_TASKRUN`: fewer task-work interrupts of the core thread; on a kernel 7.2 A/B lower CPU/op at QD1 and more IOPS at 4k QD32, 4M and idle unchanged (doc/perf/kernel72-features-20261026.md). The flag test guards against a kernel that would queue deferred work without raising `TASKRUN` (the spinning core would never enter).
- No non-io_uring fallback for hosts that disable io_uring: the tier is built on multishot receive with provided buffers; an epoll path would be a second network stack (see Alternatives: epoll) for a host setting one sysctl fixes. Loud refusal + host-tune instead (am. 11).
- Kernel tier is the default (also for RDMA validation): it must work with kernel-owned NICs and match the transport policy (DPDK parked, adr 0005 am. 2).
- Defaults chosen by A/B and the bare-metal/rental matrices (numbers in the history file); losing options were removed, not left as switches.

## Consequences

- + No NIC cooperation, no adr 0046 workarounds, no networking VF/hugepages.
- - Kernel stack cost per byte/message: below DPDK/AF_XDP on the same NIC; copies on rx (kernel -> provided buffer -> msgr2) and on tx without ZC; scheduler/IRQ jitter (use `--steer cpu`, isolcpus, busy poll for latency).
- - Per-flow ceiling ~2.0-2.9 GB/s (softirq + receive core), below the 4 GB/s single-stream target: open bug, OQ 122.

## Alternatives

- epoll: more syscalls, no multishot/provided buffers.
- One shared ring for all cores: locks, contradicts adr 0006.
- XDP/AF_XDP on a shared PF: needs queue ownership, no routing/bonding help.
- User-space TCP over a macvlan on the host NIC: forbidden (adr 0030).
- `SO_INCOMING_CPU` as the listener steer: hint for a shared listener, useless with per-core listeners; eBPF reuseport programs: need CAP_BPF/CAP_NET_ADMIN, no gain over classic BPF.
- N TCP connections per peer link: a classic OSD maps a second connection from the same addrvec onto the existing session (doc/spec/msgr2.md 10.4 rule 8h); would need an flashstore-only extension.
- Rejected after A/B and removed: `NV_KNET_DIRECT_WAITALL`, `NV_KNET_RCVLOWAT`, `NV_KNET_DIRECT_CHUNK`, `NV_KNET_RCVBUF_KB` (fixed receive buffer via `SO_RCVBUFFORCE`, else `SO_RCVBUF` only when `rmem_max` allows); opt-outs `NV_KNET_SPREAD_COLOC=0` / `NV_KNET_PLACE_OFFRX=0` (now unconditional); a poll handling only completions ready at its start (krx-8).

## Open questions

- Leftovers of the kernel tier: OQ 15. Connection balance: knet accept-time placement is done (am. 1); the DPDK equivalent is parked (adr 0005 am. 2). knet r0 receive-window wedge (rcv_wnd 4096 after repeated prune, seen once on a candidate build): not reproducible on main (12 zen4 r0 runs, longest receive pause 98 ms), reopen if seen.
