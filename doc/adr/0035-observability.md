# 0035 Observability: admin socket, perf counters, op tracker, crash dumps (rollout P0 2,3,4,5,7)
Status: accepted
Date: 2026-10-10
Context: doc/70-rollout-readiness.md P0 items 2,3,4,5,7. Operators, croit tooling, ceph-exporter, mgr prometheus/dashboard/crash/health read these; spec/ops-observability.md.
Decision:
- ONE command table (tell.rs `CMDS` + `run_command`) serves `ceph tell` (MCommand/MMonCommand) and the admin socket. `ReplyTo` = Tell | Legacy | Asok; commands answer now or (scattered) later.
- Admin socket = std helper threads (osd::asok: accept, 4 workers, a render thread; classic protocol) off all cores and off the cores' CPUs (am. 3). It hands JSON commands to the control core over a std mpsc channel; core 0 polls it from `poll_store` (already called every loop iteration; one `try_recv`; nothing on workers) and answers through a per-request reply channel with the unserialized output; the socket worker serializes it. Osd stays sans-IO. Missing/failed socket never stops the OSD. Path from conf `admin_socket` (default `/var/run/ceph/<cluster>-osd.<id>.asok`); stale socket replaced, live one refused.
- Scatter/gather for per-core state: `XMsg::Query{id,cmd}` to every worker, `QueryReply{id,r,out}` back; core 0 merges (ops dumps, dump_pgs, dump_scrubs, `pg <id> query` = first core that has the PG, flush_pg_stats). 5 s deadline, partial answer + log. `flush_pg_stats`: workers push fresh `CoreStats` (SPSC order: stats arrive before the reply), then core 0 sends MMgrReport+MPGStats and returns the seq. 1 core = same code, no messages.
- Perf counters: per-core plain `OpPerf` (u64 adds on the owning core, no atomics/locks/alloc). Every core publishes an immutable sample once a second (workers in `CoreStats`, core 0 at its tick, with the OSD aggregates); counter dumps are built from the samples off the cores (am. 3; <= 1 s stale; `flush_pg_stats` and `perf reset` resample core 0). Names/types/prios classic (spec 2). avg = (sum ns, count, count) in MMgrReport (avgcount2 was 0: wrong), `perf dump` avgtime = sum/count, `counter dump/schema` labeled form. `perf reset` = baseline subtraction on core 0. Sub-op latency = RepOp arrival -> RepOpReply send (bounded map, cleared at 8192). Out of scope: histograms, bluestore-mapped counters (backlog).
- Op tracker per PG core (optrack.rs): fixed-size record per client op (object name inline, truncated to 56 B; ops/flags/client/epoch; no heap), `FastMap` insert at PG arrival (`pg_client_primary`), remove at reply (`pg_send_outs`) which also updates the counters; description formatted only when dumped. Bounded: 65536 live ops/core (more run untracked, counted), historic rings sized by `osd_op_history_*`. Forgotten without reply on: connection close, engine teardown, drop reports, BLOCK backoff of the triggering op (resend registers again, keeps first start). `initiated_at` = arrival at the PG core (the connection core's receive time is not carried over the mesh; <1 us difference).
- SLOW_OPS: slow count + oldest age computed per core at snapshot time (scan of live ops, once per report), summed on core 0, sent as `DaemonHealthMetric` SLOW_OPS in every MMgrReport; threshold `osd_op_complaint_time`. Local log line every 10 s while slow ops exist.
- Logging: `Osd::logl(level, ..)`, `debug_osd` (first number of `N/M`) honored at runtime (config set / injectargs / mon config; refreshed on every change and tick; workers via XMsg::Conf). Driver sink (croit-flashstore-osd/obs.rs): stderr (journald) unless `log_to_stderr=false`, optional `log_file`, reopened on SIGHUP (helper thread) and `log reopen`; last 400 lines kept for crash dumps.
- Crash dumps: panic hook (osd::crash) writes `<crash_dir>/<crash_id>/{log,meta}` (meta via tmp+rename), spec 4; `process_name` = `croit-flashstore-osd`; release profile `panic=abort` ends the process afterwards. Fatal signals (SIGSEGV/SIGBUS/SIGILL/SIGFPE/SIGABRT) write a minimal dump from an async-signal-safe handler (meta without backtrace/log, `signal`/`fault_addr`), then die with the signal (am. 2). Core dumps stay off (LimitCORE=0).
- Beacon: `min_last_epoch_clean` + primary PG list collected at send time (previously only on mgr reports: stale/0 without a mgr, mon would not trim); multi-core: not sent before every worker core reported once. PG stat math unchanged (peering owns it); known gaps in 90-open-questions 7.
- Lab-only (feature `lab`, zero cost in prod): `tell lab_panic`, `tell lab_stall <ms>` (store completions held back, writes stay in flight -> SLOW_OPS).
Consequences: + `ceph daemon osd.N ...` works, prometheus `ceph_osd_op*` non-zero, SLOW_OPS/RECENT_CRASH visible, safe flush across cores; - perf values <= 1 s stale, asok commands wait for the next loop iteration of core 0 (idle sleep adds <= idle us).
Alternatives: asok served by core 0's own event loop (needs rt changes + fd polling in a DPDK loop), atomics for counters (cache-line traffic on the hot path), per-op full description at start (format cost on the hot path).
Verified live (2026-10-10, docker lab, osd.3 = croit-flashstore-osd `kernel-probe` + `--dev file:` in pool size 1 next to 3 classic OSDs, ceph 21.1.1 CLI): `ceph daemon osd.3 perf dump|help|config set|log reopen|version`, `ceph --admin-daemon`, `ceph tell osd.3 dump_ops_in_flight|dump_blocked_ops|dump_historic_*`, `ceph health detail` SLOW_OPS ("1 slow ops, oldest one blocked for 12 sec, osd.3 has slow ops") with `lab_stall`, mgr prometheus `ceph_osd_op{,_w,_r}`, `_op_w_latency_sum/_count`, `_op_w_in_bytes`, `_numpg`, `_stat_bytes*` non-zero (needs `mgr/prometheus/exclude_perf_counters=false`: Ceph >= 20 serves daemon counters via ceph-exporter = asok `counter dump`, mgr module default excludes them), `lab_panic` -> dump -> `ceph crash post` -> `ceph crash ls` + RECENT_CRASH, `ceph config set osd.3 debug_osd 10/20` honored, `log_file`, `ceph report` osdmap_clean_epochs floor of the croit-flashstore-osd pool = beacon epoch. Found + fixed: crash module asserts on `assert_msg` unless it has the classic `... thread X time T\n<file>: <line>: FAILED ...\n` shape (breaks `crash post` with an AssertionError), backtrace frames must be ` N: (fn+0x..) [0x..]`. Not live-tested: real `ceph-crash` agent (keyring setup), SIGHUP (needs the dpdk build), multi-core + SPDK paths (covered by sim tests).

Amendment 1 (2026-10-15, read lease diagnostics): context: icelake-6330 rep4m, ~1 of 4 runs after an OSD restart, PGs `laggy` 20-40 s after start, ops blocked 30-60 s (doc/perf/rep4m-20261015.md, Open). LAGGY = the primary's read lease (renewed every interval/2 = 8 s, peering.md 8.2) was not re-acked within the interval, i.e. a lease round trip > 8 s; on a lossless session queued leases/acks restore readability as soon as the path drains, so LAGGY lasts as long as the peer path stalls. Protocol check against classic (`renew_lease`/`send_lease`/`proc_lease_ack`/`recalc_readable_until`, ack = echo of the primary-clock bound, per-interval reset, process-relative mono clocks): equivalent, no wire/protocol change. Not reproduced off icelake-6330: peering sim with per-process clocks (`Sim::fresh_clocks`, restart = new clock at 1 s) + restarts under writes, xcore pair sim (4+4 cores, writes, restart), lab-e kernel tier (3 OSDs x 2-3 cores, 32/128 PGs, single restarts, all-OSD restarts, rep4m-style out/restart/in, rados 4M t16), DPDK af_packet container lab (too slow to judge: 3 MB/s). Added, edge-triggered only (no hot-path cost, rate limit 1st/2nd/4th/... episode per PG and interval): primary `pg X: laggy (readable until -N ms, renewal sent N ms ago, epoch E, acks: osd.A N ms ago (ub +-N ms), ...)` and `pg X: laggy cleared after N ms`; replica `pg X: lease from osd.P N ms after the previous one (renewal every M ms)` (forward path late); `dump_pgs` per-PG `lease` = the same status. Tells next time which hop stalls (lease not sent / not received / ack not received). Tests: peering `lease_restart` (fresh-clock restarts keep primaries readable; laggy/cleared/late-lease notes).

Amendment 2 (2026-10-31, fatal-signal crash dumps): decision: SIGSEGV/SIGBUS/SIGILL/SIGFPE/SIGABRT get a dump from a handler installed with the panic hook (SA_RESETHAND, SA_ONSTACK); it uses only async-signal-safe calls on stack buffers (clock_gettime, mkdir, open/write/fsync/close, rename), everything else (crash dir, uuid, static meta) is prepared at install; then it re-raises so the process ends with the same signal. Rationale: FFI (SPDK, liburing, verbs) and unsafe code can fault outside Rust panics; core dumps stay off (keys, data), so without this a fault left no evidence. Consequences: no backtrace and no log tail in a signal dump (not signal-safe); the liveness watchdog's abort() now leaves a dump; Rust std's stack-overflow message is replaced by the dump (same SIGSEGV). Test: `osd` crash::tests::fatal_signal_writes_a_dump_and_still_kills (child process).

Amendment 3 (2026-11-01, counter dumps off the cores): context: `perf dump` / `counter dump` held core 0 (control core, also a PG core) ~2 ms per call on tsrv2 (doc/perf/w4m-20261101.md): core 0 built names, a BTreeMap, a JSON `Value` and the bytes, walked the allocator fragmentation per request, and the asok threads it spawned inherited its CPU pinning, so their re-parse + pretty print also ran on core 0's CPU. Exporters (ceph-exporter: `counter dump` + `counter schema`) poll this. Decision: (1) every core publishes `ctrsnap::CoreCounters` (op counters, utilization, per-PG utilization, store counters) as an `Arc` once a second: workers inside `CoreStats`, core 0 at its tick plus `ControlCounters` (statfs, PG roles, removal, map/heartbeat gauges, RDMA teardown, conf caps, merge deferrals). (2) `perf dump`, `counter dump`, `perf schema`, `counter schema`, `perf histogram dump|schema` on core 0 = `CounterSnap` (one `Arc` clone per core + the reset baseline), returned unserialized (`Out::Counters`). (3) The catalogue, per-PG names and JSON are streamed (custom `serde::Serialize`, classic key order, no `Value`) by the asok worker that answers, or for `ceph tell` / MMonCommand by the asok render thread (a finished body rings the admin socket doorbell that wakes core 0, which sends the reply); inline on core 0 only when no admin socket runs. (4) The driver records the core CPUs before the cores start (`rt::set_core_cpus`); OSD helper threads (asok accept/workers/render, log sink, SIGHUP) move to the rest of the affinity mask, or to the whole mask when the cores take all of it (startup line). (5) MMgrReport `counters()` reads the same samples. Rationale: core 0's share becomes O(cores) (bench: 0.3 us per request, was 649 us on Mac; doc/perf/perfdump-offcore-20261101.md); a request rate limit or cache would leave the per-call hold. Consequences: + no data core works per stats request, output byte-identical (names, types, format; tests `ctrsnap_tests`, `tests/perf-schema.txt`); - core 0's own values are up to one tick old like the workers' (was: fresh), core 0 samples once a second (bounded frag walk step, ~3-20 us on Mac) also without scrapes; with `--cores` = whole affinity mask the helpers share the cores' CPUs (scheduler-placed, no longer core 0's). Alternatives: admin threads under SCHED_IDLE: no measurable client p99 / p99.9 gain on tsrv2, one dump starved to 32 ms at QD16 (rejected).

Amendment 4 (2026-11-08, crash reporting privacy, fail-stop, early install; review doc/reviews/2026-11-08-nt-crashreport.md): context: `LimitCORE=0` does not stop a piped `core_pattern` collector (systemd-coredump, apport: core(5)), so a native core with cephx keys and client bytes could leave the host's control; an unwind build kept running without a panicked PG core; an empty `crash_dir` wrote dumps relative to the cwd; SIGXCPU/SIGXFSZ/SIGSYS left no report; the hook was installed only after the store mount and control OSD creation, so mount/replay/bootstrap crashes left no report. Decision: (1) `main` sets `PR_SET_DUMPABLE=0` first (start fails if it cannot); the privilege drop sets it again after setuid (a credential change resets it; supersedes the dumpable restore of adr 0056 am. 3). (2) The panic hook aborts the process after the dump in every build profile. (3) Empty `crash_dir` = no dump files (classic). (4) The signal handler also covers SIGXCPU, SIGXFSZ, SIGSYS (classic's set). (5) `crash::install` may be called repeatedly; hooks are installed once, each call replaces the config (leaked `Box` behind an atomic pointer, lock-free for the hook and signal-safe for the handler): `main` installs from the command line (`--place-id`/`--id`, setting flags, schema default `crash_dir`), `run` again after the conf file is resolved (before the mon config bootstrap), `obs::setup` with the effective config and the OSD's id; the crash dir is created only by `obs::setup` (as the daemon's final user). Rationale: classic installs its handlers during global init, before the store; classic keeps cores possible, we never allow them (keys, data). Consequences: + no core reaches any collector; + every daemon start phase leaves a postable report; - unprivileged ptrace of the daemon and non-root readers of ptrace-guarded /proc/<pid> files (io, environ, fd) need root; - before `obs::setup` the report has no log tail and, on a direct start without `--id`, entity `osd`; a mon-config-only `crash_dir` applies from `obs::setup` on. Open: fatal-signal reports without backtrace/log tail (OQ 167).
