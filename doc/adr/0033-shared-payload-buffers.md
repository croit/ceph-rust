# 0033 Shared payload buffers (`bytes::Bytes`) on the message path
Status: accepted
Date: 2026-10-10
Context: e2e profile (perf/e2e-baseline.md rounds 2+3): memcpy ~40% of the NIC core at 1.14 GB/s/core; 3 of 5 write-path copies avoidable (indata copy, txn double copy, per-replica clones, frame copy).
Decision: payload bytes (msgr2 data segment, `Segments.data`, `OsdOp.indata/outdata`, `MOSDRepOp.txn_{middle,data}`, `WriteReq`, `StoreOp::ApplyTxn`) are `bytes::Bytes` (Send, atomic refcount; `From<Vec>` is free).
- rx: `Decoder` assembles into one `Vec` per segment (essential copy mbuf -> segment, crc fused), frame/`Incoming` hold `Bytes`; `messages::decode_with_header_shared` keeps unknown-type data (client ops, PG msgs) as a shared handle; `MOSDOp/MOSDOpReply::decode_shared` slice the data segment per op; `decode_repl` shares the RepOp txn.
- txn: `Transaction::encode_v9` writes the misaligned stream in place into the output (1 payload copy instead of 2); the blob is one `Bytes` shared by the local apply (`ApplyTxn` borrows it down into the store) and every replica `MOSDRepOp` (fan-out = refcount).
- tx: `Encoder::encode_message_zc` (CRC mode, rev 2.1, data >= `ZC_MIN` 8 KiB) emits header/front/middle into a small run, the data segment by reference (crc only, no copy) and the epilogue; `Connection::poll_output_chunks` -> `Osd::poll_output_chunks` -> `net::Chunk::from_bytes` (`RxBuf::from_bytes`; `NetBuf::Heap(Bytes)` -> external mbuf buffers on virtual PMDs). `poll_output` (flat `Vec`) stays for tests/lab drivers. Secure mode / rev 2.0 / small data copy as before. `rt::OsdNet` keeps a per-connection run backlog (`send_chunk` accepts whole runs only).
- reply: `data_segment` passes a single non-empty op buffer through; store read returns its `Vec` (`Bytes::from`, no copy); `store` reads device -> destination in one pass fused with the block crc (`read_runs_into`), `read_eff_bytes` trims in place.
Remaining copies (write, size 3): NIC -> segment (essential), indata -> txn blob (v9 wire needs the payload inline between header and tail; removing it needs a rope-segment + rope-aware local apply), blob -> DMA buffer (essential, fused with crc). Per replica: segment copy + DMA copy. Open: tx crc is recomputed per replica frame (same data segment; crc32c combine could share it), real-NIC tx of heap buffers still copies into DMA-able mbufs (needs hugepage arena for payload buffers, adr 0020).
Consequences: + 4 MiB write primary path 0.5 -> 0.1 ns/B in-memory (x86), read reply 0.85 -> 0.02 ns/B; payload buffers retained until the last reference (replay queue, retransmit) drops; fresh large `Vec` per request remains (allocator). - atomic refcount per clone (negligible vs payload).
Alternatives: own `Rc` buffer type (not Send; client ops cross cores through the mesh), rope/`Vec<Bytes>` segments everywhere (complexity), arena slabs (later, with DMA-registered tx memory).
