# 0097 Runtime fairness, cached SPSC windows and bounded sinks

Status: accepted
Date: 2026-10-14
Context: the performance audit found synchronous log IO on owner cores, unbudgeted event/TX drains, repeated SPSC opposing-counter probes, duplicate per-lane kernel wakes and byte-at-a-time serial admin service.

Decision:
- Drain at most 128 messenger events or a cooperative 100 us per OSD pump, with at most 16 events of one connection before rearming it behind other ready connections. Retained readiness is explicitly rearmed. A pending-work flag resumes the pump from the driver's existing poll_store hook, returning work even without new input or store completion. Monitor events use the same budget; monitor IO commands and individual event handlers remain indivisible.
- Separate transport readiness from actor readiness: queued decoded events pause further socket/relay feeding, while the pump can still accept those events. Monitor input also pauses while an event-pump continuation is pending; timer/output processing continues. A preallocated deduplicated relay-input queue resumes held raw fragments from poll_store without requiring a typed pending head or a new packet. Retry at most 32 notified relays/100 cooperative us; retain a pump yield even if its last event was consumed. A held EOF is applied only after all raw and decoded input reached the actor, and its final close event schedules independent continuation.
- An ordered cross-core control also waits for buffered messenger events on relayed links from its source. A raw relay pop is not actor acceptance. This extends ADR 0084's retained decoded-head gate to events deferred by the new scheduling budget.
- Limit each DPDK runtime TX flush to four configured bursts. Leave unsent frames in the stack; retry on the next flush. Continue flushing after every RX burst to preserve prompt ACK progress. This is a frame bound, not a hard wall-time guarantee for NIC/stack calls, and several flushes can run in one loop iteration.
- Cache the opposing head/tail in each SPSC endpoint. Refresh an Acquire observation only at the conservative full/empty boundary. Continue publishing each slot's ownership with Release; the consumer's acquired tail permits all slots before that tail. peek followed by pop reuses that observation. is_empty deliberately performs a fresh Acquire load for the sleeper's no-lost-wake recheck. No batching of published counters or new shared state.
- Advance mesh polling cursors with a branch on wrap and resolve source/lane only for nonempty rings; idle probes need no per-ring modulo/source division. This retains the ring scan and its fairness/order semantics.
- Preallocate destination wake flags and poke each successfully addressed core once after all its lanes have been published. Preserve the existing SeqCst publication/recheck fence and eventfd handshake. No fence weakening.
- Move stderr/file sink IO to one log worker. Owner cores preserve the crash tail immediately and try-enqueue sink text. Retain at most 1024 entries with 16 KiB text each (oversize text is UTF-8-safely truncated); drop newly arriving sink lines on queue exhaustion and report the count on the next processed line. Queue metadata, allocator overhead and the existing crash tail are outside that text bound. std try_send can briefly synchronize with another sender, but never waits for sink IO or queue capacity. Reopening is requested asynchronously; a blocked sink delays reopening. Shutdown attempts a FIFO flush and waits at most 500 ms if its marker fits; delivery at process exit is best effort. Pre-setup and log-worker spawn failure retain a synchronous stderr fallback for diagnostics. This explicitly trades complete sink delivery under overload for continued IO progress.
- Parse admin requests with 4 KiB reads while retaining NUL/newline termination, the four-byte legacy protocol and the existing 64 KiB limit. Four helper workers serve up to four clients; sixteen accepted clients may wait. Overload drops additional connections. The control command channel retains at most four pending requests; a full channel returns EAGAIN without waiting, so timed-out requests cannot accumulate indefinitely behind a stalled control core. Command execution stays on the control core and existing reply/read/write timeouts stay intact; four long-running commands can still occupy all workers.

Unchanged: Ceph message/wire encodings, authentication, lossless-session replay, per-connection event order, store FIFO/read visibility and durable write acknowledgements. No new disk/WAL encoding or physical placement change.

Deferred: empty mesh polling still probes existing rings. A cfg(test) data-only source-ready bitmap PoC uses release publication and Acquire swap plus local hints retained until fresh empty observation. Local aarch64 release samples for a 32-core/32-shard mesh: empty probes 134 vs 3 ns; one producer 161/175/195 vs 69/153/71 ns/message; four producers 89/103/109 vs 115/127/113; eight producers 121/126/98 vs 129/154/134. The contended shared bitmap regresses all measured four/eight-producer samples, so it is not enabled. This PoC does not qualify ordered-control policy, NUMA behavior or hardware throughput. A topology replacement needs those proofs and busy-path measurements. These changes do not introduce a global actor scheduler, CPU offload or dynamic PG/core placement.

Validation: bounded event continuation without new network input; relayed buffered events fence ordered controls; transport pauses decoded queues while actor progress remains eligible; raw tails resume with no typed pending head both with and without EOF; TX retains and later drains frames after its burst cap; SPSC full/empty cache refresh plus existing threaded FIFO/drop tests; Linux multi-lane send produces one eventfd increment; admin delimiters/legacy fragments and another client progresses behind a slow reader; bounded log text and full-queue prefix retention. Native osd/rt suites and Linux kernel/production-launcher feature suites qualify correctness. Hardware latency, throughput, interrupts and memory-bandwidth improvements require separate NIC/NVMe runs.
