# 0023 PG hosting in the OSD core (M2 replica role)
Status: accepted, amended (am. 1, am. 2)
Date: 2026-10-09
Context: M2 = our OSD hosts PGs as replica/stray (primary-affinity 0). `peering::PgSet` (sans-IO) exists; the `osd` crate had no PGs.
Decision:
- `osd::pgs` glue owns one `PgSet` (single core for now) + `Box<dyn PgStoreOps>`. Maps: every epoch of a MOSDMap is fed to `handle_map` (epochs rebuilt from the message's incrementals/fulls, base `OsdMap::default()` from epoch 0; unavailable epochs are skipped + logged). Called after `after_map` so boot/Active state is current.
- Actions: `Send` -> cluster messenger link per peer OSD (`Purpose::Peer`, dial on demand to `cluster_addrs[osd]`, policy lossless_peer, cephx authorizer via the OSD service ticket, re-dial when `up_from`/addrs change); `Persist` -> `store.submit` then `on_commit` (queue, order kept); `NeedUpThru` -> existing MOSDAlive path; `PgTemp` batched MOSDPGTemp (psm version 0; a PG sends a wanted value once per interval, again only with a new mon session, am. 1); `PgCreated` -> MOSDPGCreated, remembered and re-sent on a new mon session; `RequestMap` -> osdmap sub from `have + 1`, once per epoch (am. 1); `PgStats` -> encoded pg_stat_t kept for primaries and put into MPGStats; beacon `pgs` + `min_last_epoch_clean` come from the same collection (map epoch lowered by primary PGs' last_epoch_clean).
- Inbound PG messages: unknown-to-`messages` types are tried with `peering::Body::decode`; accepted only from OSD peers on the cluster messenger; mon `MOSDPGCreate2` on the mon session -> `handle_create`.
- `DevMemStore` (dev only) = `peering::MemStore` behind a wrapper. Not persistent: restart => no PGs, nothing claimed, peers recover/backfill us. Replaced by the NVMe store later via the same trait.
- Client ops (MOSDOp, public messenger), M2 rules: op epoch > ours -> park + request map; op epoch < ours -> share map (incrementals from the meta store, <= 40; full map fallback; per-connection projected epoch); not in acting -> silent drop; in acting, not primary: BALANCE/LOCALIZE read (not write) or primary-only op -> -EAGAIN, anything else misdirected -> silent drop; acting primary -> silent drop + one log line per PG (primary role disabled; client keeps the op until the map changes; use primary-affinity 0).
- `tell osd.N dump_pgs` (dev) dumps machine state, counters, per-type message counts, object/byte counts.
Consequences: + live M2: PGs peer, go active+clean as replica, replica writes ack, kill/restart recovers. - Scrub messages (MOSDRepScrub 93, ScrubReserve) are not decoded (no spec yet): classic primaries' operator-requested scrubs wait on us. Replica reads are never served. Lab note: AF_PACKET vdev truncates TSO/GSO frames (BadIp drops, stalls); run `ethtool -K eth0 tso off gso off` in the classic lab containers, and `--rx-csum trust`.
- am. 1 (2026-10-28): no time-based re-send of mon requests. (1) pg_temp: A primary PG keeps its request pending (`Prim::pending_temp`) until the next interval and sends it again only when it wants a different value (classic `queue_want_pg_temp` dedup) or with a new mon session (`PgSet::resend_mon_requests`, osd-lifecycle 3.7). Removed: the 10 s re-send of a request the mon had not applied (`PG_TEMP_RESEND`, run from the 1 s tick). On a live lossy mon session a request is applied (map: new interval), ignored because the primary changed (map: new interval) or lost together with the session (reset: re-sent). A want_acting member that goes down resets peering (WaitActingChange, classic `AdvMap` rule). Test: peering `scenarios::lost_pg_temp_clear_is_resent_with_the_new_mon_session` (the dropped clear stays pending 15 s, the new session re-sends it once). (2) Map requests (`Action::RequestMap`, client ops ahead of us): asked once per epoch, a request for the same or an older epoch is a no-op (classic `sub_want_increment`; worker cores ask the control core, which deduplicates again); removed: the 2 s window after which the same epoch was asked for again. The MonClient keeps the subscription (standing while active) and replays it with a new session (`Subs::reopen`). Test: osd `xcore_tests::map_requests_are_deduplicated_per_epoch_never_repeated_by_time`. Live (1)+(2): `lab/docker/mixed/25-event-paths.sh` P2 (`osd out` + SIGKILL of the mon serving most croit-flashstore-osd sessions: every croit-flashstore-osd reaches the mon epoch on a new session, pools clean with the OSD out; re-sent pg_temp requests counted from the log line `new mon session: re-sent N pending pg_temp request(s)`).
- am. 2 (2026-10-29): the acting set is re-chosen only by events: the Recovered entry (`Pg::recovered`: `choose_acting(restrict, pg_temp only)` while acting != up, also EC), a new peer's notify in Active (peering spec 5.2) and a new interval. Removed: the re-run of that `choose_acting` from the 1 s sweep for a Recovered primary with acting != up and no pending request. Its premise (an up member missing from the probe set) never held: `PriorSet::build` probes up + acting, and a stale notify is dropped before GetInfo (`last_peering_reset`). In Recovered the inputs of `choose_acting` (peer infos and stats, up, acting, pool) change only through those events, so the re-run repeated the entry's answer (full peering suite instrumented: 1 run, no change). Test: `scenarios::async_recovery_uses_pg_temp` and `backfill_after_log_trimmed` assert that no pg_temp request came from the tick (`Stats::pg_temp_from_tick`); without the Recovered-entry call the async case is rescued only by the tick (counted) and the backfill case stays remapped (Clean was never covered by the sweep). Live: `lab/docker/mixed/25-event-paths.sh` (P1 restart under load, P2 `osd out`: pg_temp set, backfill, pg_temp cleared; clean excludes remapped).
