# 0034 Deployment + lifecycle contract (prepare/activate/run, systemd, OCI)
Status: accepted
Date: 2026-10-10
Context: doc/70-rollout-readiness.md P0 items 1+6 + sections 2.1-2.4; croit deploys with systemd or plain OCI, no cephadm (user decision).
Decision:
- CLI. `croit-flashstore-tool prepare|activate|list|inspect` (prod build: `--no-default-features --features spdk,mon-std`, no lab); `croit-flashstore-osd run --id N [--cluster C] [--conf F] [--data-dir D] [-f] [--show-config] [flags]`. Exit: 0 ok, 1 runtime, 2 usage, 3 precondition/refused, 4 already prepared (no-op). `--format plain|json|json-pretty` (list: also jsonl) on stdout, log on stderr. Only touches the device given by PCI address; no host scans (list scans `/var/lib/ceph/osd` only).
- prepare = host checks (PCI present, bound to vfio-pci/uio, never a kernel-owned disk) + store mkfs (PLP required, 4096+0 LBAF via `--format-lba4k`, refuses a non-blank foreign device (GPT/MBR/FS/bluestore label/any non-zero in first 8 KiB) unless `--wipe`) + `osd new` over kernel TCP (tool only: feature `osd/mon-std`, module `osd::kdrv`; never linked into the daemon) with bootstrap-osd keyring + OSD dir. Idempotent: pending uuid/key persisted in the store before `osd new`; rerun completes a crashed prepare; same device again -> exit 4.
- OSD dir `/var/lib/ceph/osd/<cluster>-<id>/` (or `FLASHSTORE_DATA_DIR`, conf `osd_data`): `whoami`, `fsid` (OSD uuid, classic meaning), `ceph_fsid` (cluster), `keyring` (0600), `type`=`bluestore` (adr 0019: classic scanners recognise it), `croit-flashstore-osd` (JSON marker: dev spec, osd uuid, cluster fsid, class; hint only, store identity is authoritative), `ready` (last). No `block` symlink. Code: crate `osddir`.
- activate (ExecStartPre): dir valid + `ready`, device bound to a userspace driver, free hugepages >= need, RLIMIT_MEMLOCK unlimited, store superblock osd uuid == dir (cluster fsid compared when set; the device superblock keeps it zero), prints the resolved run flags. `--no-host-checks`/`--no-store-check` for containers/tests.
- run: `/etc/ceph/<cluster>.conf` (`[global]` < `[osd]` < `[osd.N]`) + dir -> daemon flags; command-line flags override (daemon takes the first occurrence). Precedence: CLI flag > `--set k=v` > conf file > mon config db; `--set` feeds the same option map as the conf (`--set flashstore_port_name=X` = conf key); a `--set` key that is not a valid Ceph option is a config error (exit 3), a valid unused one is accepted and reported in `status` (adr 0021 am. 60). Conf keys: `mon_host`, `flashstore_dev`, `flashstore_ip`, `flashstore_gateway`, `flashstore_vlan`, `flashstore_lcores` (`FIRST[-LAST]`), `flashstore_hugepages_mb`, `flashstore_eal_args`, `flashstore_vdev_iface` (lab af_packet), `flashstore_cores/queues/idle/rx_csum/port_name/neigh/huge_dir/...` (any other `flashstore_<k>` -> `--<k>`); prep-only keys `flashstore_driver`, `flashstore_hugepage_kb`, `flashstore_nic_bind`; prepare-only (mkfs) key `flashstore_store_shards` (`auto` | N, adr 0160). Config errors exit 3.
- Defaults (open decisions of 70-rollout 4): CRUSH class `nvme` (prepare `--crush-device-class` overrides; admin-set class is never overwritten, -EBUSY path); unit `croit-flashstore-osd@<id>.service` (not `ceph-osd@`; croit maps); runs as root for now, superseded by adr 0056: user `ceph` + caps (SPDK/DPDK PCI BAR + hugepage access), non-root = adr 0056; unsupported pool types stay passive (unchanged).
- Driver binding: production default `vfio-pci` (IOMMU on + hugepages: works under Secure Boot/lockdown, MSI-X eventfd interrupts for adr 0032 idle mode, DMA isolation, path to non-root). `uio_pci_generic` + `--iova-mode=pa` only as lab fallback (VM without vIOMMU): `flashstore_driver = uio_pci_generic` + `NVS_IOVA_MODE=pa` for tools. `croit-flashstore-prep@<id>.service` (oneshot, `croit-flashstore-prep.sh`, bash, idempotent) reserves hugepages, mounts hugetlbfs, binds ONLY the configured NVMe/VF; refuses an NVMe with mounted partitions/holders and a NIC with an IPv4 address; mlx5 (bifurcated) left on the kernel driver. Measuring vfio vs uio on bare metal = backlog.
- Unit `croit-flashstore-osd@.service` (lab/deploy/systemd): Type=notify (READY=1 + STATUS=booting once core 0 runs, STATUS=active when "is now active", WATCHDOG=1 from the liveness checker thread, `bin/sdnotify.rs`, no deps; am. 5), WatchdogSec=60, Restart=on-failure, StartLimitBurst=3/30min, LimitMEMLOCK=infinity, LimitCORE=0, journald, CPUAffinity via per-instance drop-in (example shipped). Known limit: a failing ExecStartPre (exit 3) still restarts (RestartPreventExitStatus covers the main process only); StartLimit stops the loop. Core liveness: am. 5.
- OCI (lab/deploy/container): multi-stage Containerfile (builder = devcontainer image with SPDK/DPDK; runtime debian-slim, shared libs copied, no python, no ceph pkgs), `run.sh` documents mounts/devices/caps (`--network=none`, `--cpuset-cpus`, no CPU quota, vfio devices + IPC_LOCK/SYS_NICE, hugepages/data/conf/asok/crash mounts, `--ulimit memlock=-1`, `--stop-timeout 60`). Hugepage reservation, driver bind, VF setup stay host-side (prep unit). Same binaries + CLI as native. SUPERSEDED by adr 0052 (runtime-only image from prebuilt binaries, built + tested).
- Device metadata (items 6): boot metadata `devices` (PCI addr; no kernel name while SPDK owns the device), `device_ids` (`<pci>=<MODEL>_<SERIAL>`, spaces -> `_`, classic udev form), `device_paths` (`<pci>=pci-<addr>-nvme-1`), `bluestore_bdev_dev_node` (only key set; the other bluestore_bdev_* keys have no consumer); `tell smart [devid]` = `{devid: smartctl-json subset}` from Get Log Page 0x02 (SPDK admin command from a 5-min background thread, never a core), `tell list_devices`. Spec: spec/devicehealth.md. Verified live: `ceph device ls` (WEAR from percentage_used), `device scrape-daemon-health-metrics`.
Consequences: + one conf file + one dir per OSD, croit tool drives a stable CLI; + `ceph device`/devicehealth/dashboard see the NVMe; - kernel-TCP mon client lives in the tool (not the daemon); - dir `type=bluestore` may make classic tooling try (and fail) to activate it: intended, loud failure.
Alternatives: `ceph-osd@` unit name (confusing with classic), cephadm layout (rejected by user), conf-less flag soup (unmaintainable), daemon-side `osd new` (needs DPDK stack in prepare).
- Amendment 1 (2026-10-16) shutdown contract (SIGTERM/SIGINT). Order: (1) core 0 sets state Stopping (no new client ops), (2) MOSDMarkMeDown request_ack to the mon, wait for the ack (`osd_mon_shutdown_timeout` 5 s, then go on; `osd_fast_shutdown_notify_mon`), (3) core 0 broadcasts `XMsg::Shutdown`, workers leave their loop, (4) every core releases its own NIC state, (5) main joins ALL core threads, (6) only then the ethdev is closed (`rt::close_parked_ports`) and the process exits 0 with the exit report. 2nd signal / timeout = hard exit, never a crash. Rules that make (4)-(6) crash-free: (a) `DpdkNic` NEVER frees rx slots it did not take: the mlx5 vector rx copies its whole elts window into the `rx_burst` array, slots past the returned count are PMD-owned posted rx mbufs (zero-filled header after a ring reset); freeing them at drop put them into the pool = `segfault at 44` (null `m->pool`) in a `coreN` thread at the end of almost every stop under small-packet load (found 2026-10-16: core of the prod build, gdb, all 3 cores in `Port` drop); `DpdkNic::drop` leaks them (`Mbuf::leak`), (b) the port (PortGuard = `rte_eth_dev_close`) is parked and closed by the main thread after the join, never by whichever core drops last, (c) pending tx mbufs are freed before the port. Drain (`osd_shutdown_drain_timeout`, default 5 s, 0 = off): order is refuse new ops (state Stopping, new ops dropped: the client resends against the new map) -> wait until every core has no op left (per-core slots `DRAIN_LEFT`, control core waits for all) or the window ends -> MOSDMarkMeDown+ack -> exit; replies to our own in-flight writes are accepted while draining (`pg_peer_in`), an op unfinished at the deadline was never acked (logged with pg + open repops). Draining BEFORE the mark-down keeps the PG intervals alive while ops finish. Final WAL flush / checkpoint / clean flag: NOT done on purpose, measured replay after SIGTERM under load = 0-5 txns, mount 2.0 s fixed cost (doc/perf/shutdown-20261016.md). Release order: every core frees its mbufs, ports closed by main after the join (DPDK), SPDK ctrl dropped after the join (`drop(ctrl)`), kernel tier rings die with their core thread (20 cycles clean). Test: `lab/baremetal/stopcycle.sh dpdk|kernel N` (stopm.sh on the VMs), 10+10 cycles PASS, numbers in doc/perf/shutdown-20261016.md; before the segv fix 1 of ~4 stops crashed.
- Amendment 2 (2026-10-19) mkfs deallocates the namespace. Whenever mkfs (re)creates a store (`--wipe` or unformatted) it first deallocates the WHOLE namespace (not only `--store-size`: the namespace belongs to the OSD) so the FTL forgets all old mappings (GC / write amplification, fair vs BlueStore). Parity: BlueStore `bluestore_discard_on_mkfs` (default true) trims the whole device at mkfs.
- Mechanism: DSM deallocate on SPDK and kernel-NVMe passthrough (`kernel:/dev/ngXnY`), BLKDISCARD over the whole device on kernel O_DIRECT (`kernel:/dev/nvmeXnY`; mkfs only, no runtime trims there) (FileDev: punch hole), ranges of at most 2^32-1 LBAs (DSM range length field), kept outstanding up to the queue depth; one line `mkfs: deallocated N LBAs (G GiB) in T ms`; no deallocate support or a failed range = error, no silent fallback. Also after Format NVM (not known whether the format deallocated).
- Opt-outs: `--no-discard` (prepare/mkfs), conf `bluestore_discard_on_mkfs = false` (Ceph's key, default true); logs `mkfs: whole-device deallocate skipped (--no-discard)`; the kernel-cmd DSM probe (adr 0169 am. 8) still runs.
- Amendment 3 (2026-10-19) one output-format flag. `--json` is removed (no alias); every croit-flashstore-tool subcommand and hwcheck take `--format plain|json|json-pretty` (`jsonl` only for record streams: `list`, `raw`), parsed by crates/outfmt; unsupported value = exit 2 (doc/ops/croit-flashstore-tool.md "Output format"). Applies to adr 0046 (`asok`) and 0166 (`hwcheck`) as well.
- am. 4 (2026-10-29) exit without run-on. After the mark-down (acked, or `osd_mon_shutdown_timeout`) the kernel-TCP core loop (knet `KCore`) returns at once; the 300 ms "linger" that kept stepping the loop so queued output could leave is removed. Classic parity: `osd_fast_shutdown` = true exits right after the mark-down (spec osd-lifecycle 7.5); a socket closed with unread inbound data (usual under load) makes the kernel send RST and drop its send buffer, an idle one sends what it holds and the FIN; replies lost so, and output still queued in user space, are covered as with classic fast shutdown: clients resend on the reset / new map, an op that was durable is answered from the PG log dup (reqid dedup). Nothing depends on the run-on: acks only after durability (adr 0008), a lost reply costs a resend. Siblings: RDMA (adr 0469; upgraded knet sessions, driven by `KCore`) leaves through the same exit; dev driver (kdrv) flushes exactly at exit, `pg_core` pumps until idle (work-bounded, no clock); own-stack `core_loop` (AF_XDP/DPDK, parked/deprecated) keeps its 300 ms run-on: its TCP lives in user space, the loop itself must send the FIN; close-all-then-exit there = open question (doc/90). Test: `lab/docker/mixed/25-event-paths.sh` P1 graceful step (SIGTERM under load: exit 0, `shutdown complete`, no shutdown WARNING TIMEOUT, marked down, clean after restart); production loop: `PROFILE=knet CASE_ENV="NV_NET=kernel" lab/vm-case.sh <vm> <sha> 25-event-paths.sh`.
- am. 5 (2026-10-31) readiness and core liveness. (a) READY=1 when core 0's loop runs (store mounted), not when up in the map: preboot waits (`noup`, mon outage, map / purged-snaps catch-up) are legitimate and unbounded, as in the classic `Type=simple` unit; tying READY to "up" let `TimeoutStartSec` kill + restart the unit 3x and leave it failed (StartLimit) under `ceph osd set noup`. STATUS= reports booting / active. (b) Every core beats from its 1 s tick (`osd::liveness`); a checker thread compares the beats with `osd_op_thread_timeout` (15 s: OSD unhealthy, core 0 drops heartbeat pings so peers report it down, no re-boot while unhealthy, `WARNING TIMEOUT core <n> progress exceeded <limit>s`) and `osd_op_thread_suicide_timeout` (150 s, 0 = off: abort -> crash report, restart), the classic thread-timeout semantics applied per core. A wedged worker core used to hang its PGs forever while core 0 kept the OSD up. A component that knows its core cannot progress although the loop turns (device wait without completions) withholds the tick beat; device-hang detection itself is the store's. systemd WatchdogSec stays as the backstop for a stuck checker. Siblings: all drivers (knet KCore, own-stack core_loop, multi/PG-only cores) build their Osd through `build_osd` or set the liveness in the single-core path; the rt loops no longer carry a beat. Test: `osd::liveness` unit tests, `core_tests::ping_gets_reply_and_you_died` (pings dropped while unhealthy), sdnotify datagram test.
- am. 6 (2026-11-08) settings keep their source level. `run` passes conf-file and OSD-dir settings as `--conf-set k=v`, an environment-derived one (`FLASHSTORE_DATA_DIR` -> `osd_data`) as `--env-set k=v`, command-line `--set` pairs and daemon flags as `--set k=v`; the daemon layers them file < env < cmdline (classic levels 2/3/4), so `config diff` and the mgr's `config show` name the classic source. A command-line `--set` no longer hides the conf value: both layers reach the daemon, the command line wins (unchanged effective value). The built-in `osd_data` default is not forwarded (the daemon expands the same default). A direct daemon start's `--set` is cmdline. Rationale: classic `config diff` / `config show` report per-source layers; one flat `--set` list made every startup value look like one source. Code: `osd::config::{Level, LocalSources, local_layers}`, `croit-flashstore-osd` `args::SET_FLAGS`, `run::resolve`.
