# 0100 Storage ownership and projected omap reads

Status: accepted (2026-10-14)
Date: 2026-10-14

Context: the performance audit identified payload copies and value materialization outside the data/metadata work a request actually consumes. Ceph compatibility is the governing constraint. The existing parallel data/WAL commit, durability witnesses, checkpoint ordering, reader pins, wire encodings and disk formats remain unchanged; this is not the rejected ADR 0027 commit architecture.

Decision:

- Add a committed-view, budgeted omap scan that projects keys and logical value lengths directly from tree pages. Admit entries before copying inline values or fetching fragments. Inline values copy straight into their result once; selected fragments retain bounded parallel prefetch. Keys-only reads do not materialize values or request fragment pages. Projected scans run only on Store's fresh read Stage, after existing visibility fencing; mutation overlay iterators retain their existing implementation.
- Preserve the values iterator's approximate byte budget and first-entry rule. OMAPGETKEYS budgets serialized keys (`4 + key.len()`), with zero keys at a zero byte budget. Recovery has a separate strict cutoff (`next entry size >= remaining budget` after the first admitted entry), inclusive continuation key and first-oversized-entry rule. The omitted entry's value is not fetched. Recovery moves omap entries into PushOp and takes the first returned data allocation directly; concatenating further disjoint runs still copies.
- Add safe complete-initialization operations to IoBuf: full copy, concatenation with a zero tail, and full blockwise copy/CRC32C with supplied seeds. SPDK implementations write through raw/MaybeUninit destinations and mark initialized only after every byte is written. Validate sizes before any write. Safe slice access keeps lazy zero initialization. AnyBuf delegates to the backend implementations. Raw write staging keeps its fused copy/CRC; WAL/pad/root and checkpoint images use complete initialization. No generic caller is allowed to assume an arbitrary callback initialized a buffer.
- Defrag retains the completed read's device buffer, verifies old-address CRCs once, and sends that allocation directly as the new-address write. Every attempt still checks the extent record; new-address CRCs are recomputed after allocation. Temporary submit rejection returns the original buffer to the job and unreserves the rejected destination. The ordinary data/WAL transaction and delayed frees remain unchanged.
- Count queue metadata's encoded length with a nonallocating BufMut sink. Version-envelope patch operations check bounds without storing bytes. Existing conservative size multipliers and error fallbacks remain.
- CloneRange takes ownership of its read allocation. Aligned destination runs move that allocation; unaligned destinations own only RMW boundary blocks and retain the aligned middle as Bytes slices. Dirty-run cuts promote an owned allocation only when a prefix or suffix survives, avoiding full remnant copies. CloneRange still reads and physically writes data; shared-extent CloneRange is not implemented here (since adr 0021 am. 38 the block-aligned middle shares blocks, see amendment 1).
- Cold Sio writes borrow input slices for their single device-buffer copy and use unspecified-content allocations for reads/full writes. Clock behavior and completion/durability requirements remain.

Consequences: bounded scans can still inspect up to sixteen metadata entries per tree step, and restarting a nonblocking metadata scan can repeat cheap projection work. Fragment reads, device DMA and selected reply storage remain real costs. Defrag must still read/write media and calculate destination CRCs. Counter encoding still walks metadata structure; it avoids serialized output allocation rather than all encoding CPU. CloneRange sharing, data/omap value separation and per-PG scheduling are separate architecture experiments, not included here.

Validation: native store/storeadapt suites include model and crash matrices; new regressions cover projected keys versus fragmented-value reads, zero/count/prefix budgets, owned CloneRange allocation retention and unaligned boundaries, remnant subrange retention, and rejected defrag ownership/reservation cleanup. SPDK tests run without PCI or hugepages and check fresh complete initialization, AnyBuf delegation, CRC/output equality and existing safe-slice behavior. Comparative fixtures: `storeadapt/examples/perf_storage_audit.rs`, ignored `storeadapt::perf_audit::perf_queued_metadata_size`, and ignored `nvme::spdk::tests::perf_fresh_dma_full_init`. Results and hardware limitations belong in the performance results report; no production throughput gain is asserted by this ADR.

Final verification: full native `cargo test -p store -p storeadapt` and scoped all-targets Clippy with warnings denied passed. Linux `cargo test -p nvme --features spdk,lab --lib` passed 22 tests (two explicit benchmarks ignored), including fresh full-initialization, invalid input guard, pool reuse and safe slice cases. Comparative results and five raw samples are retained in `doc/perf/storage-audit-2026-10-14.md` and `doc/perf/probes/2026-10-14-storage-*.log`.

## Amendment 1 (2026-10-25): CloneRange shares blocks
CloneRange no longer always reads and writes: the block-aligned middle of an eligible range shares the source's committed blocks (`Stage::clone_range` / `share_range`, adr 0021 am. 38, 2026-10-15); the unaligned head/tail blocks and ineligible ranges (inline, compressed, same object, unequal block offset) keep the owned-allocation copy described above. "CloneRange sharing" in Consequences is thereby implemented.
