# 0116 EC client read path: one-pass sub-reads, shared buffers, fused crc
Status: accepted. Date: 2026-10-14. Scope: EC primary client reads (legacy L0/L1 and mode O via the primary), sub-read replies.

Context: rented single host, rados 4M seq read t16: EC k2m1 -25 % vs BlueStore, rep3 at parity (doc/perf/rented-single-20261013.md). Read path: `Engine::cold` probed the LOCAL shard with the client's LOGICAL range (`warm_data`) before `ec_wait`; the op parked on that device read and only then asked the peers -> local device read and remote sub-read serialized. The probe's 256 KiB prefetch runs never matched the shard read and stayed pinned until expiry (`PF_TTL`): 16 x 2 MiB pinned = the 32 MiB prefetch table full, later probes refused (in the sim: stall). Copies per 4 MiB read: shard reply in the front (shard) + copy out on decode (primary) + `to_vec` of the reply buffer + interleave + cache `to_vec` + msgr2 crc pass over the 4 MiB reply.

Decision:
- EC pools: no data probe in `Engine::cold`; `ec_wait` asks our shard (non-blocking warm, `own_wait`) and every remote shard in the same pass.
- `EcRd.got` keeps reply buffers as `Bytes` (no copy); `Backend::{assemble, shard_columns, repair_shard}` take any `AsRef<[u8]>` column.
- Client reads: `assemble_crc` fuses `crc32c(!0, out)` into the interleave copy (`crc32c_extend`, one pass on x86); the cache entry is `Bytes` + crc; `ObjView::ov_read_bytes` (default = `ov_read_crc` moved) returns a slice of the entry, with the crc when the read is the whole entry -> `CrcHint` on the reply, msgr2 skips its pass.
- Shard role: `ECSubReadReply` struct v3 (compat 2, empty omap fields, data in DATA segment; one buffer = the segment itself) when the map's `require_osd_release >= tentacle` (every peer then decodes v3: tentacle classic sends this shape itself, spec ec.md 6.2.2); else v1 inline as before. Decode keeps `data_segment` only when no omap field implies v3 (re-encode identical).
Healthy reads never decode (plan `direct`, systematic data chunks); degraded reads decode as before.

Compat: no new encoding (v3 is classic's own tentacle shape, gated by require_osd_release); mixed classic primaries/shards unchanged below tentacle. Tests: ecwire `read_reply_data_segment_without_omap`, ecback exhaustive read check with `assemble_crc` (direct + every degraded set), osd `ec_client_read_roundtrip` (3 OSDs, v3 + v1 replies, unaligned/partial/past-end ranges; debug builds verify every crc hint). Bench: `w4k_bench` `NV_W4K_READ=1`.
Limits: see am. 1-2.
Am. 1 (2026-10-14): a cache entry a client read took whole (`ec_cache_read_bytes`, whole range) is dropped at the next `ec_wait` (only between ops: a second READ of the same range in one op still finds it; a later reader of the same range reads the shards again). Sequential 4M readers no longer keep 64 MiB/PG of consumed buffers (memory back at once); 4K readers keep the cache scan short (the FIFO held up to 16 k entries of 4 KiB, scanned linearly per warm).
Am. 2 (2026-10-14): shard role reads its range with `PgStoreOps::ec_read_crc` (store block crcs, `Store::read_crc`); the reply carries `ECSubReadReply::data_crc` (never encoded) and `pg_send` hands it to msgr2, which uses it only when the DATA segment is exactly that buffer (v3, one buffer): no 2 MiB crc pass per sub-read reply.
Am. 3 (2026-10-14): `ec_obj_size` (2-3 calls per client read) reads the one `_` attribute (`PgStoreOps::ec_getattr`, default = from `ec_getattrs`) instead of the whole xattr map.
Am. 4 (2026-10-22): shard role serves a plain one-object one-extent sub-read with `PgStoreOps::ec_read_shared` (store `read_shared`: the verified prefetch / device buffers by reference, piece crcs from the verification): the first piece is the buffer of `buffers_read` (DATA segment, v3), the others go to `ECSubReadReply::data_more`; the extent length covers all pieces. `pg_send` moves them out (`take_data_more`) into the msgr2 frame after the DATA segment (`DataX.more`, as replicated large writes); `Message::encode` concatenates them (copy) for any other path; pieces without the one-buffer v3 shape are an encode error. L0 hinfo check, clay sub-chunks and v1 replies keep the copied buffer. Wire unchanged. Measurement: doc/perf/ecread-seq-20261022.md.
Am. 5 (2026-11-01): parked EC client reads wake per object. A gated op whose `Engine::cold` is false only because of `ec_wait` (a client read or write of the object in flight) names the object's EC token (`peering::wake::ec_tok`, kind 0 + bit 61; store tokens use kinds 1-3). `EcPrim` collects the tokens of the objects whose client read ended (data, error or stale) or whose write was submitted / finished; `PgSet::take_ec_wake` hands them out per PG and `pg_post` merges each PG's set into the store wake of that PG only. Before, any EC read completion set `woke.all` for the whole core: every gated op of every parked PG was probed again (`ec_wait` each), O(gated ops x completions) per core, a feedback loop on cores holding several EC primaries (30-OSD gate: ec83 4K randread 12.7 probes/op, loop iterations > 100 ms, p99 175 ms). No lost wake: a token past `WAKE_MAX` degrades the PG's batch to `all`; `retry` (interval, peering, recovery) wakes everything as before. Test: opexec `ec_reads_wake_on_their_object_only_and_never_miss_a_wake`. Measurement: doc/perf/ec-read-wake-20261101.md.
