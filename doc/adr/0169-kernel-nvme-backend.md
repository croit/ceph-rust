# 0169 Kernel NVMe backend (io_uring) for the kernel tier
Status: implemented, amended (am. 11), default off (`--store-backend spdk`). Gate FAIL 2026-10-18 (r4m-q1-fresh CPU/op 1.09x BS): open bug (OQ 47), default stays spdk until fixed.
Date: 2026-10-17
Context: adr 0162 (+am. 1): in the kernel tier CPU/op of a QD1 4K read = spin wall time of the 70-90 us device wait (SPDK completions are polled). adr 0165: SPDK interrupt mode needs VFIO MSI-X (absent in the lab VMs) and an eventfd hop. Measured baseline: BlueStore sleeps on the kernel NVMe interrupt (CPU/op reference). Zen 4 r4k-q1 CPU/op 0.66x BS, Ice Lake 0.86x (zen4-vs-icelake-20261017). Rule: never worse than BlueStore.

## Decision
- Backend `KernelNvme` (crate `nvme`, feature `kernel`, Linux; module `kdev`): the namespace stays bound to the kernel `nvme` driver. Spec `kernel:/dev/nvmeXnY` = O_DIRECT on the block device ("direct"); `kernel:/dev/ngXnY` = NVMe passthrough, `IORING_OP_URING_CMD` (`NVME_URING_CMD_IO`) on the generic char device ("cmd"). The node type picks the mode. Enum dispatch in `AnyDev` (static, adr 0024); compiled into the production binary through the `knet` feature (tool: `spdk`), selected at runtime.
- `--store-backend spdk|kernel|kernel-cmd` (conf `flashstore_store_backend`): with an `spdk:BDF[,ns=N]` device spec the daemon/tool resolves the kernel node of that controller + NSID from sysfs, so osds.table/prepare stay unchanged. The OSD dir keeps the `spdk:` spec (identity = PCI address + NSID).
- One io_uring per core thread (device ring), shared by all queue handles of the thread; SQE128/CQE32 (both modes, one ring type), single issuer, no COOP/DEFER taskrun: the completion task_work runs at the interrupt return on the submitting core, so a polling core sees CQEs without a syscall and a sleeping core is woken.
- Registered resources: the device fd (fixed file per queue) and one global buffer arena (`NV_KDEV_ARENA_MB`, default 512, 2 MiB hugepages if available, else populated 4 KiB pages) registered as fixed buffer 0 in every device ring: `READ/WRITE_FIXED` and `URING_CMD_FIXED`, no per-IO page pinning. Buffers: per-thread exact-size bins (4 KiB .. 16 MiB) carved from the arena; arena exhausted / larger buffers = 4 KiB aligned heap, plain ops. Zero-copy payload views (adr 0061 am. 4) allowed when dword aligned (kernel `dma_alignment` 3), plain ops.
- Submission: SQEs are queued per thread and submitted once per loop iteration (`kdev::flush`, called by the kernel tier at the end of each step) or by the device `poll` (tools, sync helpers, DPDK tier): one `io_uring_enter` per iteration for all queues, never one per IO.
- Payload memory: the kernel backend has no SPDK env, so `kprod.rs` starts a memory-only EAL (`--no-pci --in-memory`, lcore 0 on the whole affinity mask, no threads) and enables `HugeAlloc` with the SPDK budget rule (`--mem` default 2048, budget a quarter, `NV_HUGE_ALLOC*`). Without it the 4 MiB read reply and the write rx buffers were 4 KiB heap pages: per-page pinning and skb frags in the zero-copy send, fresh-page faults; measured +0.86 ms CPU per 4M read (3.47 vs 2.61 ms), 1.09x BlueStore; now 0.99x (doc/perf/read-cpu-20261018.md).
- One wait point: knet arms a multishot `POLL_ADD` on the device ring fd in its own ring (`K_STORE`); a store completion wakes the core like a socket completion. Idle policy (adr 0162 `IdleState`): with a waking backend the device-wait park defaults to 100 = sleep in the ring until the completion wakes the core (no timer, no overshoot); `--knet-store-park N` < 100 = adr 0162 hybrid (timer park to N % of the learned latency, then poll; an earlier completion still wakes the core).
- Durability (adr 0008/0021/0027 unchanged): completion = durable. PLP (VWC = 0): plain writes, no flush. VWC = 1 (lab `--allow-vwc` only): direct = `RWF_DSYNC` per write (block layer issues FUA, or a post-flush when the device lacks FUA), cmd = FUA bit (CDW12 bit 30) like SpdkDev; write zeroes on VWC: direct refuses it (fallocate is not FUA; the store writes zero blocks with DSYNC), cmd = FUA (am. 10). No page cache anywhere (O_DIRECT / passthrough). Ordering: none between in-flight commands, same as NVMe/SPDK: the store already orders by completion (data + WAL concurrent, ack on both durable).
- Geometry = the SPDK rule: Identify Controller/Namespace through `NVME_IOCTL_ADMIN_CMD` on the opened node: AWUPF/AWUN (NAWUPF/NAWUN when NSFEAT bit 1), VWC, ONCS (DSM, write zeroes), NSZE, current LBAF. Required: 4096 B data + 0 metadata, no PI (direct: the kernel hides metadata formats; cmd could address 4096+64, the store does not use metadata). Wrong format = refused with the `nvme format` hint; `ensure_4k` stays SPDK-only. Max transfer = min(MDTS (4 KiB pages), 512 KiB, kernel `max_hw_sectors_kb`).
- Exclusivity: `O_EXCL` open of the namespace block device (fails when mounted, a partition is in use, md/dm/LVM holder, another OSD/tool), held in both modes; namespaces with partitions refused. Health probe = the existing kernel admin passthrough (`kprobe`).
- Write zeroes / deallocate: direct = `IORING_OP_FALLOCATE` (`ZERO_RANGE|KEEP_SIZE` / `PUNCH_HOLE|KEEP_SIZE`, executed by io-wq; mkfs and lab trims only); cmd = NVMe Write Zeroes / DSM deallocate.
- Errors: cmd = NVMe status (one decode with SpdkDev, `nvme::nvme_status_err`: sct 2 = media, generic sc 7/8 = aborted); direct = errno (`ENODATA`/`EILSEQ` = media, `ECANCELED`/`ETIMEDOUT`/`ENOLINK` = aborted, other = `Status(errno)`). An `io_uring_enter` error other than EBUSY/EAGAIN/EINTR, or a completion for an empty slot, latches the device ring dead (`is_dead`, loud once): the store fail-stops; synchronous `Sio` waits (mkfs, mount reads, replay) end with a `WARNING TIMEOUT` after 30 s without progress; the post-replay checkpoint wait has no bound of its own (a large replay writes many pages), reports a `WARNING TIMEOUT` line periodically and ends on a failed device (`is_dead`, `Event::Failed`) (am. 10, review D1; SPDK: qpair failure latches the same way).
- IOPOLL rings: evaluated, not built. Needs `nvme.poll_queues` > 0 (module parameter, reload) and the core polls in the kernel during the wait: same CPU/op as SPDK polling, the opposite of this ADR's goal. A per-load option only pays off at high QD where the core is never idle and SPDK already serves it.
- hwcheck (feat/hwcheck): report per OSD which backend is usable (kernel driver bound, `/dev/ngXnY` present, io_uring `URING_CMD`) and the VWC/PLP state; no code here.
- Crash matrices: the device contract (completion = durable, no ordering between in-flight commands, single-LBA atomicity) is the one the simulator already models (`SimDev`); no new store matrix. Backend tests: `cargo test -p nvme --features kernel` on Linux against a file (O_DIRECT) and a loop device; passthrough on the lab VMs (`lab/baremetal/kvnme-func.sh`).

## A/B (interim, doc/perf/kernel-nvme-20261017.md)
- Functional PASS on a PM1743 (both modes, verify, write zeroes, exclusivity); store roundtrip test on a kernel device.
- Zen 4 (4 rounds, BlueStore live): kernel-cmd r4k-q1 CPU 69.9 us/op vs BS 77.7 vs SPDK 88.5 (kernel = the only backend at or below BS); latency +7 % vs SPDK, -11 % vs BS; busy cells (QD16, 64K, writes) SPDK ahead by 5-20 %, kernel >= BS (r64k-q16 TIE). Hybrid park 75 % (1 round): p50 -12 us for +5 % CPU.
- Ice Lake (1 round + stage profile): kd r4k-q1 CPU 162.9 vs SPDK 190.6 vs BS 206.7 in the A/B block, but within noise in the stage block (kc 159.8 vs SPDK 162.5): the interrupt + wake path costs ~25 us/op of guest CPU on these VMs; latency +10 us (pg_exec_store p50).
- cmd > direct in every measured cell. All backends lose r4m-q1 vs BS (store read path, not the backend): open bug, OQ 47.

## am. 1 (2026-10-26): fixed-buffer passthrough and passthrough DSM are probed, not assumed
Context: on kernels without upstream 2ff949441802 ("block: fix sanity checks in blk_rq_map_user_bvec", e.g. Ubuntu noble 6.8.0-147) every `URING_CMD_FIXED` command on the arena fails with EINVAL: the bvec mapping walks every remaining segment of the registration and rejects one past the IO length, so only a buffer at the tail of the registration maps. Read, write and DSM (range list = arena buffer) all fail; mkfs and the OSD cannot start. O_DIRECT `READ/WRITE_FIXED` takes a different kernel path and works. Evidence: doc/perf/kcmd-fixed-probe-20261026.md.
Decision:
- Cmd mode, at namespace open: `probe_fixed_cmd` reads 16 KiB at LBA 0 into an arena span that straddles a 2 MiB boundary in the middle of the registration (multi-page, non-zero offset, not the tail), then writes the same bytes back (FUA per VWC, as production writes), both with `URING_CMD_FIXED` on a private ring. A fixed command that fails with EINVAL is repeated once without the flag: plain ok = capability missing -> cmd mode submits without `URING_CMD_FIXED` (arena memory kept, per-IO page pinning) and logs one `WARNING kernel-cmd <dev>: this kernel lacks fixed-buffer NVMe passthrough ...` line; plain also failing or any other error = open fails with context. Success logs `fixed-buffer NVMe passthrough probe ok (IORING_URING_CMD_FIXED on)`.
- Same probe, passthrough DSM (ONCS DSM only; am. 8: no longer at open, mkfs only): one attribute-free DSM (no deallocate, no data change; range list in the arena, FIXED per the verdict above). An NVMe status = the kernel/device pair rejects passthrough DSM (seen: Intel P5520 on Debian 6.12.111, 0x4002 for every passthrough DSM while the kernel's own discard works): `Geometry::dealloc` false (no runtime trims, as direct mode), the whole-device mkfs discard is `BLKDISCARD` on the claimed block node (claim opened for write), one `WARNING kernel-cmd <dev>: the device rejects NVMe passthrough DSM` line. An errno fails the open.
- Runtime: no retry. A `URING_CMD_FIXED` completion with EINVAL, or a DSM with an NVMe status, after a passed probe logs an `ERROR kernel-cmd ...` line with op, LBA, length and is returned as an IO error.
- Siblings: O_DIRECT fixed (bio path, measured working on 6.8), SPDK (user-space driver, no kernel mapping; its DSM works on the same Intel drives) and the RDMA arena registration (ibv_reg_mr, no block layer) do not use these kernel paths: not affected. Direct mode already discards via BLKDISCARD without runtime trims.
Rationale: a capability probe on the real device with the production command shape is the only reliable test (no kernel-version gating, distros backport; the DSM rejection depends on kernel and firmware); one probe per open costs two 16 KiB IOs and one hint DSM.
Consequences: on kernels with the capability nothing changes (FIXED on, QD1 4K latency/CPU equal to main). Without it cmd mode runs with per-IO pinning (CPU cost not yet measured on 6.8).
Open questions: CPU/op of plain vs fixed passthrough on 6.8; descriptor-level cause of the DSM rejection (suspected: SGL for user commands, kernel 6.13 / 6.12.y).

## am. 5 (2026-10-26): kernel 7.2 store-ring features: measured, not adopted
Decision: the store ring keeps `SINGLE_ISSUER` + SQE128/CQE32 + `URING_CMD_FIXED`. Measured on bare metal (7.0, rep3, ABBA) and not
adopted: (a) `DEFER_TASKRUN` with a registered eventfd as the knet wake: QD32 IOPS -6 % (read) / -11 % (write), p99 worse;
(b) IOPOLL (host `nvme.poll_queues` > 0): QD32 read IOPS -18 %, p99 5x, CPU per op up to 2.6x; (c) hybrid IOPOLL (6.13; needs a
builder setter io-uring 0.7.15 lacks): QD32 -7 % / -15 %, CPU per op up to 2.5x. QD1 and 4M tie. Evidence: doc/perf/kernel72-features-20261026.md.

## am. 6 (2026-10-27): io_uring policy and unprivileged passthrough probed at open (old-kernel fallback)
Context: kernel gate (lab/e2e/kernel-gate.sh) on AlmaLinux 9 (5.14.0-687.el9): (a) default `kernel.io_uring_disabled=2`: `croit-flashstore-tool prepare` ended in `mkfs: Io(Aborted)` (the device ring was first created at the first submit; its error became `SubmitError::Dead`); (b) with `=0`: `activate` (user ceph) refused `Permission denied`: the RHEL 9 NVMe passthrough permission check refuses Identify (and passthrough IO) to a process without CAP_SYS_ADMIN, which the OSD does not have (adr 0056). Upstream 6.2+ allows unprivileged Identify and IO on a writable open; NVMe Get Log Page (SMART) needs CAP_SYS_ADMIN on every kernel.
Decision:
- `KernelCtrl::open` creates one small io_uring first: a refused ring fails the open with the host cause and exact fix (crate `uring-access`, same text as knet, adr 0053 am. 11). A later device-ring failure logs one `ERROR kernel store: device ring: ...` line.
- Identify refused with EACCES/EPERM = capability `UNPRIV_PASSTHRU` missing. Fallback: geometry from sysfs (`queue/logical_block_size`, `size`, `queue/write_cache`, `queue/discard_max_hw_bytes`, `queue/write_zeroes_max_bytes`; an integrity profile = metadata/PI, refused like an Identify format; capacity 0 = hidden format, refused with the format hint); atomic write unit 1 LBA (only recorded in the superblock). Cmd mode (`/dev/ngXnY`): passthrough IO is refused the same way, so the namespace runs in direct mode on its block device (one `WARNING kernel-cmd ...` line; startup line `store backend kernel (direct) ...`). Mapped LVs (klinear) use the same fallback for the backing namespace.
- Startup line: `croit-flashstore-osd: store backend kernel (<mode>) <dev> nsid N vwc=.. max_xfer=.. KiB missing=[..]`, names: `UNPRIV_PASSTHRU`, `URING_CMD_FIXED` (am. 1), `PASSTHRU_DSM` (am. 1).
- The SMART refresh error names the cause (admin command allowed to CAP_SYS_ADMIN only). No SMART for a non-root OSD on this backend (all kernels); identity strings stay from Identify.
- No non-io_uring store path (adr 0053 am. 11).
Siblings: knet (same `uring-access` refusal line, am. 11 of adr 0053); SPDK (vfio, no kernel passthrough or io_uring): not affected; rados-rt client rings: own epoll default (adr 0402), not affected.
Rationale: probing the real permission at open is the only reliable test (distro backports; RHEL 9.8 5.14.0-687 ships a 6.2-style check function yet refuses Identify to the OSD, gate 2026-10-27); sysfs carries everything the store uses from Identify except the atomic write unit, for which 1 LBA is the store's minimum contract.
Consequences: kernel storage works as a non-root OSD on kernels without unprivileged passthrough (direct mode); cmd mode there is direct mode. Gate: doc/perf/kernel72-features-20261026.md "Fallback gate".

## am. 7 (2026-10-28): whole NVMe namespaces only; adr 0468 (linear LVM) superseded
Superseded in part by adr 0646 (2026-11-03): the bounded linear-LVM mapping is supported again; the rest stands.
Decision: `KernelCtrl::open` accepts only a whole NVMe namespace (`/dev/nvmeXnY`, `/dev/ngXnY`). A partition node, a namespace with partitions, an LV / dm device or any block device without namespace ioctls (lab loop/null_blk excepted, feature `lab`) fails with `croit-flashstore-osd needs a whole NVMe namespace: <dev>`. The `klinear` opener (dm-linear table validation, mapped geometry, backing-partition checks) is deleted, no switch left.
Rationale: no filesystem/LV/partition in the OSD data path; identity, PLP, LBA format and durability checks stay on the real namespace; one device model for kernel tier and SPDK.
Consequences: lab layouts that put croit-flashstore-osd on an LV use a namespace instead (lab/omap-matrix: `NVME_NS_WWID`). The classic BlueStore arm may still use an LV (not an croit-flashstore-osd device).

## am. 8 (2026-10-30): the DSM capability probe runs only at mkfs in the production shape and is persisted; opens send no probe DSM
Context: a ScaleFlux CSDU5SXC38 executes an attribute-free DSM (NR 0, cdw11 0) as a deallocate. The am. 1 probe sent one such DSM over LBA 0..7 on every cmd-mode open: the superblock was wiped (`superblock: NotFormatted` on the next start, an existing store destroyed on restart). The fixed-buffer probe (16 KiB read, same bytes written back) is harmless and stays.
Decision:
- Passthrough DSM probe = `KernelCtrl::probe_dsm_at_mkfs`, called only by mkfs when it creates a store (`discard_namespace`, before the whole-namespace deallocate, also when `--no-discard` skips that). Production shape: deallocate attribute (AD, cdw11 bit 2) over LBA 0..7, the blocks mkfs clears anyway (without the deallocate: the blocks the fresh store's format overwrites). The attribute-free variant is gone.
- Verdict persisted in the superblock: feature `FEAT_DSM_VERDICT` (bit 21, incompatible, set by mkfs only with a verdict) + one byte (1 accepted, 0 rejected). Without the bit the verdict is unknown.
- Opens (`KernelCtrl::open`, `croit-flashstore-tool` fsck/inspect/repair/upgrade, the daemon) send no DSM. Mount (`mount_dev`) applies the superblock verdict (`apply_dsm_verdict`) before the store builds its shards; runtime deallocate = cmd mode and verdict accepted.
- Old stores (no verdict): no passthrough DSM (the rejected-DSM path: runtime trims through the block node where the kernel has `BLOCK_URING_CMD_DISCARD`, adr 0642; mkfs discard = BLKDISCARD), one `WARNING kernel-cmd ...: DSM verdict unknown` line per mount. Re-prepare the OSD for passthrough DSM. `--no-discard` skips only the whole-device deallocate; the probe (LBA 0..8, overwritten by the store format) runs anyway and its verdict is persisted.
- Older builds refuse a store carrying the bit (unknown feature), so none of them runs its own open-time probe on it.
Rationale: a probe that can change data must run only where the change is already intended; the mkfs deallocate covers the same LBAs, so the probe's own effect is nil there. Persisting the verdict makes runtime behaviour a property of the store, not of each open.
Consequences: runtime trims on kernel cmd stores exist only after a mkfs with this build. Existing stores keep working without them (no data change). Opens cost one fewer command.
Open questions: why am. 1 chose the attribute-free DSM: rationale not recorded (no open decision).
Evidence: unit tests (`dsm_verdict_gates_runtime_deallocate`, `dsm_verdict_roundtrip`); live check on the ScaleFlux drive pending (coordinator).

## am. 9 (2026-10-31): direct mode fails closed on the write cache
Context: durability in direct mode is `RWF_DSYNC`, which the kernel turns into FUA / flush only while `queue/write_cache` says "write back". The sysfs fallback read an unreadable attribute as no volatile cache (writes without DSYNC), and a namespace whose Identify reports VWC while the kernel was told "write through" acked writes before they were durable.
Decision: an unreadable `queue/write_cache` counts as volatile (DSYNC on, like lab block devices). Direct mode refuses a namespace with Identify VWC and `write_cache` = "write through"; the error names the fix (`echo 'write back' > /sys/class/block/<dev>/queue/write_cache`).
Rationale: ack only when durable (adr 0008); the OSD does not change host settings, it refuses with the fix.
Consequences: a host that forced write-through on a volatile-cache device must restore "write back" before the OSD starts in direct mode.
Siblings: cmd mode and SPDK send FUA from Identify: not affected; lab block devices already failed closed.

## am. 10 (2026-10-31): a failed device latches `is_dead` on both tiers (kdev: any `io_uring_enter` error other than EBUSY/EAGAIN/EINTR; SPDK: qpair failure), mount ends on a dead device; one NVMe status decode (`nvme::nvme_status_err`) for SpdkDev and KernelDev. Review: hardening 2026-10-31 store-space D1.

## am. 11 (2026-11-01): passthrough names only registered-arena buffers; every other buffer is O_DIRECT IO on the block node
Context: mixed lab cases 12/07a/19/20 (case 20 = 900 x 4 MiB writes under the memory envelope: 888-899 of 900 failed) ended in errno 14 (EFAULT) on 256 KiB cmd-mode writes from aligned payload views (plain user address, no `URING_CMD_FIXED`). The memory was mapped and unchanged (lab free-guard allocator and crc view guard silent: no early free in the OSD). Kernel return probes (lab/docker/mixed/trace-map-efault.sh, Debian 6.12.111): the inline issue fails with -EAGAIN (`REQ_NOWAIT` tag allocation, ~15k times in the run), io_uring punts the command to an io-wq worker, there `nvme_map_user_request(ubuf=0x2001dd60000)` calls `pin_user_pages_fast(0x1dd60000)` -> -EFAULT; per worker deterministic (one worker failed 20 of 20, the others none). Cause: `nvme_to_user_ptr()` truncates to 32 bits when `in_compat_syscall()`; in an io-wq worker that is not a property of the ring: on x86_64 with `CONFIG_X86_X32_ABI=y` `in_x32_syscall()` tests the X32 bit of the worker's inherited `pt_regs->orig_ax`, which is set (`~vector`) when the worker was created by task_work on an interrupt return. Mainline (2026-11) still converts this way. A truncated address that happens to be mapped would write wrong memory to the device, read into wrong memory, or deallocate LBAs from a wrong range list: data safety, not only availability.
Exposure: x86_64 kernels with `CONFIG_X86_X32_ABI=y` (Debian 13 6.12.y on every lab VM and the build host: y; Ubuntu 7.0 (tsrv2): not set; RHEL/Alma 9: not set; arm64 compat = per-process 32-bit flag: not exposed), cmd mode, a non-arena buffer (payload views; arena-miss heap buffers; `alloc_buf_ram_uninit` reads; am. 1 plain retry and plain mode without fixed passthrough), and an inline -EAGAIN (queue tags exhausted or queue entry would block). Direct mode and `READ/WRITE(_FIXED)` are not exposed (`u64_to_user_ptr`, no compat conversion).
Decision:
- Cmd mode: a passthrough command names a data buffer only when it is in the registered arena on a ring that registered it (`IORING_URING_CMD_FIXED`; the kernel imports it by registered range). Every other read/write is an O_DIRECT `READ/WRITE` (`RWF_DSYNC` on VWC) on the namespace block node, registered per queue as fixed file `MAX_QUEUES + q`; its completion is decoded as direct mode (bytes / errno). `kdev::passthrough_ok` is the one rule; `entry` asserts it.
- The block node (`claim`) is opened `O_DIRECT | O_EXCL` and is required: cmd mode without it fails the open with the fix (`pass /dev/nvmeXnY too`). Direct mode's write-cache check (am. 9) applies to both modes.
- The am. 1 plain retry is gone: fixed passthrough EINVAL = capability missing = the namespace runs in direct mode (`missing=[URING_CMD_FIXED]`, one `WARNING kernel-cmd ...` line).
- DSM: the range list must be a registered-arena buffer: runtime deallocate with an arena miss is `QueueFull` (retry later); the mkfs probe fails with context.
- Second defect (same punt): 6.12.y reads a punted `URING_CMD` SQE from ring memory in the worker (no prep copy); the crate refilled SQEs in tail order, so a worker issued a LATER command (trace: opcode 23, nsid 0 -> EINVAL; a later passthrough = its IO under the earlier user_data, silent loss). Every command now owns an SQE index until its CQE is reaped (`kdev_sq::SqOwn`, SQ indirection array).
- Queue depth <= blk-mq tags (`queue/nr_requests`, startup `tags=`): fewer -EAGAIN punts (latency only).
Rationale: the kernel defect is outside our control and present in mainline; naming only registered buffers removes the user-pointer conversion from every passthrough command on every kernel without version gating. O_DIRECT on the same namespace keeps zero copy for payload views.
Consequences: payload-view writes (the client write path) take the block-layer O_DIRECT path instead of passthrough; cost measured in doc/perf/kdev-efault-20261101.md. Deployments that pass only the ng node must pass the block node too. Kernels without fixed passthrough (e.g. Ubuntu noble 6.8) run direct mode instead of plain passthrough.
Siblings: knet uses only regular opcodes (read at submit, no deferred SQE read; prep copies the SQE, plain addresses via `u64_to_user_ptr`; its `IO_LINK` send chain is safe); SPDK has no io_uring; rustyrados has no uring_cmd: not affected.
Alternatives: the tag bound alone: no guarantee (queue freeze, shared tags); register payload memory (rx pool) as fixed buffers so views stay passthrough: follow-up if O_DIRECT costs measurably.
Open questions: report upstream (nvme ioctl should take compat from the ring, `io_is_compat`); x32 config of the croit OS 7.2 and elrepo kernels.
