# 0054 Peer OSD session placement (connection handoff + socket relay)
Status: accepted
Status note: Partly superseded by adr/0682-remove-afxdp-dpdk-networking.md (2026-11-06): own-stack (AF_XDP/DPDK) port classes and placement is history; the rest stays valid.
Date: 2026-10-11
Context: one `SessionTable` per core (adr 0006/0031); the NIC (RSS) / kernel (`SO_REUSEPORT` hash) lands a classic peer's connection on any core. A SESSION_RECONNECT landing on a core without the peer's session was answered `SESSION_RESET(full)`; classic then drops its whole out queue (sent + unsent, e.g. a pg_query2) and never resends: wedged PGs (oq 15a). A peer's dial racing our dial from `peer_core(osd)` was decided in two different tables (no WAIT/replace), only the `wait_backoff` hack kept it alive.
Decision: sessions of OSD `n` live on core `n % net` (`CoreSpec::peer_core`; our own dials already go there). No directory: the owner is a pure function of the authenticated peer id.
- msgr2 (`Config::home = Some(Home{me,n})`, cluster messenger of multi-core OSDs only): a server-role connection whose authenticated entity is an OSD owned by another core stops before CLIENT_IDENT/SESSION_RECONNECT (parks the frame, `Event::Handoff{osd,owner}`). `Connection::into_handoff` -> `Handoff` (handshake state: framing, crypto, auth result, unsent output, undecoded input; session table and auth handler dropped, so the rest is plain data: `unsafe impl Send`, only `Rc` was the table) -> `Connection::from_handoff(core cfg, core table)` on the owner re-dispatches the parked frame: normal reconnect/ident/race rules run in the one table that holds the session.
- Socket stays on the landing core (a userspace TCP flow cannot move; knet could move the fd, not done: KISS, one mechanism for all tiers). Landing core = byte relay in the `osd` layer (`pipe.rs`), transport drivers unchanged: `XMsg::Handoff/PipeIn/PipeOut/PipeClose/PipeClosed`; the landing link id stays the driver's connection id (`on_bytes`/`poll_output_chunks`/`on_closed`/`IoCmd::Close` are intercepted by id), the owner's resumed link is hidden from `conn_ids()`; its `IoCmd::Close` becomes `PipeClose`. Ordering: single SPSC ring per direction.
- Only authenticated OSDs (cephx name) are placed; clients, mgr, mon, hb messengers, single-core OSDs and auth-none peers are handled where they land (status quo).
Cost: a relayed connection pays one copy + one ring hop per direction. Expected share (net-1)/net of inbound peer connections when both sides dial; our own dials (replication we originate) are never relayed. Avoid on DPDK with a NIC flow rule steering the peer's cluster IP to the owner queue (needs one rule per peer, only valid when one OSD per IP); on knet `--steer cpu` already aligns flows with cores. Revisit with the bare-metal replication matrix; fd move for knet is the follow-up if relay shows in profiles.
Alternatives: shared session directory + session migration to the landing core (PG layer assumes one link per peer on `peer_core`; in-flight `Wire` frames would need forwarding; rejected); broadcast session query on miss (same migration problem); proxy from the first byte (identity unknown before auth).
Tests: `msgr2/tests/handoff.rs` (reproducer: reset + lost frame without placement; resume, no loss, exactly-once with it; new session; dial race), `osd::xcore_tests::placement` (4-core OSD, real handshake through the relay, reconnect on a foreign core resumes, close both ways).
Am. 1 (2026-10-12, knet): source-port steering avoids the relay on the kernel tier. Cluster listener cBPF: core = TCP source port % own cores (IHL-aware, IPv4 listeners only); dials to OSDs bind a port `p % P == own id % P` (P = `--knet-peer-cores`, default own cores; ports from `ip_local_port_range` minus `ip_local_reserved_ports`, 32 tries, else automatic port). Default on with `--steer hash` and > 1 core, off with `--steer cpu`; kill switch `--knet-peer-steer off`. Wrong guess / classic peer / busy port = relay (unchanged correctness). Measured: relayed peer connections 8/4/6/18 -> 0, 4M write size 3 +17 % (doc/perf/knet-vs-bluestore.md). Tests: `knet::tests::peer_source_port_selects_the_cluster_listener_of_the_core` (6 cores, IP options), `src_ports_follow_the_kernel_range_and_skip_reserved_ports`, `kprod::tests::peer_steer_defaults_kill_switch_and_peer_cores`.
Am. 2 (2026-10-15, DPDK tier): dials of cluster peer links (`Osd::dial_remote_core` = `peer_core(whoami)` with the peer's net cores assumed equal to ours) pick a source port that our RSS (`KEY_MS`, round-robin table, assumed identical at the peer) steers to our dialing core AND that the peer's NIC steers to the core owning our session there (`Stack::connect_paired`, ~1/n^2 of the ephemeral ports; none found -> local steering only, as before). The accepted side then needs no relay (one batch copy + 2 cross-core hops per direction less, ~(n-1)/n of peer links before). A wrong guess (other key, queue count or table) only falls back to the relay; a remote queue our RETA never yields skips the paired scan. Measured icelake-6330-host1/02 (osd.6/7/8, 4 cores, mlx5, interleaved A/B, origin/main df2c5e63 vs paired, script `lab/baremetal/paired.sh`, removed in 51a77491d5): relayed links among the 3 OSDs 1-3 -> 0 (remaining handoffs: lab VM peers); rep3 4M t16 1 proc 2052/2051/1873 -> 2369/2238/2293/2201 MB/s (+14 %), 4 procs 2255/2295/2122 -> 2334/2376/2342 (+6 %); EC k2m1 4M t16 2365/2800/2289 -> 2525/2651 (noise); rep3 4K QD1 3740/2631 -> 2678/2437 IOPS, 8xQD16 38.5k/35.4k -> 38.1k/33.3k (noise, 2 rounds). Test: `net::rss::tests::paired_opens_are_steered_at_both_ends` (incl. an unreachable remote queue).
Am. 3 (2026-10-19, knet -> own-stack peer): knet dials also aim at the RSS queue of an own-stack (AF_XDP / DPDK) peer. Before, the port class `p % P == whoami % P` (am. 1) placed the link on a kernel-tier peer only; an AF_XDP peer accepted it on the Toeplitz queue of the 4-tuple (random w.r.t. the class) and relayed ~(P-1)/P of knet peer links. Now the dial prefers a class member whose Toeplitz hash under the own-stack model (`KEY_MS`, equal table of P queues over `NV_EXT_RETA` entries, default 64, same model as am. 2 / `dpdk.rs`; `rss::ext_reta_size`, `listen::peer_rss`) is queue `whoami % P` too (~1/P of the class, linear scan from a random member); no such port free -> class only (as before). Kernel-tier peers ignore the hash (port filter): unchanged. Wrong model (other key / table / queue count) = relay, still correct. Cost: <= class size Toeplitz hashes per dial (dials are rare). Test: `knet::tests::dial_ports_land_on_the_peer_core_by_port_class_and_by_rss` (P 2/4/6/8, every core, fallback). Siblings: DPDK/AF_XDP dialer already paired (am. 2); knet listener side unchanged; rep/EC, crc/secure: transport-only.
