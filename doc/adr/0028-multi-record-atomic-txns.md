# 0028 Multi-record atomic txns in the WAL ring (amends 0021, supersedes 0026 bound)
Status: accepted
Date: 2026-10-09
Context: 0021 limits one txn to one WAL unit (`max_unit_blocks`, 64-256 KiB record). Big PG txns (whole-log claim with thousands of entries + dups, big missing sets, large omap batches) were Rejected; 0026 bounded the pg log to 100-150 entries as workaround (short outage = backfill). 0027 (single-IO clog) was rejected; the ring stays.
Decision:
- A txn whose record encoding exceeds one unit is written as a CHAIN of K units, contiguous in ring order, never interleaved with units of other txns (all K are sealed synchronously in one `submit`; the open group-commit unit is closed first). Unit header flags: `FLAG_PART` (parts 0..K-2), `FLAG_END` (part K-1); header `ntxn` = part index; payload = a slice of the ONE record encoding (`encode_record`, unchanged); all parts carry the txn's lsn as `first_lsn` and consume no lsn (END consumes it). prev_crc chain, epoch rule, payload crc, shard check apply per unit exactly as before. A wrap PAD may sit between parts.
- Replay: parts are collected; the txn applies ONLY if indices 0..K-1 are consecutive, END is valid and the reassembled record decodes (lsn == chain lsn, no trailing bytes) and all its data extents pass the crc check (parallel-commit rule, whole txn = unit of validation). Otherwise the whole chain is dropped and the log ends there (valid-prefix rule; ring head = start of the dropped chain, so later incarnations overwrite it; stale parts cannot revive: chain crc + epoch). No lsn gap, nothing partial ever visible.
- Ack: strictly in unit order after all K units, the END unit and the data writes of the txn are durable (data writes are attributed to the END unit). Durable lsn advances only at END.
- Admission/space: the whole chain's ring blocks are required up front: `free >= chain_blocks + 2*max_unit_blocks` (one PAD + slack), else `WalFull` (+ forced checkpoint; retry after `Released`). Cannot deadlock: a checkpoint releases every sealed unit, so waiting always ends. A chain larger than `wal_blocks/2 - 2*max_unit_blocks` is `TxnTooLarge` (nothing applied). Ring sizing: max txn ~ ring/2; default ring 1 GiB (max txn ~512 MiB); labs with rings < 16 MiB cap txns at a few MiB (a 10000-entry claim + 3000 dups is ~3 MiB).
- Checkpoint boundary stays an END/normal unit (parts are `RingUnit.part`, never a release boundary nor mistaken for a PAD).
- Meta admission estimate (`State::prepare`): was `height+2` pages per op (5/key, ~40000 pages for an 8000-key txn). Now: distinct clean pages on all probed paths (shared pages once, already dirty pages free) + split bound (`leaves + 2*put_bytes/psz`, +1/8 for parents, + height) via `Tree::probe_path`/`PathSet`. Cache guard: distinct path pages + queued wants <= cache/4 (was ops*height). ENOSPC semantics unchanged (`Busy` while a checkpoint can help, else `NoSpace`).
- PG log defaults restored to Ceph's (spec/pglog.md): min 250, max 10000, trim_min 100, trim_max 10000, dups 3000 (peering `Config`). Backfill claims (<= max_pg_log_entries + dups) are one atomic txn.
Consequences: + no size cap on PG/omap txns short of ring/2, no backfill-after-short-outage; + replay/format change is additive (old logs have no flags). - a chain occupies ring contiguously and delays group commit behind it; cost per part = one more IO and a 64 B header (<0.1% at 256 KiB); big txn CPU ~1.4 us/key (tree inserts), 85-850 MB/s/core by key size (perf.rs `microbench_big_multi_part_txns`).
Tests: store `tests/multi.rs` (per-part fates: drop/torn at every part, END lost, data extent lost, ack rule with jitter, ring wait + checkpoint, > ring/2, 8000 keys on a small meta region), `crash.rs` matrices with 15-30% multi-part txns (every IO boundary x drop/persist/mixed, ring wrap with PADs inside chains, multi-generation), storeadapt `tests/bigtxn.rs` (LogReplace 5000+3000 dups, Missing 5000 + PutInfo, > ring/2 Rejected) and crash matrices (every boundary).
Alternatives: jumbo single unit (one crc over MBs, one DMA buffer > max_xfer: fine for atomicity, rejected for buffer size and split IO); txn ids with interleaving (parallel chains: more replay state, no benefit); chaining in the adapter (partial apply on crash).
