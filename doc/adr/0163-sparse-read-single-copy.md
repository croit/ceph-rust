# 0163 Sparse read replies: one pass over the payload
Status: accepted (no switch: pure bug fix + removal of a copy; wire bytes unchanged, test-checked)
Date: 2026-10-17
Context: scoreboard 2026-10-17 lost 4M seq read (nv kernel tier vs BlueStore): BW 0.87 (QD1) / 0.89-0.93 (QD8), CPU/op 0.66-0.80, p99 0.76. librbd (fio rbd) reads with SPARSE_READ (0x1205), not READ: the 4M reply was built by `sparse_out`, which copied the store's result Vec into a new Vec. On-CPU profile (icelake-6330 VM, dwarf call graph, s1 r4m1, 744 non-idle samples): fused DMA-buf -> Vec copy+crc 19 %, `sparse_out` copy 15 %, **`Vec` regrow inside `sparse_out` 17 %** (capacity guess `16 + 4 + n` is 4 bytes short of the 24-byte header: realloc to 8 MiB = a 4 MiB copy plus a block outside the EAL 4 MiB pool class), **EAL `rte_free` of that 8 MiB block 16 %** (`malloc_elem_free` zeroes the freed block). Plain READ (rados bench, krbd) never hit this. Everything else of the 4M read path was already minimal (crc from block crcs by combine, msgr2 by reference, `SendMsgZc` with `zc_copied` 0).
Decision:
1. `sparse_out` sizes its Vec exactly (stays pooled, no regrow).
2. (replaced by adr 0043 am. 13) The sparse read output is pieces: the 24-byte header (extent map + length, its own crc) followed by the data pieces of `ObjView::ov_read_shared` untouched (store DMA / prefetch buffers by reference, no copy; EC: the decoded cache slice). The header-in-front read (`ov_read_crc_head`, `Store::read_crc_head`, `sparse_out_headed`) is removed. 0-byte reads: the header piece only.
3. lat-trace counts SPARSE_READ as a read (stage tables for rbd reads); `stage-profile.sh` cells r4m1 r4m8 r4k64 r64kq16, `leaf.sh` (self-time symbols), `NVCAP` (call-graph env for the nv capture), `read4m-ab.sh` / `read4m-sum.sh`.
Result (icelake-6330 VMs, prof builds before/after, 2 rounds alternating, s1 + r3; doc/perf/read4m-20261017.md): r4m1 BW 880 -> 1341 MB/s, p50 4.49 -> 2.95 ms, CPU/op 3755 -> 1831 us; r4m8 BW 2536 -> 3291, CPU 3812 -> 2146; r64k-q16 CPU 123 -> 113; no cell worse. vs BlueStore (scoreboard CSV, prod build vs prof build here): 4M read BW, p50, p99, CPU/op win in s1 and r3, QD1 and QD8.
Consequences: remaining passes per payload byte for a 4M sparse read: 1 fused copy+crc (cold DMA buffer, ~0.16 ns/B). Not done (measured candidates, no need yet): NT-store destination (needs 64 B aligned data start: head pad to 64), reading the NVMe straight into the reply buffer (PRP alignment: head pad 4096, read-only verify crc; prefetch must then own the destination), copy+crc of a command's blocks as it completes instead of after the last one (latency; the crc half is done by adr 0043 am. 14), pool classes for 128 KiB..3 MiB payloads (EAL free zeroes those too: 1 MiB reads pay a 1 MiB memset per op; same for the rx buffers of such writes).
Tests: `exec::sparse_tests::sparse_read_output_decodes_and_its_crc_hints_are_the_crcs_of_the_pieces`, `store tests/obj.rs shared_read_*`.

## Amendment 2026-10-17: pool size classes 128 KiB..4 MiB+64 KiB
Where: `net::dpdk::HugeAlloc` (EAL heap, `rte_free` memsets every freed block: DPDK keeps free heap memory zeroed for `rte_zmalloc`; library behavior, not a security rule: the global allocator does not promise zeroed `alloc`, and `alloc_zeroed` still zeroes). Before: only (3 MiB, 4 MiB+64 KiB] was parked in a pool; 128 KiB..3 MiB blocks (1 MiB rbd objects, 1 MiB write rx buffers, EC chunks/shards >= 128 KiB, any Vec/Bytes in that range) paid a memset per free plus heap search per alloc.
Change: 9 classes (KiB: 192, 320, 576, 832, 1088, 1600, 2112, 3136, 4160; step <= 1.8x, +64 KiB header slack as before), 16 lock-free slots each, request rounds up to its class, free parks without zeroing, `alloc_zeroed` zeroes only the requested length. Failed budget reservation drains the pool, then retries (parked blocks of other classes cannot starve a request). Over-aligned (> 64) and > 4160 KiB requests unchanged. Read, write rx and EC share this allocator: one fix. Requests < 128 KiB never touched the EAL heap (mimalloc), so 64K cells have no zeroing to lose.
A/B (prof 610b0a9 vs fc2607e, s1+r3, 2 rounds alternating, cells r64kq16 w64k r4m1 w4m1 r4k1; doc/perf/zero-free-20261017.md): no cell worse (latency <= 1.01, CPU <= 1.00); w64k CPU/op 0.94-0.97, w4m1 0.96-0.98, r4k1 0.97-0.98 (small, partly noise); r4m1/r64kq16 unchanged (already in class / below threshold). 1 MiB-class benefit is by construction (no memset per op), not measured by these cells.
Tests: `net dpdk::pool_class_tests` (Linux, `--features dpdk`, build host).

## Amendment 2 (2026-10-20): classes up to the 128 MiB object limit, page-aligned blocks, counters
Finding (ice-b call graph, c64mL write, TCP): 3.94 % OSD CPU in `memset` <- `rte_free` <- `nv_big_free`: payloads above 4160 KiB (every 64 MiB object payload) were freed for real (memset of the whole block) and allocated by heap search.
Change: classes continue above 4160 KiB at steps <= 1.5x (KiB: 6208, 8256, 12352, 16448, 24640, 32832, 49216, 65600, 98368, 131136); 19 classes cover requests up to 128 MiB + 64 KiB. Slots per class = 128 MiB / class clamped to 2..16 (16 up to 8 MiB, 2 from 64 MiB): parked bytes per class <= max(128 MiB, 2 class) <= 256 MiB; process bound = the huge budget (parked bytes stay in `HUGE_USED`, a failed reservation drains every parked block: the sum over 19 classes is capped by the budget, ~1 GiB is a ceiling of the slot arrays, not retained memory; the budget is EAL hugepage memory fixed at start, outside the heap envelope, adr 0175; test `mapped_payload_budget_falls_back_to_copy_and_returns_capacity`). Waste: block <= 1.8x (<= 4 MiB) / 1.5x (above) of the request. Pooled blocks are 4 KiB aligned and requests with align <= 4096 are pooled (kernel-NVMe 4 KiB-aligned heap buffers >= 128 KiB took the unpooled rte_malloc/rte_free path under `NV_HUGE_ALLOC`); align > 4096 stays unpooled.
Counters (`perf dump`, logger `flashstore_payload_pool`, dpdk builds): `used_bytes`, `limit_bytes`, `fallbacks`, `unpooled_allocs|frees`, per class `c<KiB>_hits|misses|frees` (frees = `rte_free` calls = memsets). Steady state: frees ~ 0 per class.
Siblings: SPDK tier `DmaBuf` frees through `spdk_dma_free` = `rte_free` (same memset), pooled per thread only up to 1 MiB: fixed in am. 3. Kernel-NVMe tier: arena bump + thread bins, heap buffers via the global allocator (affected only through this pool when `HugeAlloc` is active, fixed here); no memset of its own.

## Amendment 3 (2026-10-20): SPDK `DmaBuf` recycling for buffers above 1 MiB
Finding: SPDK tier `DmaBuf` freed through `spdk_dma_free` = `rte_free` (memsets the whole block); the per-thread pool only recycled 4 KiB-multiple sizes up to 1 MiB, so every 4 MiB+ read/write buffer paid a full memset plus heap search per op (sibling of am. 2).
Change (`nvme::dmapool`, feature `spdk`): lengths above 1 MiB up to 128 MiB + 64 KiB are allocated at the size of the smallest of 15 classes (MiB: 1.5, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48, 64, 96, 128, 128 + 64 KiB; steps <= 1.5x) and parked per class in the thread-local pool (any length of the class, not only 4 KiB multiples; the class tail is never exposed, `len` stays the request). Bounds per thread: slots per class = 128 MiB / class clamped 2..16 (parked per class <= max(128 MiB, 2 class)); all parked bytes (small bins + classes) <= 256 MiB (was 128 MiB). Above the last class: unpooled. Exact-size bins <= 1 MiB unchanged. A pool is drained when its thread exits.
Memory pressure (same rule as am. 2): a failed `spdk_dma_malloc` bumps a process-wide epoch and drains the caller's pool, then retries once; every other thread's pool drops its parked blocks at its next pool operation (no cross-thread access, no locks). The payload pool is not reused: it lives in crate `net` (DPDK builds, global allocator, `Bytes` ownership) and `nvme` must not depend on it; both draw on the same EAL heap.
Zero fill: none to remove. `DmaBuf::new_uninit` already allocates with `spdk_dma_malloc` (not zmalloc) and tracks `initialized`: device reads and full-overwrite copies set it, CPU slice access zero-fills lazily only a never-written buffer. `DmaBuf::new` zeroes by contract (callers that overwrite fully use `alloc_buf_uninit`).
Counters (`perf dump`, logger `flashstore_dma_pool`, spdk builds): `parked_large_bytes` (gauge), `pressure_drains`, `shelf_bytes` (gauge) / `shelf_hits` (cross-core return of shared read buffers, adr 0043) / `shelf_refused` (puts over the cap or into a full shelf: the dropping thread pools the buffer, nothing is lost), `unpooled_allocs|frees`, per class `c<KiB>_hits|misses|frees` (frees = `spdk_dma_free` calls = memsets; steady state ~ 0). Exact-size bins <= 1 MiB are not counted (hot path, no shared atomics).
Kernel tier shelf (adr 0043): arena memory is bounded and never freed, so its 128-slot shelf has no byte cap; counters `kshelf_bytes|hits|refused` in the same logger (a refused put pools the buffer on the dropping thread).
Siblings checked: DPDK payload pool (am. 2, same scheme); kernel NVMe tier (no memset of its own); replicated / EC and crc / secure share `DmaBuf`; knet / AF_XDP not affected (store side).
Tests: `nvme dmapool::tests` (class, slot, cap, epoch logic; pure), `nvme spdk::tests::large_buffers_recycle_within_their_class_without_exposing_the_class_tail` (needs the SPDK env); check script `lab/spdkpool-check.sh`. No lab A/B yet: the benefit is by construction (no memset per op).

## Amendment 4 (2026-10-25): shelf replaced by per-owner inboxes
The 128-slot cross-core shelf and its counters (`shelf_bytes`, `shelf_hits`, `shelf_refused`, `kshelf_*`; am. 3) are gone (adr 0043 am. 13 era, 2026-10-21): a buffer dropped by another core returns through a lock-free per-owner inbox (`nvme::shelf`, MPSC, the owner adopts the chain at its next allocation). Counters: `return_hits` / `return_refused` (SPDK, `nvme::dmapool`), `kreturn_hits` / `kreturn_refused` (kernel tier, `nvme::kdev`), logger `flashstore_dma_pool`.
