# 0056 Non-root operation (user ceph, minimal capabilities)
Status: accepted
Status note: Partly superseded by adr/0682-remove-afxdp-dpdk-networking.md (2026-11-06): AF_XDP capability amendment is history; the rest stays valid.
Date: 2026-10-11
Context: adr 0034 ran as root "for now". Production hosts want the daemon unprivileged (blast radius of a parsing bug on a network-facing daemon). Nothing in the daemon needs root itself (no setrlimit/mlockall/chown/setuid in crates; verified by grep); only device nodes, hugetlbfs and directories need the right owner.
Decision:
- Default = user `ceph` (uid/gid of the ceph packages) with exactly `CAP_IPC_LOCK` (pin DMA memory) + `CAP_SYS_NICE` (RT priority / affinity of other threads) as ambient AND bounding set. No `CAP_SYS_RAWIO`, `CAP_SYS_ADMIN`, `CAP_NET_*` for the production tier (vfio-pci NVMe + vfio/mlx5 NIC VF, DPDK stack).
- Requires vfio with an IOMMU (DMA via IOVA=VA; no physical addresses needed, so `/proc/self/pagemap` stays unreadable). uio_pci_generic / vfio-noiommu lab hosts keep root (`flashstore_user = root` in `[osd.N]`, unit drop-in `root.conf.example`): BAR mmap through sysfs and PA mode need root there.
- Host side (`croit-flashstore-prep@N.service`, runs as root, idempotent): after binding, `chgrp/chmod 0660` of `/dev/vfio/<iommu group>` of every bound device (NVMe + NICs; udev default is root 0600), hugetlbfs dir `chgrp ceph` + `1770`, `/var/run/ceph`, `/var/log/ceph`, `/var/lib/ceph/crash` and the OSD data dir (small; recursive chown only when the top dir is not ours yet) handed to the user, shared claim-lock directory `/run/croit-flashstore-osd` created (claim files are not chowned, am. 4). Conf key `flashstore_user` (default `ceph` with vfio, `root` with uio).
- `croit-flashstore-osd@.service`: `User=ceph Group=ceph AmbientCapabilities=CAP_IPC_LOCK CAP_SYS_NICE CapabilityBoundingSet=` same, `NoNewPrivileges=true` kept (ambient caps survive exec under NNP), `RuntimeDirectory=croit-flashstore-%i` + `XDG_RUNTIME_DIR` (DPDK runtime files; as non-root DPDK does not use `/var/run/dpdk`), `LimitMEMLOCK=infinity` as before. Per-tier drop-in examples: `tier-knet.conf.example` (none needed; optional `CAP_NET_ADMIN` for io_uring zcrx; `kernel.io_uring_disabled=1` needs the user in `kernel.io_uring_group`), `tier-afxdp.conf.example` (`CAP_NET_RAW CAP_NET_ADMIN CAP_BPF CAP_PERFMON` for AF_XDP/af_packet on kernel NICs), `root.conf.example`.
- Container (`run.sh NONROOT=1`, `OSD_UID/OSD_GID` default host `ceph`): runtimes do not give a non-root `--user` ambient caps, and file caps are void under `no-new-privileges`. So the container starts as root with `+SETUID +SETGID` (besides IPC_LOCK, SYS_NICE) and the entry `exec setpriv --reuid --regid --clear-groups --inh-caps/--ambient-caps=+ipc_lock,+sys_nice --bounding-set=-all,+ipc_lock,+sys_nice` before running anything else (SETUID/SETGID are gone from the bounding set afterwards; `no-new-privileges`, `--cap-drop ALL`, read-only rootfs stay). vfio group nodes passed with `--device` keep the host gid, so the host `ceph` gid (same numbers as prep) must match. Not combinable with `UIO=1` / `LAB=1` (af_packet needs NET_RAW/NET_ADMIN as root).
- Not changed: `croit-flashstore-tool prepare` (kernel-TCP mon client + device format) and `activate`'s device/driver checks still run as root by the operator; `activate` as ExecStartPre runs as the daemon user and only reads.
Consequences: + daemon never root on the vfio path, two caps; + lab/uio flows unchanged with a drop-in; - hosts without IOMMU stay root; - `/dev/vfio/N` ownership is re-applied by prep on every start (udev rules would be an alternative: a rule keyed by driver `vfio-pci` + group would hand every vfio device of the host to ceph, rejected: prep touches only this OSD's devices).
Verified: unit tests only (shell syntax checked; no behavior in Rust changed). NOT verified, needs a vfio host: `croit-flashstore-osd@N` as `ceph` end to end (hugepage mapping as non-root, `/dev/vfio` ownership, DPDK runtime dir), container `NONROOT=1` (setpriv drop, ambient caps visible in `/proc/1/status` CapAmb), mlx5 bifurcated NIC (needs `/dev/infiniband/uverbs*` access + CAP_NET_RAW: not covered).
Alternatives: file capabilities on the binaries (void under NNP; EPERM on exec when the bounding set lacks a file cap), user namespaces (rootless podman: no vfio groups), systemd `DynamicUser=` (no stable owner for the data dir / vfio nodes).

## Amendment (2026-10-19, am. 1): AF_XDP tier needs CAP_SYS_ADMIN; non-root vfio path verified
Context: lab/e2e (adr 0461) runs `croit-flashstore-osd@` as `ceph` with the shipped drop-ins. AF_XDP cells: libxdp `couldn't get program fd: Operation not permitted`, then `xsk_configure(): Failed to create xsk socket`, exit 1. libxdp looks the XDP program attached to the interface up by id (`BPF_PROG_GET_FD_BY_ID`), which the kernel allows with CAP_SYS_ADMIN only (CAP_BPF does not cover it).
Decision (user 2026-10-19): `tier-afxdp.conf.example` adds CAP_SYS_ADMIN (ambient + bounding). The daemon stays user `ceph`; the vfio (SPDK) and knet paths keep their caps unchanged (IPC_LOCK, SYS_NICE).
Consequences: + AF_XDP works non-root as shipped; - SYS_ADMIN is broad (near-root for a compromised daemon) on AF_XDP hosts only. Alternative kept for later: prep (root) loads the xsk program and pins its map, the PMD uses the pinned map (no SYS_ADMIN in the daemon).
Verified (lab/e2e CI, nested QEMU, Debian 6.12 kernel, CentOS Stream 9 userspace): `croit-flashstore-osd@N` as `ceph` end to end on the vfio path (prep: hugepages, NVMe -> vfio-pci, `/dev/vfio/N` to ceph; SPDK store; knet; Type=notify; restart from boot after a power cut). The "NOT verified, needs a vfio host" item above is closed for vfio + knet.

## Amendment (2026-10-31, am. 2): SMART on the kernel tier = classic `sudo smartctl` route; unit allows it
Context: kernel 7.2 allows the NVMe admin command Get Log Page (SMART, 0x02) to CAP_SYS_ADMIN only (Identify stays allowed on a read-only open). With the daemon at two caps the direct read fails: `smart` returned `{}`, `ceph device get-health-metrics` empty, no wear / life expectancy in `ceph device ls` / devicehealth. Classic ceph-osd runs unprivileged too and gets SMART via sudo (spec doc/spec/devicehealth.md "Classic SMART probe"); its unit sets `NoNewPrivileges=false` for exactly that.
Decision:
- The SMART refresh thread (never a PG core) reads directly first (SPDK admin queue; kernel passthrough when the kernel allows). A permission error (EPERM/EACCES) on a kernel device switches that thread permanently to the classic route: `sudo -n smartctl -x --json=o /dev/<name>` and, with a vendor, `sudo -n nvme <vendor> smart-log-add --json /dev/<name>`; the published value is smartctl's JSON object plus `nvme_vendor` / `nvme_smart_health_information_add_log`, or classic's error object (`{"error":"smartctl failed","dev",...}`) when a command fails. Each child has a 5 s hard timeout (classic `osd_smart_report_timeout` default), killed by handle, `WARNING TIMEOUT` on expiry. SPDK has no kernel name and never needs the sudo route.
- Startup/journal message says the route (`route: direct NVMe admin command` / `route: classic sudo -n smartctl`) and, on failure, the cause plus the needed sudoers rule and unit setting. Each distinct message is printed once; a failing sudo route retries every refresh (300 s), so installing the rule later heals without restart.
- `croit-flashstore-osd@.service`: `NoNewPrivileges=false` (sudo is setuid); the AMBIENT set stays `CAP_IPC_LOCK CAP_SYS_NICE` (the daemon holds no new cap); the BOUNDING set grows by `CAP_SETUID CAP_SETGID CAP_AUDIT_WRITE CAP_SYS_ADMIN CAP_SYS_RAWIO`, which only a root child of an allow-listed sudo rule can obtain (a bounding set also caps what setuid-root exec may gain: without it sudo/smartctl run capability-less). Tier drop-in examples carry the same additions.
- Host requirement (as classic): `smartmontools`, `sudo`, the stock `/etc/sudoers.d/ceph-smartctl` of the ceph packages (`ceph ALL=NOPASSWD: /usr/sbin/smartctl -x --json=o /dev/*`, `/usr/sbin/nvme * smart-log-add --json /dev/*`).
Consequences: + `smart` / devicehealth identical to classic on kernel-tier hosts without CAP_SYS_ADMIN in the daemon; - NoNewPrivileges=false and the wider bounding set (classic has no bounding set at all): a compromised daemon can run the two sudoers commands as root (same exposure as classic) but gains no capability otherwise; - the proven bounding list was not minimized one cap at a time.
Alternatives: grant CAP_SYS_ADMIN (rejected: near-root); keep `{}` (rejected: blind devicehealth); a root helper service (more moving parts than the packaged sudoers rule).
Sibling check: SPDK tier not affected (admin queue); AF_XDP/knet transport, rep/EC, crc/secure not involved. Classic's `escape_quotes` is a no-op, so an error output containing quotes makes it drop the device; we emit valid JSON instead (adr 0256 spirit, noted in the spec).
Verified: unit tests (JSON passthrough/error objects/vendor derivation/fallback decision); `lab/tests/smart-sudo-vm.sh` on a lab VM (Debian 6.12, nvme-loop namespace, user ceph in a transient unit with the packaged unit's caps): data with the packaged settings, classic error object with `NoNewPrivileges=true` and without the sudoers rule. NOT verified: `ceph tell osd.N smart` on a full cluster.

## Amendment (2026-11-05, am. 3): classic `--setuser` / `--setgroup` drop privileges in-process
Context: review 2026-11-05 (B10): cephadm and the stock `ceph-osd@.service` start the daemon as root with `--setuser ceph --setgroup ceph`; classic drops to that user/group in-process right after config parsing (spec osd-lifecycle.md 3.1a). croit-flashstore-osd ignored the flags and kept running as root, so a binary drop-in into a classic unit ran the network daemon as root.
Decision: croit-flashstore-osd drops like classic, at the same point (daemon start, before store, sockets, pid file): lookups, `setuser_match_path` (classic gate incl. the stay-root WARNING), setgid then setuid, `set_keepcaps`, dumpable. Own additions: supplementary groups = the target user's (initgroups; classic keeps root's), `RLIMIT_MEMLOCK` lifted to unlimited while still root, read-write access check of the kernel NVMe device / file store / data dir as the new user (error names path, owner, mode, fix). Tiers that need root (SPDK storage: vfio + hugepage DMA; DPDK / AF_XDP networking) do not drop: startup WARNING naming the tier, the daemon stays root (documented deviation; never refused). Not root: classic's `ignoring --setuser X since I am not root` note. `croit-flashstore-osd@.service` (non-root unit, ambient capabilities) is unchanged.
Rationale: classic units must work unchanged (cephadm, distro units). The kernel tier needs no capability as a plain user: pinned memory (io_uring registered buffers, RDMA registration) is covered by the lifted memlock limit, `smartctl` already runs through `sudo -n`, CPU affinity of own threads needs no privilege; device and dirs belong to the user via ceph-volume / udev / croit-flashstore-prep@ as for classic. SPDK cannot run unprivileged without the vfio/hugepage handover of croit-flashstore-prep@, so the classic unit keeps root there rather than failing.
Consequences: + classic and cephadm units start croit-flashstore-osd as the ceph user on the kernel tier; + a mis-owned device fails at start with the fix instead of an EACCES deep in the store open; - `croit-flashstore-osd run`'s mon config bootstrap (TCP, reads the OSD dir keyring) runs before the drop; - `HOME` is not changed (classic sets it; nothing in croit-flashstore-osd reads it); - io_uring NVMe passthrough (`kernel-cmd`) as non-root needs a kernel that checks the char device's file mode (classic has no such path).
Alternatives: refuse the flags as root (first version of this amendment; rejected: breaks every reused classic / cephadm unit); keep capabilities (CAP_IPC_LOCK, CAP_SYS_NICE) through the drop (rejected: memlock limit covers the pinned memory, nothing uses CAP_SYS_NICE); ignore the flags (rejected: silent root).

## Amendment (2026-11-06, am. 4): prep creates the shared lock directory /run/croit-flashstore-osd

Context: croit-flashstore-osd's cross-process claim files moved from `/var/tmp` (private under `PrivateTmp=true`) to
`/run/croit-flashstore-osd` (adr 0649 am. 1, adr 0463 am. 1). The daemon runs as the user from `flashstore_user` (default `ceph`) and
must create the lock files there; root tools must reach the same files.

Decision: `croit-flashstore-prep.sh` creates `/run/croit-flashstore-osd` idempotently on every start (`install -d -o root -g ceph -m 1770`),
for both the non-root and the root drop-in. The package additionally ships `/usr/lib/tmpfiles.d/croit-flashstore-osd.conf` with the
same owner/mode and creates the directory in its post-install script. `0750` is not enough: group `ceph` needs write
access, so the mode is `1770 root:ceph` (sticky: root tool state files and the daemon's locks share the directory, so
neither uid may unlink the other's files). Claim files are created `0666` by their first opener (adr 0649 am. 1), so
prep chowns no file in that group-writable directory (a swapped-in symlink would redirect a root `chown`).

Rationale: one root-owned, host-visible directory at boot and before every OSD start; no daemon-side `mkdir` and no
silent fallback (the daemon refuses with the exact fix when the directory is missing or not writable).

Consequences: + non-root daemon and root tools share the claim files with `PrivateTmp=true`; - hosts that run the daemon
as a group other than `ceph` need that group in the `install -d` line (the runtime error names the fix). The other
prep-owned directories (run, log, crash, data) are unchanged.

Tests: `lab/deploy/tests/croit-flashstore-prep-device-source.sh` (dry-run prep), `nvme::pcilock` directory tests (missing and
unwritable directory name the fix). Not verified: a prep run as a non-ceph `flashstore_user` on a real host.

Siblings checked: container mode runs host prep; `lab/spdk-mp-live.sh` and `lab/vstart-bench.sh` create the same
directory as root for their root daemons.

## Amendment (2026-11-08, am. 5): no dumpable restore after the drop
Decision: after setuid the drop sets `PR_SET_DUMPABLE=0` (start fails if it cannot) instead of restoring dumpable 1 like classic (adr 0035 am. 4). Rationale: native cores hold keys and client data; piped core collectors ignore `LimitCORE=0`. Consequences: `gdb`/`perf` attach to the daemon needs root.
