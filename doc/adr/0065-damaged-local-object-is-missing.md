# 0065 damaged local object = missing locally (repair from a peer)
Status: accepted
Date: 2026-10-12
Context: adr 0042 made read/decode errors typed and protected peer copies, but left the repair to scrub (open question 10). Classic repairs a primary read that fails with EIO in replicated pools: marks the object missing on the primary, pulls it from a peer, the client op waits and is served after the pull (`rep_repair_primary_object`); an unreadable object_info on the primary never answers EIO while a peer may still have the object.
Decision (replicated pools only; EC stays as before: EIO / scrub):
- Primary, `Pg::local_damage(oid, known_version) -> bool` (module `damage`): object (head or clone) failed a local read or its object_info/snapset does not decode -> add to own missing (need = known oi version, else newest non-delete log entry, else `NEED_ANY` = 0'1), persist, `REPAIR` state, start recovery (from Clean/Recovered: reservation; from a backfill state: stop backfill, recovery first, backfill resumes behind it). Idempotent. `false` = not an active replicated primary, object deleted in log, offset beyond own last_backfill.
- Pull source = existing `holders` order (acting members not missing it, then strays/backfill targets that already hold the range). All copies damaged/absent -> unfound (`RECOVERY_UNFOUND`), nothing invented; ops keep waiting (classic).
- Version unknown (object older than the log window, own oi unreadable): pull carries version 0'0; replica answers with its own oi version (classic does the same: "requester does not know the version"), `got` accepts any version >= 0'1.
- Engine (`opexec`): `Env::local_damage` on `load_state` EIO and on an op result EIO; true -> op parks in `parked_obj` (counter `parked_repair`), re-runs when the object left missing (`Pg::read_blocked`: own missing item or a damaged clone of the head). The OSD env only forwards a real fault: a store read answered EIO during this op (`eio` flag in `PgEnv`) or `recovery_info_checked` = Corrupt/Io; a cls/client EIO is answered as before (no repair loop).
- Backfill (primary): corrupt/unreadable local object in a scan digest or while pushing -> `local_damage` instead of `Stalled` (only if it returns false the old stall stays). Peer copies are still never removed.
- Replica: a pull it cannot serve (own copy damaged) -> answers blank and marks the object missing (persisted). The primary learns it at the next peering (classic-compatible: no new message; classic has no replica->primary channel) and pushes. Objects beyond the replica's last_backfill are the primary's backfill job.
- Counting: `Pg::shards_repaired` (damaged object recovered) -> perf `osd.shards_repaired` and osd_stat `num_shards_repaired` (`clear_shards_repaired [count]` works as in classic); perf `osd.read_repair` = client ops that waited for a repair.
- Side items of oq 10: `Stalled` backfill retries on a timer (`rec.retry_at`, fixed `PeeringCfg.backfill_retry` = 30 s (`peering/src/types.rs`; `osd_backfill_retry_interval` is not registered as an option); test `stalled_backfill_releases_reservations_and_retries`); SnapMapper check (`snapmap_check`) reports a failed list / unreadable mapper entries as message `SNAPMAP_READ_ERR` -> PG error counter + clog note (never silent); sim `MemMap::next` returns `Corrupt` on an undecodable value (no skipping).
Consequences: + a damaged primary copy heals on first read or backfill touch, clients never see EIO while a peer has the object; classic wire unchanged. - replica damage is only discovered by pulls (and scrub), repaired at the next peering; an op whose object is unfound waits (SLOW_OPS) instead of failing; clone object_info damage found only through snap-read resolution (`resolve_snap`) still answers EIO (open).
Alternatives: probe the peer version with a backfill scan (rejected: GET_DIGEST outside a backfill reservation can abort a classic replica, classic-peer-model 5); new replica->primary "I am damaged" message (rejected: not classic wire); fail the OSD on read error (rejected, availability).
Tests: peering/tests/damaged.rs (primary pull, version unknown, replica -> push after peering, all copies damaged = unfound, classic stand-in replicas, damage during backfill, snapmap read failure), opexec/tests/damaged.rs (op parks, served after repair; no repair possible -> EIO).

## Amendment 1: review (2026-10-12; crates peering/opexec/osd; no format change)
Classic checks (source read): a 0'0 pull is valid for a classic replica (`handle_pull`/`build_push_op`: "requester did not know the version" -> its own oi version; later chunks carry it); a blank push to a classic primary is classic's own failed-pull path (`_failed_pull`: that peer forced missing, other sources tried), the same answer a classic replica gives when its read fails; a replica missing item with need 0'1 makes a classic primary push its oi version (`got` needs need <= v). Replica marking kept.
Fixes (each with a regression test):
- NEED_ANY source = acting peers only. A stray that was out while the object was rewritten served the 0'0 pull: object rolled back to old data (`unknown_version_is_never_pulled_from_a_stale_stray`). No current holder = unfound.
- Peer missing item NEED_ANY (replica damage of an object older than the log): the primary pushes its current version; before, `ri.version != need` skipped it forever, recovery stuck (`damaged_replica_older_than_the_log_is_pushed`).
- Damage while the backfill is held (nobackfill, toofull): recovery reservation starts at once; before, the repair waited for the backfill flag (`damage_while_backfill_is_held_is_repaired`).
- Ops wait while the head OR any clone of it is in the durable missing set (`Pg::read_blocked`, range query); before: in-memory damage set (lost at restart; a snap read of a not-yet-recovered clone answered ENOENT).
- Clone object_info damage (snap read, rollback): `Target::Damaged(clone)` / `Outcome::damaged` -> the clone is repaired, the op waits; before EIO (snap read) or the HEAD was repaired again and again (rollback) (opexec `snap_read_of_a_damaged_clone_waits_for_the_clone_repair`, `rollback_to_a_damaged_clone_repairs_the_clone`, `ops_behind_a_parked_repair_keep_their_order`).
- EIO attributed per object (`PgEnv::eio` = first object whose store read failed; a fault of another object never repairs the target); one repair per object per interval (`rec.dmg_repaired`): a second fault after a repair answers EIO (no loop on a fault a fresh copy does not cure, e.g. a store error that is not damage but maps to EIO).
- Replica: a data/omap read failure while serving a pull marks missing too (was: object_info only). A damaged local copy found while pushing goes through `local_damage` (persisted, last_complete recomputed).
- Crash right after the mark: the durable missing item is repaired after restart, version known or 0'1 (`crash_after_the_mark_still_repairs`).
- Cluster log (ERROR) like classic `primary_error`: `<pg> missing primary copy of <oid>, will try copies on osd.N[,..]` / `, unfound`; replica mark; snapmap read errors. Note prefix `ERROR ` is stripped into a clog ERROR line.
- Perf `read_repair`, `shards_repaired` moved to the `osd` section (were under `bluestore`). Classic has no such counters (only osd_stat `num_shards_repaired`).
OSD-layer test: `osd xcore_tests damaged_primary_objects_are_repaired_from_the_replica_and_served` (2 OSDs, real store on SimDev: rotted data blocks + undecodable object_info on the primary; reads wait, served with the replica's bytes, store copies good, counters 2/2/2).
