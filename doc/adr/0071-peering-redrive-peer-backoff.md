# 0071 peering messages lost with a msgr session are redriven; per-peer back-off
Status: accepted, amended (am. 1 superseded by am. 2; am. 3)
Date: 2026-10-13
Context: icelake-6330 (doc/perf/w4k-cpu.md, findings 2+3): (a) a peering message lost on a faulted link was never sent again, PG stuck in GetInfo until `ceph pg repeer`; the OSD only logged msgr `Fault`/`Reset`/`RemoteReset`, peering never heard of them, and a fault closes the link with its queue. (b) osd.7 sent ~200 k type-130 frames (MOSDPGNotify2) to an unreachable peer (`nodown` set, peer up in the map) in minutes: ActMap ran for EVERY message delivered to a PG at the current map (`advance_pg`), and a stray resent its notify with each. Classic: lossless peer msgr (loss only with a peer restart = new map/interval), one ActMap per map (a stray notifies once per map until activated); no peering timer.
Decision:
1. OSD (`osd.rs on_link_event`, `pgs.rs pg_peer_link`): cluster-messenger links to an OSD (dialled `Peer(o)` or accepted) report `Fault`/`Reset`/`RemoteReset` and a closed peer link as lost, `Connected` as up, to the PgSet of every core (`XMsg::PeerLink`).
2. PgSet (`pgset/peers.rs`), per peer: loss -> `lost` + redrive due after back-off 0 (first loss), then 1 s doubling to `PEER_BACKOFF_MAX` 30 s per further loss or unanswered redrive; READY -> `lost` cleared (single loss: redrive now); any message from the peer resets the back-off. While `lost`, MOSDPGQuery2 to the peer are held at `finish` (the redrive carries them); map churn cannot flood it. Redrive = every PG's `redrive_peering(osd)`. Entries die with peer down / new `up_from` (peering restarts with the map). Peers the map marks down get nothing (unchanged: `finish` drops, probe skips).
3. Pg (`primary.rs`): the primary keeps the last query per peer (`Prim::queries`) and the activations not acked yet (`Prim::act_sent`); `redrive_peering` sends again: GetInfo `peer_info_requested`, GetLog the auth query, GetMissing `peer_missing_requested`, Activating unacked activations (croit-flashstore-osd peers only: a classic ReplicaActive merges a repeated activation log). No timer (am. 3). Duplicates are harmless (msgr replay already produces them; tests with `dup_kind` 1).
4. Replica: a repeated activation (log or info from the primary in ReplicaActive, activation committed) is answered with the activation ack again (the lost message may have been the ack). Classic primaries ignore an extra info in Active (lease ack only).
5. ActMap per message kept (scrub/recovery stepping order depends on it) but the stray notify goes out once per map epoch (`Pg::acted_epoch`).
Consequences: + no repeer for lost query/notify/log/info/activation/ack; + bounded traffic to dead peers (sim: 10 min, 8 PGs, 2 senders: ~330 messages, 24 redrive rounds); + stray notify per map as classic. - duplicate peering messages after every fault (cheap); - activation messages are cloned until acked (one log copy per peer while Activating); - redrive cost O(PGs of the core) per peer per round (rare).
Alternatives: local repeer (enter_reset) on a session loss (heavier, unsafe while the activation commit is in flight); msgr-level replay across fresh sessions (classic peers must never see old-session frames, spec 10.3); fixed-rate requery without per-peer state (no bound under map churn).
Tests: peering/tests/lost_msgs.rs (`lost_query_on_link_fault_is_redriven`, `query_lost_with_a_restarting_peer_is_covered_by_the_new_interval`, `lost_answers_and_activation_are_redriven`, `messages_to_an_unreachable_peer_are_bounded`; Sim `drop_next`/`drop_faults`/`unreachable`); osd xcore_tests `peer_session_loss_reaches_every_core`.

## Amendments
- am. 1 (2026-10-20, superseded by am. 2, code removed): the peer redrive also asks EC sub-reads again (`Pg::ec_redrive_reads`: pending sub-reads to the peer get a new tid, warm reads to it are forgotten, recovery attribute / omap reads from it restart via `ec_recov_redrive`); sub-reads are idempotent, a late answer to the old tid is discarded. Needed since EC sub-reads have no timer (adr 0049 am. 9, OQ 28 O14). Test `ec_primary_sub_reads_lost_with_a_session_are_redriven`. Open: sub-writes, repops, pushes / pulls lost with a session are still not redriven (90-open-questions.md 28 O15).
- am. 2 (2026-10-20, OQ 28 O15): data-plane messages (EC sub-writes, repops, pushes / pulls, their replies) lost or stalled with a faulted cluster connection while the peer stays up. Root cause in the OSD's msgr2 integration, not the PG layer: cluster sessions are `lossless_peer` (spec msgr2.md 10, 11) and the msgr2 session already replays sent-unacked frames on reconnect; three gaps broke it. (a) A link superseded by the peer's reconnect was closed at once with its held input (store / ingress backpressure) and decoded events, which in_seq had already acked: lost. (b) An accepted connection that faulted while the session owed the peer messages was never dialled back (spec 10.7 step 7); the peer (classic: standby with an empty queue) never redials: stalled replies. (c) `peer_transmit` sent on an accepted link already closed for the wire (dropped), and messages of a faulted link still holding input were overtaken by the reconnect's. Decision: msgr2 `SessionTable::take_owed` + `needs_dial` (peer name) -> OSD `pg_dial_owed` (map-current incarnation only); a superseded link with undelivered input is closed for the wire and drains (`Osd::retire_link`); at READY the new carrier takes over the held input and decoded messages of older links of the same session, ahead of its own (`Connection::take_over_messages`, `Osd::take_over_input`); `peer_transmit` skips links closed for the wire. Exactly once and in order per session while both peers stay up; loss remains only with a restart / down (new map: interval change, adr 0049 drop). am. 1 removed (duplicate of the session guarantee). Peering redrive (Decision 1-5) kept: it bounds traffic to an unreachable peer and covers RESET / new sessions. Sibling paths: one integration for every transport (knet, AF_XDP, DPDK compile-only) and both msgr2 modes (crc / secure share session + frame decode), all PG message kinds (rep / EC, peering, recovery). Tests: crates/msgr2/tests/lossless_peers.rs (1000 seeds: socket kills, dial races, role swaps, held input; counter-tests without dial-back / takeover), osd placement_tests `{rep,ec}_sub_writes_held_on_a_{superseded,faulted}_link_*`, `an_accepted_session_that_owes_the_peer_is_dialled_back` (fail without the fix); lab lab/docker/mixed/23-cluster-conn-kill.sh. Open: whether the peering redrive is still needed beyond RESET / unreachable peers (90-open-questions.md 28 O15).
- am. 3 (2026-10-28): the per-PG safety-net timer (`REDRIVE_MIN` 10 s doubling to `REDRIVE_MAX` 120 s, `Pg::redrive_timer` from the 1 s tick) is removed. It covered a silent loss (no fault, no reset reported) while both peers stay up; since am. 2 the lossless cluster session delivers exactly once and in order in that case, so the only silent loss left is a peer process restart, which is a new incarnation in the map: every PG with that peer starts a new interval and peering begins again (classic has no peering timer either). `redrive_peering` takes one peer (the link-event path is its only caller). Test `query_lost_with_a_restarting_peer_is_covered_by_the_new_interval` (lost queries, no fault: PGs stay peering, no redrive; the restarts' new intervals make them clean) replaces `silent_query_loss_is_redriven_by_the_timer`; the silent half of `lost_answers_and_activation_are_redriven` is dropped. Receiver side: with no timer nothing sends a dropped peering message again, so the PG set drops none silently. (a) A PG copy being deleted when a new map puts this OSD into the PG again (classic: ToDelete sits under Started, the new interval interrupts the delete) keeps the messages for it in `waiting_pg` (also notifies / logs that create it, until then dropped as "create while deleting": a primary activating the copy, classic or ours, stayed in Activating = prime safety); the committed delete (`PgRemoved`) routes them in arrival order (`loopq`): a notify / log creates the PG, a query is answered. (b) `waiting_pg` keeps at most `WAIT_PG_MAX` 1024 messages per PG; past it the drop is counted (`waiting for pg: queue full`, `dump_pgs` `dropped`), as every other drop. (c) The old-map parking bound `PARK_MAX` 1024 (PGs, and messages behind one PG) lies above the classic per-OSD PG hard limit (`mon_max_pg_per_osd` 250 x `osd_max_pg_per_osd_hard_ratio` 3); a full queue is a counted drop. (d) A peer message reaching a core that does not own its PG (the routing core's placement table lagged: split child on its parent's shard, moved PG, adr 0031) goes on to the owner (`XMsg::Pg`; the owner's table changes first, so one extra hop at most), was dropped as "pg owned by another core". Tests: peering/tests/remove_remap.rs (copy remapped as replica / as primary while its delete commit is held; fail without (a)); osd xcore_tests `peer_message_routed_by_a_stale_placement_reaches_the_owner` (fails without (d)). Open: a core whose table has not learned the placement yet takes the message as its own (90-open-questions.md). Live: `lab/docker/mixed/25-event-paths.sh` P1 (croit-flashstore-osd SIGKILL / classic stop under load on mixed acting sets, clean after each restart) + case 23 (link faults).
