# 0029 PG split and merge (pg_num changes)
Status: accepted
Date: 2026-10-09
Context: with the default `pg_autoscale_mode=on` the mgr splits/merges pools; until now croit-flashstore-osd refused every pg_num change (`Pg::refusal`): children stayed `unknown`, parents `incomplete`. Spec: `spec/split-merge.md` (+ peering, pglog, replication, osdmap). Classic OSDs in a mixed acting set run the same local transformation at the same epoch, so ours must be bit-compatible in what peers can observe (history, log head/tail, infos), not in how the store does it.
Decision:
- **Math** (`pgwire::pgmath`, pure u32 functions, tests T1-T4 vs brute force 1..1024 + all worked examples): `stable_mod`, `split_bits(seed, n)`, `ancestor`, `parent`, `split_children` (candidates `seed + k*2^(cbits(old)-1)`), merge source/target/sources, `is_pending_merge`, reversed-hash ranges. `opexec` PGLS/backoff ranges use `split_bits` of the seed (non power of two pools have PGs with different bit counts during a merge sequence). Op layer drops an op whose hash is not in the PG (`object_pg(hash, pg_num) != seed`) and ops older than `last_epoch_split` (client resends).
- **Map advance is lockstep** (`PgSet::advance_all/step_epoch`): all PGs process epoch e before any processes a later one; within e merge sources first (quiesce, removed from the PG table, parked), then every other PG: merge targets absorb parked sources BEFORE their AdvMap, parents split AFTER their AdvMap. A PG far behind (restart, missed maps) steps through every retained epoch the same way, so gaps/jumps give the same layout as step-by-step (T12). Maps are never dropped below the oldest PG epoch (U-SM1 avoided). A source whose target is absent locally gets a placeholder target (incomplete, backfilled); a missing source makes the target incomplete (`last_backfill = MIN`, peers backfill it).
- **Split** (`Pg::split_self`, `split.rs`): one txn of the parent = `SplitOut` + rewritten log/missing/info/past_intervals/epoch. Children get log entries and missing items by `object_pg(hash, new_n)`, head/tail/rollback bounds and ALL dups copied, history copied with `epoch_created = E`, `same_primary_since = E` if their primary differs, stats divided (`ObjectStatSum::split`, parts add up) + `stats_invalid`, `parent_split_bits`; non-MAX `last_backfill` -> both MIN and missing cleared. The log head may be newer than the last entry of a child: new `StoreOp::LogSetHead` (merge_log persisted the head only through appended entries; found by the sim). `pg_num` change without a recorded interval still sets `same_interval_since`.
- **Merge**: PG state PEERED+PREMERGE (not ACTIVE: client I/O waits, no scrub) from AllReplicasActivated when `is_pending_merge`; primary reports via `PgSet` registry (`note_merge`): clean + both ready -> `Action::ReadyToMerge{ready}`; undersized at activation -> `ready=false`; once per source per mon session (`resend_mon_requests` clears). Message `MOSDPGReadyToMerge` (type 122, `messages`, spec bytes tested). Execute at the pg_num epoch: `Pg::merge_from` (logs rolled forward+emptied into dups, dups merged sorted, head=tail=max(last_update), missing cleared, stats added, `last_user_version` max, mismatch vs `last_pg_merge_meta` or incompleteness -> `last_backfill = MIN`). `PoolParams.merge_meta` carries the meta from the osdmap.
- **Store** (`storeadapt::split`): objects keep their onode. Same engine shard: `MoveRename` batches (256 objects/txn, no data copy). Different shard (shard = `(pool+seed) mod S` is KEPT, 0021: children of pools with pg_num < S land on other shards): objects are COPIED (data in 4 MiB chunks, xattrs, omap in 1024-key batches), the parent's copies are dropped after its commit. Decision against changing the shard map: any split-stable mapping makes small pools single-shard (child c = parent + k*2^b for b down to cbits(pg_num_at_creation)); cross-shard copy happens only for pools with pg_num < S (S=32 prod) and only once per split.
  Crash safety without a giant txn (multi-record WAL 0028 bounds a txn at ring/2, a 1M-object split would not fit): every step is idempotent and ordered so the durable prefix is redoable from the unchanged parent state at E-1: (1) create child collection, move/copy batches; (2) child PG state in ONE txn (the child exists from here; a complete child is never touched again); (3) parent: ONE txn (state + epoch + coll bits + `_splitout` marker for cross-shard children); (4) drop parent's copies, clear marker (`recover_structural` at mount resumes). Merge mirrors it: move/copy sources into the target, ONE target txn, then `remove_pg(source)` (`_remove` marker, resumed at mount; a source that survived a crash is found past the merge epoch by the PG table and removed). Orphan collections without PG state are removed by `gc_orphans` AFTER the PGs were loaded, never while a possible parent (ancestor seed) is in the store.
  Invariant 11 (atomic with map advance) is weakened to "redoable": a crash leaves objects physically in the child collection while the parent still says E-1; nothing reads the parent before `load_pgs` re-advances it.
- EC stays passive; `Pg::refusal` is only for EC. Replicas never see collection ops in MOSDRepOp (still `Unsupported`).
Consequences: + autoscaler works, mixed acting sets; + split of a same-shard child is O(objects) metadata, not data; - cross-shard split/merge copies data synchronously inside the OSD loop (blocking driver, 0025: heartbeats stall for large PGs; fine for pg_num < S pools, revisit with async store); - PREMERGE blocks client I/O of the two PGs until clean (short); - the child's `stats_invalid` stays until the next scrub; - no `pg_num_history` persisted (maps are retained instead).
Tests: pgwire `pgmath` (T1-T4); peering `tests/split_merge.rs` (1->2->4->8 and 8->64 under writes, 16->8 merge sequence with ReadyToMerge, merge target state, stale OSD backfilled, far-behind OSD, not-ready when undersized, stale op epoch, chaos with kill/restart at random moments, 30 seeds); storeadapt `tests/split_merge.rs` (differential vs MemStore, crash at every IO boundary x 3 policies: same shard, cross shard, 1->8 mixed, 12->32, merge same/cross shard, multi-source, orphan gc); messages unit (ReadyToMerge bytes); live L1-L6 (below).
Alternatives: one atomic txn per split (size bound, long WAL chains); children always on the parent's shard (pool-level sharding, kills parallelism); placeholder PGs for missing merge participants (more state, backfill covers it); persisted `pg_num_history` (maps already kept).
Live results: see end of file.
Review fixes (2026-10-10): EC PGs are forgotten in memory only by `step_epoch` (no store op, no message); a merge source whose target is absent gets an empty placeholder target (`Pg::merge_placeholder`, incomplete -> backfilled), a target already past the merge epoch absorbs late and re-peers, nothing is ever RemovePg'd for lack of a target; `merge_status` Ready needs Active/Clean with `last_interval_clean == same_interval_since`; the merge registry is keyed by the actual source (`merge_pairs`); `advance_pg` advances only the late PG and the PGs it creates (`advance_set`); `copy_object` keeps zero blocks as holes + final truncate; `split_settle` replaced by `SplitGate` (U-SM4 in split-merge.md); WAIT after activation only if a prior-interval member is DOWN in the map (`prior.down`), so splits / pg_num_pending changes with the same up acting set no longer stall for the read lease; lost ops: the OSD glue dropped engines (reset, merge source, demotion) without sending their UNBLOCKs, so a client blocked by a PREMERGE/DOWN backoff never resent (`pg_engine_sync` now sends them, `Engine::teardown`).
Live results (2026-10-09/10, docker lab, 4-shard file devices, own CRUSH roots, cleaned up to HEALTH_OK):
- (a) 3 croit-flashstore-osd, size 3, autoscale on: mgr split 8->32 on its own; explicit 32->64 and 64->16 (48 merges): 200 objects (data+xattr) md5 identical, all `active+clean`, HEALTH_OK, deep-scrub clean; restart of all OSDs afterwards fine. L5: `rados bench` through splits/merges completes without errors (max latency 15-30 s: per-PG read-lease WAIT after each interval, see below).
- (b) mixed 2 croit-flashstore-osd + 2 classic (21.1.1), 8->32->64->128->16 (+15 after an aborted merge): md5 identical, deep-scrub clean, L3 (croit-flashstore-osd primaries commit merges), L4 (OSD down during PREMERGE -> `merge not ready` -> mon reset pg_num_pending) verified.
- Found live: classic OSDs ABORT (`PeeringState::Crashed`, "bad state machine event") when a peering message for a child PG reaches them between the child's creation and its first ActMap (events parked for the split slot are replayed before the child's NullEvt). croit-flashstore-osd splits in microseconds and talks first. First fix was a fixed 2 s hold (`split_settle`, removed: timing based); now `PgSet::split_gate` (state based, see U-SM4 in split-merge.md): peers not known to run croit-flashstore-osd (`osd metadata` -> `flashstore_version`) get child messages only after they spoke about the child or a later map exists (re-stamped). Also fixed live: `MOSDPGCreate2` stamped with an epoch we do not have is kept (was dropped, creates lagged one epoch behind forever on a busy mon); dropped client ops (stale epoch, gate full, torn-down engine) trigger a map share to their clients (clients otherwise sat 10 s on their own tick; merge sources, splits). Live (2026-10-10, 3 croit-flashstore-osd + 2/3 classic mixed): 8->32->64->128->16, repeated, continuous 16-way put workload: 0 failed ops of ~70k per run, md5 identical, no classic crash after the gate fix (3 aborts before it).
- Found live: ops parked in the engine across a split would have run on the parent for objects now owned by a child; `Env::op_stale` drops re-queued ops older than `last_epoch_split` (clients with RESEND_ON_SPLIT resend).
- Known/open: (1) every new interval costs up to the read-lease WAIT (16 s) of I/O on that PG: a split stalls the whole pool for that long, a merge two PGs twice; (2) in 3 of ~12 bench runs a few client ops never completed after the pool settled (observed before and after `op_stale`; none in the last runs, no drop counter fired on croit-flashstore-osd; cause not found, `tell osd.N dump_pgs` now shows `dropped_ops` and the engine `stale` counter); (3) small file devices fill up with bench data (NoSpace -> OSD exits as designed).

Live verification round 3 (2026-10-10, Mac lab, 3 croit-flashstore-osd + 3 classic mixed + all-croit-flashstore-osd pool, 16-way put/get md5 workload, 200 objects): pg_num 8->32->64->128->16 x2 on both pools, classic restart during split, croit-flashstore-osd restart during merge, late merge (croit-flashstore-osd down + out over 64->16, back later: replays merges incl. placeholders, clean), 0 failed ops of ~800k, md5 identical, deep-scrub clean, no classic abort. Found + fixed: (1) `osd metadata` peer query sent `id` as a JSON string, the mon answers EINVAL ("bad or missing field 'id'"): NO peer was ever recognised as croit-flashstore-osd, every peer stayed classic-gated (split gate waits) and every map re-asked everyone (~1000 queries/min); now an integer (`pgs::peer_meta_cmd`, unit test). Split phase 120-150 s -> 25-33 s, per-phase op max 20-33 s -> 3-6 s. (2) kdrv (dev driver) wrote with a blocking 500 ms write: two OSDs sending multi-MB batches to each other deadlocked until reset, PGs went laggy, ops hung; now nonblocking with per-connection pending buffer. (3) `pg_num` stepping is done by the mgr: the option is `mgr/target_max_misplaced_ratio`, not mon; stepping also stalls while any PG of ANY pool is degraded (lab tip: size 2 on a 3-host pool while one host is out). Merge 128->16 takes 8-12 min in the lab (one step per clean round), not an croit-flashstore-osd stall.
