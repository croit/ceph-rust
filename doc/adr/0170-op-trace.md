# 0170 Always-available sampled per-op stage tracing (replaces `lat-trace`)
Status: accepted
Date: 2026-10-17

Context: stage latencies (rx, decode, PG queue, exec, store, repops, reply, tx) were only available in lab builds (`lat-trace`: global mutex vector, report at exit, perturbs what it measures, never in prod). Operators and perf work need the same breakdown on the production binary, at any time, without a restart and without a measurable cost when off. Never-worse-than-BlueStore needs per-stage numbers on the real build.

Decision:
- Runtime switch `flashstore_trace_sample` (0 = off, default; N = 1 of N client ops) and `flashstore_trace_ring` (events per core, default 16384, rounded up to a power of 2). `config set` reaches every core (XMsg::Conf, same path as `osd_op_history_size`); each core caches `n` in its `Tracer`.
- Sampling rule: `splitmix(reqid) % N == 0` over the osd_reqid (client name, inc, tid). Deterministic and stateless: the conn core, the PG core, and every replica reach the same verdict from data they already have (MOSDOp, MOSDRepOp.reqid, log entries). A per-core counter was rejected: a replica cannot reproduce it, and carrying a context through ops/XMsg/wire would cost bytes on every op. No wire change; classic OSDs are untouched (their ops are simply not traced; they never see anything).
- Trace id = the 64-bit reqid hash (`trace_id`, hex). Primary and replica records of one op share it; join across OSDs by `trace_id`. A replica OSD reports `role:"replica"` records in its own dump.
- Storage: per core a fixed `Vec<Ev>` ring of 32-byte events (key, tsc, aux, aux2, x, stage, core), overwrite oldest, written only by the owning core (single writer, no atomics, no lock). Readers never touch it: `dump_op_traces`/`trace_summary`/`trace_reset` are scattered commands (like `dump_ops_in_flight`); each core copies its own ring between loop iterations and the control core joins events by `trace_id`. This replaces "lock-free concurrent reader": nothing is shared.
- Cross-core stamps need no carried context: conn core writes `rx`,`routed` events by recomputing the key; the PG core keeps a small fixed table (64 live sampled ops, overwrite oldest, no allocation) mapping (conn,tid) / store token / repop tid -> key, only touched when it is non-empty. The link core learns that a reply/ack frame of a sampled op left via `XMsg::TraceTx{key,stage}` queued behind the frame (rings are FIFO per core pair); its next tx step stamps `tx`.
- Off cost: ingress = one branch on `n != 0`; every later site = one branch on `live_n != 0` (a usize in the PG core struct). rx/tx hooks in the core loops = one branch. No allocation, atomics, or locks. On cost: a hash per op on the sampled-in path decision, 32 B stores per stamp, one tsc read.
- Clock: TSC (`rdtsc`) when CPUID reports invariant TSC (x86_64), `cntvct_el0` on aarch64, else `Instant`. Calibrated once against `Instant` (10 ms, first use at start). Event times are ticks; converted to ns when dumped; one origin for all cores (invariant TSC is socket-synchronous; a skewed core shows as a negative delta, reported as 0).
- Stages (names stable, JSON): primary `rx, routed, pg_in, pg_run (last run of the op; exec splits into pg_wait = queue wait and pg_work), submit, durable, rep_send(peer), rep_ack(peer), reply, tx`; replica `r_rx, r_in, r_pg, r_submit, r_durable, r_ack_out, r_tx`. `rx` = last NIC rx poll before decode (knet: top of the loop step), `tx` = frames handed to the NIC / `io_uring_submit` of that step. `rep_ack` is stamped when the PG core processes the RepOpReply (includes the cross-core hop). Store-internal stages (WAL, checkpoint) are not stamped yet (OQ).
- Output: `dump_op_traces [--last N] [--format plain|json|json-pretty|jsonl]` (jsonl = one trace per line, newline-terminated, truncation-safe; recommended for tools), `trace_summary [--format plain|json|json-pretty]` (p50/p99/p999/max/mean per segment per role/op type/size class), `trace_reset`. Fields in doc/ops/op-trace.md; schema integer 1, additions compatible.
- Ops with a trace also get their stamps as events in `dump_historic_ops*` (classic names: `started`, `waiting for subops from N`, `sub_op_commit_rec`, `op_commit`, `commit_sent`).
- `lat-trace` feature, `osd::lat`, its exit report, the `prof` build flavor's feature and the `NV_LAT_CMD` watcher are removed; `stage-sum.sh`/`stage-profile.sh` read `dump_op_traces --format jsonl` via the asok.

Consequences: + production-safe per-stage latency, any time, per OSD, cross-OSD joinable. + deterministic sampling = replicas traced for free. - sampling is 1/N in expectation, not exact. - a changed `N` mid-flight yields partial records (marked `complete:false`). - replica parts live in the replica OSD's dump (no cross-OSD merge in the daemon).
