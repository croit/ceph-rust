# 0063 L3 / CCD aware core placement
Status: accepted
Status note: Partly superseded by adr/0682-remove-afxdp-dpdk-networking.md (2026-11-06): AF_XDP/DPDK queue-IRQ wording is history; the rest stays valid.
Date: 2026-10-12
Context: rented AMD EPYC, 4M writes: two OSDs sharing one CCD 5.8 GB/s total, on separate CCDs 10.6 GB/s (L3 + memory-path contention). Before: cores = `mask[..N]` of the affinity mask, so OSDs without cpuset overlapped on the lowest CPUs.
Decision: `rt::topo` (impl), used by croit-flashstore-osd `args::choose_cpus` (DPDK + knet tiers).
- Mask: only CPUs of `sched_getaffinity` (cpuset/taskset/systemd CPUAffinity) are ever used. Explicit `--lcore` / `flashstore_lcores` and `flashstore_l3_placement=false` (`--l3-placement false`) = old behaviour.
- Core count unchanged: `cores` is computed as before (min(mask, store shards) or `--cores`); placement only chooses WHICH `cores` CPUs. So default ON never reduces cores. Whole mask requested -> mask as is.
- Topology from /sys/devices/system/cpu/cpuN: `cache/index*/` with level 3 `shared_cpu_list` (domain key = lowest CPU), `topology/thread_siblings_list` (physical core), `nodeM` entry (NUMA node). No L3 info (some ARM/VMs) -> one pseudo domain per node. Missing files degrade to node 0 / no SMT.
- Fill order: one thread per physical core of the domain, then SMT siblings of the same domain, then the next domain (rest of preferred node first). Packing in one L3 beats one-thread-per-core across domains.
- NUMA hint: node of the NVMe (`spdk:` address) else the first `-a` NIC PCI (`/sys/bus/pci/devices/<bdf>/numa_node`); domains on that node are preferred. knet tier has no PCI address: no NIC hint (open).
- Multi-OSD without a daemon: preferred domain rank = OSD id (`croit-flashstore-osd run` passes `--place-id`) modulo preferred domains; then `flock(LOCK_EX|NB)` on `/run/ceph/croit-flashstore-l3-<node>-<l3>.lock`, first free domain from the preferred rank wins, lock held for the process life (kernel drops it on crash). Dir not creatable (non-root, container without shared /run/ceph) or all taken -> plain id-modulo, no lock. Chosen over pure id-modulo (ids 3,17,25 collide randomly) and over a coordinating daemon (extra moving part). Skipped when the mask has one domain.
- Observability: startup log line, OSD metadata `flashstore_placement`, `tell status` field `placement` (cpus, l3 key, node, domains in mask, spilled).
Consequences: an OSD holds a whole domain even if it uses fewer cores than the domain has. Two OSDs in different containers with disjoint cpusets never collide anyway. Not measured on hardware yet (rented AMD run pending: expect 5.8 -> ~10.6 GB/s for 2 OSDs w/o operator pinning).
Open: NIC node for knet (iface -> /sys/class/net/X/device); NPS>1 / per-domain memory binding of hugepages; EAL main lcore still starts on mask[0] before the core thread pins.

## Amendment (2026-10-19): auto placement avoids the data NIC's queue-IRQ cpus (am. 1)
User principle: "when I start the OSD it must run as automatically and optimally as possible": what the OSD owns is self-tuned, host/NIC settings the operator owns are never changed (only warned, adr 0166 am. 1).
- Trigger: no explicit `--lcore` / `flashstore_lcores` (explicit stays authoritative, only `flashstore_lcores` vs IRQ overlap WARNs via hwcheck `net.<if>.irq`). `--l3-placement false` = the old plain `mask[..N]`, no avoidance (A/B arm).
- Data NICs: knet = interfaces of the resolved public + cluster address (`iface_of_ipv4`); AF_XDP/af_packet = `--vdev-iface`. Bond/VLAN/bridge resolve through `lower_*` links to the physical NICs; a PCI-bound DPDK NIC has no kernel queue IRQs (none to avoid).
- IRQ cpus = `effective_affinity_list` (else `smp_affinity_list`) of every `/proc/interrupts` line naming the NIC or its PCI address (`hwcheck::nic_info`; same parse as the `irq` check). `rt::topo::avoid_irq(mask, irq, N)`: drop those cpus from the affinity mask when >= N cpus remain, then the unchanged L3/NUMA placement runs on the rest. Fewer than N IRQ-free cpus (core count is NOT reduced, default cores = min(mask, shards) as before): mask unchanged + loud `croit-flashstore-osd: WARNING only X of Y cpus are free of NIC IRQs ...` with the fix (move IRQs / give the OSD more cpus), placement log says `sharing NIC IRQ cpus [...]`.
- NUMA: the NIC's node (`/sys/class/net/<if>/device/numa_node`) is the preferred node (was: NVMe node; NVMe node remains the fallback when the NIC reports none). Closes the "NIC node for knet" open point above.
- Several OSDs per host: unchanged mechanism (rank + L3-domain flock). All OSDs avoid the same IRQ cpus; domains stay keyed by (node, L3), so OSDs still take different domains; with one domain they overlap exactly as before.
- Snapshot at start: IRQs that irqbalance or the operator move later are not followed (restart re-places). Operators who pin IRQs themselves keep `flashstore_lcores`.
- Siblings: knet + AF_XDP covered (same `choose_cpus`); DPDK PCI NIC: no kernel IRQs; SPDK / kernel-NVMe backends not affected (placement is per NIC, the NVMe path has no NIC IRQs; their interrupts are per-queue and polled/own cores); rep/EC and crc/secure share the placement.
- Measured (zen4 lab, bnxt VF, hk IRQs on cpus 0-1, `lab/baremetal/irq-place-ab.sh`): see doc/perf/irq-placement-20261019.md.

## Amendment (2026-11-01): spread NIC queue IRQs over all NIC-local cpus; OSD cores may share them (am. 2)
Evidence (doc/perf/irq-spread-20261101.md): e9455 (EPYC 9455P, 48 cores, 6 OSDs x 6 cores, kernel tier, rep3, 2 rounds) host layout A/B: queue IRQs spread one per cpu over all 48 cpus (48 queues/port, OSD cores included) beat 12 queues on 12 housekeeping cpus: 4M append +5 % (p99 1.35 vs 1.63 s), 4K randread +5 % (p99 0.72 vs 0.76 ms), 64K randread +1.5 %; clients +12 %. Cost: softirq moves onto the OSD cores (busy 18 -> 37 %), more incast drops and TCP timeouts, still a net win. The 12 housekeeping cpus ran at 47 % busy: a few dedicated IRQ cpus cap the NIC.
Decision (supersedes the "never on an OSD core" rule of am. 1 and of the hwcheck `net.<if>.irq` check):
- Recommended host layout: one queue per NIC-local cpu, queue IRQs spread over all NIC-local cpus, OSD cores included (driver/RSS default). Concentrating the queue IRQs on a few housekeeping cpus is no longer recommended.
- hwcheck `net.<if>.irq`: warns when the queue IRQs are concentrated (fewer IRQ cpus than NIC-local cpus while the NIC has fewer queues than NIC-local cpus, or several IRQs on one cpu while a NIC-local cpu has none: with at least as many queues as NIC-local cpus it warns when the IRQs cover fewer cpus than that); fix = more queues (`ethtool -L`) + spread affinity; never warns because an IRQ lands on an OSD core. `croit-flashstore-tool host-tune` applies the spread, not the housekeeping pinning.
- OSD placement (`avoid_irq`): unchanged when the operator confines the IRQs to a cpu subset (zen4 2026-10-19: avoiding them still saves 3-10 % OSD cpu/op, p99 4k better). When the IRQs cover the whole mask (spread layout) the OSD shares them silently: no `only X of Y cpus are free of NIC IRQs` warning, the placement log keeps `sharing NIC IRQ cpus`. Partial case (fewer IRQ-free cpus than cores wanted but IRQs not on the whole mask): not avoidable without shrinking the OSD, so the OSD shares silently as well (one rule: avoid only when >= N IRQ-free cpus remain, else share); concentrated IRQs are reported by hwcheck `net.<if>.irq`, not by the OSD. `Irq::Short` became `Irq::Shared`; `startup_warnings` no longer takes the OSD cores. The IRQBALANCE_BANNED_CPULIST advice is dropped. host-tune pins queue k to NIC-local cpu k (wrapping), only IRQs not already there.
Open: the A/B changed queue count (12 -> 48) and co-location together; which of the two carries the gain is not separated (an arm with 48 queues on the non-OSD cpus would split it, impossible on the 9455P layout used). kernel-stall-20261017 (zen4 VMs, GRO-sw softirq on OSD cores filled rings) is a VM with 2 queues per VF, not the spread layout.
