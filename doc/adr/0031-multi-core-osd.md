# 0031 Multi-core OSD: one `Osd` per core, PG ownership by store shard

Status: accepted, amended (am. 11)
Date: 2026-10-10
Consolidated 2026-10-19; full pre-consolidation text: git show 60868596d:doc/adr/0031-multi-core-osd.md
History/tests/crash detail: doc/perf/adr-0031-history.md (doc not in the source snapshot).

## Context

Network (`rt` mesh, RSS) and store (S shards) scale per core (adr 0006, 0021). Goal: N cores, a PG owned by exactly one core, no locks on the hot path, wire-compatible with classic peers (one session per peer OSD).

## Decision

### Cores and placement
- One `osd::Osd` per core (`CoreSpec{id,n,net,shards}`, max 64 = `MAX_CORES`). Core 0 = control: mon/mgr sessions, boot, heartbeats, osdmap ingestion + persistence (meta store on shard 0), tell commands, aggregation. Cores 1..n = workers: links + PGs only. `--cores 1` (n == 1) is the single-core path: no messages, all messaging short-circuited. Cores mount only their own shards (`Store::mount_shards`, own device queues); tiny pools (< cores PGs, e.g. `.mgr` 1 PG) are fine while they never split.
- Default cores = CPUs in the process affinity mask (`sched_getaffinity`: cgroup cpusets, systemd, taskset), capped by the shard count. `--cores N` overrides (error if N > mask size); core `i` pinned to the i-th mask CPU (`--lcore X` = start at X). Startup logs cores and cpus. Several OSDs per host: each is pinned to its own cpuset (cgroup cpusets, systemd `CPUAffinity`, cephadm, taskset).
- Store shards S = mkfs `store_shards` (`auto` = configured cores; any 1..=256). Core c of n owns shards `s % n == c` (any n; non-dividing = unbalanced, warned). `--cores N` > S runs on S cores with a warning. `mount_dev_core` splits the cache budget per device shard. Restart with another core count needs no reformat.
- A PG lives on the shard its collection was created in. New PG: shard = `(pool+seed) % S`, unless core 0 placed it when it arrived with a map (adr 0639: least loaded core, per pool then in total; placement-only moves of the gate's round). Split children inherit the parent's shard (zero-copy split, imbalance accepted; OQ 5). PG core = `shard % cores`. The placement table of off-hash PGs is the collection locations (`Store::scan_placement` at mount; `PgSet::place`; core 0 collects every core's PG list at boot; `XMsg::Placement` for moves and for the children a boot replays). `PgSet` only loads/creates/routes PGs it owns (`Config.owner`).
- Split children (am. 7): every core records them from the map itself, before any PG advances (`PgSet::place_split_children`), and routes a seed beyond its own map to its ancestor's shard (`PgSet::pg_shard`, also the input lane). The core and lane of a child never change, so a sender's messages and ops for it take one path. Where a merge source's copy is stored: `PgSet::stored_shard` (no ancestor routing).
- Connections live on the core their flow lands on (RSS, `net` cores `0..net`) and never move; link ids carry the core in bits 48..56 so `send_raw/send_link/close_link` route themselves. PG-only cores (no NIC queue, `--queues Q < --cores N`) are allowed (needed on af_packet vdev).

### Routing (`xcore::XMsg` over `rt::mesh` SPSC rings; `rt::XPort` per-destination backlog, never blocks)
- Client MOSDOp: decoded on the connection core, forwarded as `Op{conn, tid, Arc<ConnInfo>, Box<MOSDOp>}` to the PG core (ConnInfo built once per session). Replies/backoffs/notifies are encoded on the PG core and return as finished `Wire` frames. Map sharing to a lagging client happens on the connection core. `ConnClosed` goes only to cores the link forwarded to.
- Peer OSD traffic: validated + decoded on the receiving core, `Pg{from, tid, Body}` to the owner(s) (`peering::body_spgs`). Outbound `Action::Send` is encoded on the PG core with the peer's negotiated features (`PeerFeat`; used only for the `up_from` incarnation they were negotiated with, else all-but-`TENTACLE_BIT`) and sent as `PeerWire` to the core holding the single link to that peer (`peer_core(osd) = osd % net`; msgr2 sessions are keyed by address).
- Heartbeat PINGs are answered where they arrive; replies to our pings arrive on core 0's dialed links. tell/mon-command on a worker link: `Ctl` to core 0, reply back as `Msg`.
- Owned `Vec`s move through the ring (no copy, no refcount); rx mbufs are not shared across cores.
- Bounds: `XPort` backlog <= `MAX_BACKLOG` (16 Ki) over all destinations, beyond it the OSD outbox is not drained; with `XOUT_MAX` (8 Ki) messages queued in the OSD a connection core answers new client ops EAGAIN (objecter resends).
- Message order: FIFO per lane and core pair; an ordered message (the default route) is a barrier on its pair. Messages of a moving PG keep their per-sender order by the move protocol (am. 8, PG move on merge).

### Control plane
- Core 0 -> workers: `Map(Arc<MapUpdate>)` (shared immutable `Arc<OsdMap>` per epoch, last 64 kept), `State`, `Keys`, `Conf`, `Create` (MOSDPGCreate2 broadcast), `NvPeers`, `MonSession`, `Shutdown`. Worker boot: lists own PGs, asks core 0 for maps from its oldest PG epoch (`MapsReq`/`Boot`).
- Workers -> core 0: `Mon` (any mon-bound message), `UpThru`, `ReqMap`, `Fatal` (local store failure stops the whole OSD), `Stats` every second. Core 0 aggregates MPGStats, beacon, osd_stat, statfs/fullness, map trim bound. First-boot crush weight waits for all workers.
- Per-core, not aggregated: PG counters, `tell dump_pgs|query` (core 0's PGs only), op engines/backoffs. Reservations and slots (`osd_max_backfills` local + remote, `osd_max_scrubs`, `osd_max_trimming_pgs`) are OSD-wide budgets kept by core 0 and reached by message (am. 9), never divided over cores.
- Driver: `rt::XPort`, `Core::run_osd_x` (net cores), `rt::run_pg_core` (PG-only); `croit-flashstore-osd --cores N [--queues Q]`, `Port::start_mq` + `Config::steer` when Q > 1; per-core device queues (`osd::nvmestore::{core_queues, mount_dev_core}`); core 0 stops everything when it exits.

### PG move on merge (pg_num / pg_num_pending lowered)
A merge source must sit on its target's core. Split-derived merges are co-located by construction.
- Rounds are decided once by core 0: when a map reaches the head of core 0's queue it computes the moves and sends `Gate{epoch, moves}` (empty = no round) after `Map`; workers hold the map until the Gate arrived. Sources report `MigDone{epoch, deferred}` to core 0 only; core 0 sends `Release{epoch, deferred}`; on Release every core switches placements of non-deferred moves, then applies the held map.
- Map vs PG set (am. 6): a worker's core map advances on `Map`, its PG set only when the held map is applied (after `Gate`, after a round's `Release`). A client op waits (`pg.parked`, FIFO) while its epoch is newer than the core's PG set epoch, not only newer than the core map (spec client-ops 5.1 item 2, classic waiting_for_map): it never runs against an older interval nor overtakes a parked op of its client. A retried waiting op whose PG moved to another core under that map follows it (`reroute_op`).
- Move unit = PG (`PgT`); the source exports every instance (SpgT) it holds, replicated and EC alike. Stream via `storeadapt::migrate` (objects, xattrs, omap, data runs without zero blocks, pgmeta last, 1 MiB batches, credit window 3); the destination imports one system txn per batch, `adopt`s only when ALL instances arrived (`MigReserve.n`), then acks; the source then deletes its collection. `PgSet::set_ec_enables` loads nothing before boot load and never a detached instance.
- Completion marker: last op of the last batch sets pgmeta `_mig_done`; `meta::load` treats a collection with `_mig_in` but no `_mig_done` as absent (garbage, `gc_orphans`). A crash after copy, before source delete, leaves two copies: the higher `_mig_in` generation wins. Keys sorting behind `_info` (`_loghead`, `dup_*`, `missing/*`) may still be missing before the marker.
- Headroom before detach: source sends `MigReserve{pgid, shard, bytes, n, seq}`; the destination `Store::mig_hold` raises user and system floors (user = data_reserve + hold; sys = data_reserve/3 + hold) and answers `MigGrant{ok}`. Size = `storeadapt::mig_bytes` (exact, at reservation time: collection data + 2 blocks per object (+2 objects) + 2 x omap bytes from the store's own omap counters). Each import batch releases its share; `mig_release_all` at round end.
- No room = deferred, never a stop: the PG keeps serving on its source core. `MigDeferred{list}` mirrors `Deferred{pgid,to,shard,bytes,stranded}` on every core; elastic wants derive from it (non-stranded, `to == me`). Visible: health `FLASHSTORE_PG_MOVE_DEFERRED` (os_alerts), perf `flashstore_mig.moves_deferred` (counter) / `flashstore_mig.pgs_deferred` (gauge). Retry: core 0 on `Stats`, when no round runs, no maps held, boot done, destination room (`CoreStats.mig_rooms`) >= bytes -> `MigRetry{epoch, moves}`; deferrals whose merge was cancelled or move became local are dropped. Elastic pool (feature `elastic`): destination shard borrows chunks until room >= want.
- Import NoSpace = undo + defer: destination deletes what it imported, restores placement, sends `MigAbort{pgid, imported}`; the source drops its jobs, adopts its instances back, defers asking `bytes + imported`. `seq` in `MigReserve/MigData` drops stray data of an aborted attempt.
- Strand = incomplete target (Ceph semantics): if the held map completes the merge while the move is deferred, the target merges without the source (`merge_from`: absent source -> `last_backfill = MIN`), so peers backfill it; classic peers see a backfill target. A stranded copy is never moved or absorbed; it stays unloaded (`PgSet::keep_unloaded`) and is deleted when obsolete (target's core sees every local instance of the covering PG at `last_backfill = MAX` -> `MigObsolete{pgid}` -> core 0 -> `MigDeferred` broadcast -> holder deletes). Pool deletion deletes it. Size 1: no strand possible. `merge_sources` skips sources on a shard not mounted locally.
- Boot never moves data: copies of one PG on two cores are resolved per PG (most instances, newest epoch, newest generation, lowest core; losers deleted); a merge source on the wrong core is deferred to a runtime retry, or stranded if the merge completed.
- Messages of a moving PG (am. 8): from the start of a round to its Release every core holds what it routes itself for the round's PGs (client ops, backoff acks, copy reads, pre-write pieces, single-PG peer messages: `Osd::pg_item`, `MigState::hold_q`) and sends each source core of the round `MigHold{round}` (ordered: behind everything it routed by its old table). Held messages keep their input reservation: the input windows bound the hold, a full window makes the links wait. A source starts its moves once every other core's barrier is in: nothing routed by an old table is on its way to it any more. Rounds run in the same order on every core (Gate per held map, `MigRetry` after the held maps), so round ids match.
- Detach = merge-source quiesce (`PgSet::detach`): queued writes stay, in-flight sub-writes are aborted (`SubWritesAborted` returns their repop credits at once, not when the held map drops them), reservations go back. What waits for the PG on the source (PG set per-PG and map queues, `PgSet::take_waiting`; parked client ops) and whatever still reaches it go to its hand-off queue. After the last instance's ack the source switches its own placement, sends the queue to the destination and closes it with `MigHandoff{pgid}` (ordered). The destination queues what arrives for the PG (`Arrival`: hand-off first, then the rest) and runs it once the hand-off is closed and its own Release switched it. At Release every core switches, sends what it held by the new table, then applies the held map. A deferred move keeps the PG on the source (what was held or queued for it goes there); an undone import (`MigAbort`) runs the hand-off queue on the source again.
- Result: no message of a moving PG is handled by a core that no longer hosts it, none is dropped, none overtakes an earlier one of its sender. `PgSet::create_from` never creates an instance whose copy is stored unloaded on this core (moved away, stranded): counted drop `create info for a pg stored unloaded here`.

## Rationale

- PG ownership by shard keeps all PG work lock-free; cross-core cost = one ring push per message.
- Persisted placement + migration instead of refusing cross-core pg_num changes: autoscaler merges are routine, refusal = outage. Co-location-by-placement is impossible (any merge-closed placement is constant); backfill from peers loses data at size 1.
- Default cores = affinity mask: every core thread busy-polls at 100%, so each OSD uses exactly the cpuset it was given.
- Strand-without-absorb: a late absorb of the old copy would overwrite what the merged PG received since.
- Move hold at the routers (am. 8): no relay, no timer, no per-sender state on the destination beyond one hand-off queue; the barrier makes the source's queue complete before it hands it over. The held messages of a normal round meet the held map's new interval of the merge PGs anyway (clients resend), a retry round's PGs are premerge (backoff).

## Consequences

- + PG work (peering, op engine, store commit, replication encode) scales over cores; + restart with another core count needs no reformat.
- - One client connection is bounded by its connection core (decode + msgr2 crc); peer traffic to one OSD flows through one core.
- - Stats lag <= 1 s; `flush_pg_stats` is not synchronous across cores.
- - Split children inherit the parent's shard: imbalance grows with repeated splits (OQ 5).
- - A deferred move near-full leaves the merged PG backfilling on peers until room exists.
- - Messages of a moving PG wait at their routing core for the whole round (am. 8); a source starts copying only once every core entered the round.

## Alternatives

- Refuse cross-core pg_num changes (FATAL + mark-me-down): rejected, outage on autoscaler.
- Hash shard % cores with power-of-two cores only: replaced by persisted placement, any core count.
- Boot-time moves: removed, resolved by dedupe + runtime retry.
- Late absorb of stranded copies: removed (data overwrite risk).
- Move fence relayed through the source (each router's fence forwarded behind the source's parked messages, destination holding direct sends until it arrived): rejected for am. 8, per-router state on two cores for the same order. Moves only at an interval change: retry rounds have none.

## Open questions

- Across a move (am. 8): peer messages for several PGs (MOSDPGRemove, scrub2) and creates parked for an old-map replay (`parked_old`) stay on the source; a client link closed during a round before its core's Release is not told to the destination; a retry-round move reloads the PG without an interval change. doc/90-open-questions.md (Placement lag).
- EAGAIN storm under a long stall (no delay on objecter resend). OQ 5.
- Client IO gap during a PG merge (~3 s per merge step, equal on classic BlueStore; lab/baremetal/pg-merge-gap.sh, 2026-10-19): mon/mgr merge pacing + re-peering, not the store (`ckpt_max_ns` <= 11.5 ms).

## Reservations and slots (OSD-wide) (am. 9)

Problem: `osd_max_backfills` (primary-side local reserver, replica-side remote reserver) and `osd_max_trimming_pgs` were divided over the PG cores (rounded up, >= 1 per core): 8 cores and `osd_max_backfills` 1 ran up to 8 backfills per direction, 8 trimming PGs at the default 2 -> 16, i.e. 8x the recovery and trim load the operator configured, and mixed acting sets with classic OSDs saw it (classic bounds the whole OSD, spec/replication.md 7.3).
Decision: every concurrency budget that classic keeps per OSD is kept by ONE core (core 0, the only core when single) in `peering::slots::Slots` and reached by message, the mechanism of adr 0083 am. 4 generalized: pools `ScrubLocal`, `ScrubReplica`, `Local`, `Remote` (backfill and recovery), `Trim`; `XMsg::Slot` / `XMsg::SlotReply` on one ordered lane; per-core request numbering (stale replies ignored); the owner remembers core and number per PG (a release from a core the PG left is ignored); a release of a slot never asked for is dropped; grants for vanished PGs and for PGs that no longer want them are released at once; every slot and queue place of a PG is released when the PG is removed or moved as a merge source; a changed limit answers the queued requests it lets through. Backfill / recovery pools queue by priority (highest first, FIFO within, preemption: am. 10); scrub and trim queue FIFO. Limits: backfill and recovery share ONE pool per side of `osd_max_backfills` slots (am. 10), scrub `osd_max_scrubs` per side, trim `osd_max_trimming_pgs`; all runtime-changeable.
Rationale: a reservation or slot changes hands at the rate of PG recovery, backfill, scrub or trim starts (seconds apart at best), so one cross-core round trip costs nothing and no lock, atomic or shared structure touches a hot path (adr 0006, 0031). KISS: one owner, one mechanism, no per-resource split rules.
Consequences: `osd_max_backfills` 1 = one backfill per OSD per direction; the 1-per-core minimum is gone for all budgets; a grant takes one core round trip more. `dump_recovery_reservations` / `dump_scrub_reservations` list the owner's state, the control core sums the cores (OSD-wide). Mixed case 09 samples the backfill reservations of 4-core croit-flashstore-osds and fails above `osd_max_backfills`.
Siblings: knet / AF_XDP / SPDK / kernel NVMe, replicated / EC, crc / secure not involved (scheduling only; EC PG instances use the same pools). `osd_recovery_max_active`: am. 10.
Tests: peering `slots::owner_tests` (budget N over 8 cores never exceeded for backfill local / remote, trim, scrub; priority order; requeue priority; former-core release; raised limit answers the queue), `pgset::slot_tests::reservation_and_trim_slots_of_vanished_pgs_are_freed`, existing `scenarios` / `split_merge` local-slot-leak asserts; lab: mixed case 09 (`nv_multicore`, `bf_sampler_*` in lib.sh) on a multi-core knet VM.

## Recovery reservations and op budget (am. 10)

Problem: croit-flashstore-osd kept a separate recovery pool of 4x `osd_max_backfills` without preemption (workaround for the 2026-10-11 RGW stall: a 130k-object backfill held the only FIFO slot while degraded control PGs waited, commit 17bdbbde6d), and `osd_recovery_max_active` was a per-PG constant 3 (up to 12 ops per OSD at the default, nothing wired to the option). Classic: one pool per side shared by backfill and recovery with priority preemption, and an OSD-wide in-flight budget `osd_recovery_max_active` (`_ssd` 10 when 0; mclock gates the options).
Decision: (1) root cause of the stall fixed as in classic: the local and remote reserver are ONE pool of `osd_max_backfills` slots each, a strictly higher priority request preempts the lowest holder, `osd_min_recovery_priority` honoured; replica REVOKE on preempt, primary defers (a local preempt during WaitRemote defers when the remote exchange ends, classic runs on slotless). The 4x pool is gone. (2) `osd_recovery_max_active` (else `_ssd`, 10) is an OSD-wide in-flight op budget: core 0 owns the limit (`peering::recops::OpsOwner`), each core holds a quota (`OpsLease`) split into per-PG leases; a PG with no competitor refills its lease with no message, with competitors leases pin to the in-flight count and freed units go round-robin; idle quota returns to the owner. (3) mclock default gates `osd_max_backfills` / `osd_recovery_max_active*` like classic (`osd_mclock_override_recovery_settings`): values from mon/runtime are removed with `config rm` and a cluster WARN; effective 1 / 10.
Rationale: replication.md 7.3, 7.5. Per-core quotas instead of one round trip per op keep the recovery op rate (thousands/s) free of cross-core latency and locks; messages only on contention, quota moves at rebalance rate.
Consequences: at most `recovery_max_active` recovery ops per OSD at every instant with any core count; no starvation of small degraded PGs behind a big backfill. Open: `osd_recovery_max_single_start` is not wired (even-share leases instead); limits clamp to >= 1.
Siblings: knet / AF_XDP / SPDK / kernel NVMe, replicated / EC, crc / secure not involved (scheduling only; EC counts `ep.recov.ops + deletes`).
Tests: `peering::recops` (8-core simulation: limit never exceeded, liveness, no leak, runtime change), `tests/recovery_budget.rs`, `slots` reserver and owner tests (preemption, shared pool, min priority), `osd::config` mclock gating, mixed case 30.
