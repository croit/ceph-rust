# 0066 a replica never refuses a PG transaction: data in waves, refusal = fail-stop
Status: accepted
Date: 2026-10-12
Context: OQ 23 (found by the OQ 16 live copy run, adr 0057 am. 2). A replica whose store refused a repop txn (`Queued::Rejected`, e.g. `TooLarge`) logged "malformed transaction dropped", closed the sender link and never acked: the primary's repop (and, completing in tid order, every later write of the PG) waited until the next interval (SLOW_OPS, `ceph pg repeer`). Worse, the PG had already appended the entry in memory (log, `last_update`) before the store said no, so later persists of that PG recorded a `last_update` covering an entry whose data and log record were never written (divergence a later peering trusts). Main cause = the data-extent rule of the store (`extents + 2*max_inflight_units + 2 <= device queue depth`): the primary judges its own allocator, a replica with more fragmented free space needs more extents for the same bytes; with the production SPDK qpair (depth 128) the rule capped ANY txn at 94 extents (<= 23.5 MiB even on an empty device, 4 MiB on a 44 KiB-fragmented one), so a classic primary's 90 MiB write (osd_max_write_size) to an croit-flashstore-osd replica could never apply, an 8 MiB recovery push not on a fragmented one. Same path for EC sub-writes, recovery pushes, deferred txns (adr 0064 am. 1). Classic: a replica cannot refuse; BlueStore never says no for size, a failed apply aborts the OSD (fail-stop).
Decision:
1. Store (`shard.rs`): no data-extent limit. Data writes the device queue cannot take now wait in `Shard::data_backlog` (FIFO) and go out in waves from `poll` as completions free slots, always leaving `data_floor` = min(2*max_inflight_units + 2, depth/2) slots for WAL units/pads/root. They count in their unit's `pending_data` from the start: the unit (and every later one) is acked only once all landed; replay already validates the data crcs of every record (a unit whose data did not land ends the log, nothing after it was acked), the checkpoint root needs `durable_lsn >= L`, reads of not yet durable objects wait (`wlsn_pending`). Admission: a txn with data is `Busy` while the backlog is not empty (one oversized txn at a time); a txn that fits the queue keeps the old rule (room for all its extents + floor). `check_fits` / `check_txn` drop the extent rule, so the primary's pre-flight and the replica's apply judge only the same two limits: WAL record <= ring/2 (identical record for identical txn) and tree pages <= budget (the primary checks half the budget for margin). Stat `backlog_writes`.
2. OSD (`pgs.rs pg_exec`, `storeadapt apply_deferred`): a PG txn the store refuses (anything still `Rejected`: the two limits above, malformed input) -> `store_failed` (log FATAL, mark down, exit 1), never drop. Nothing was applied (atomic store txn), the diverged in-memory state dies with the process; the mark-down is the interval change: the primary aborts the repop and re-runs the op without us (croit-flashstore-osd engine re-queues, classic objecter resends), restart + peering + recovery bring the OSD back from its durable state. A repeat (txn that can never apply here) is a visible flapping OSD (classic `osd_max_markdown_count` stops it), never a silent wedge. The primary's own txns fail-stop too (am. 4).
Consequences: + no wedge for any size a primary may send (classic 90 MiB writes, 8 MiB pushes, staged copies) and no extent-driven EMSGSIZE for clients on SPDK qpairs; + classic-consistent (replica cannot refuse); + small change: one FIFO, one drain, one branch. - a txn bigger than the queue holds later data txns of its shard until its data is out (one at a time, bounded by the txn size); - a poison txn (one a primary accepted that this replica can never apply, e.g. omap page budget of a reshaped tree) crash-loops the replica instead of wedging the PG: visible, and the rest of the PG keeps working without it. Open: undecodable repops (`repop: bad log entries` / `repop: bad transaction`, both `peering/src/pg.rs`, `version not increasing`) are still counted and dropped unacked in `peering::on_repop` (protocol bug class, no store involved): 90-open-questions 23.
Alternatives: replica answers an error result (classic primaries do not handle a failing MOSDRepOpReply: rejected, could confuse classic); primary-side cap matching the replica (cannot know a replica's fragmentation; classic primaries would still send 90 MiB); split one txn over several store txns (not atomic); fail-stop only, keep the extent rule (every classic write > 23.5 MiB to an SPDK replica would crash-loop it).
Tests: store/tests/wal.rs `txn_with_more_extents_than_queue_depth_goes_out_in_waves` (3x queue depth extents, Busy behind it, remount), `crash_while_data_waits_in_the_backlog_loses_only_the_unacked_txn`; store/tests/obj.rs `a_write_with_more_extents_than_the_device_queue_is_applied_not_refused` (16 MiB, queue 48, check_txn Ok, remount + fsck); osd xcore_tests `a_replica_refusing_a_repop_fail_stops_and_the_primary_completes_the_write` (cfg(test) knob `PgHost::refuse_next`).
Live (2026-10-12, lab-f mixed, build 18fc0ee knet): case 12-copy 54/54 (staged copies classic<->nvme, 16 x 128 MiB into a 1-PG pool, 500 k omap keys, backoff storm, classic OSD kill; RSS peak 357 MB, no FATAL/refusal in any croit-flashstore-osd log), case 11-purge-exit 19/19.
Amendment am. 3 (2026-10-27, shallow queues): checkpoint page writes and tree page reads leave the same `data_floor` (min(2*max_inflight_units + 2, depth/2)) as data writes, not the raw 2*max_inflight_units + 2: on a queue of depth <= 34 (`nvme::set_queue_depth` allows 2) the checkpoint never issued a write and page misses never issued a read, the ring never released and every txn parked until the parked-txn timeout. Test: store/tests/olsm.rs `shallow_queue_still_checkpoints` (depth 8/16/32).
Amendment am. 4 (2026-10-31, hardening review R1/R2/P9): one fail-stop for every input a PG can never apply. (1) Primary's own txn `Rejected` (ops.rs `run_actions`): fail-stop, not `fail_closed`. The PG had appended the entry in memory (log, `last_update`, head) with a pending token that never completes: the next interval's barrier never released (every later send of the PG blocked cluster-wide) and its info flush persisted a head over a record never written. Its staged repops are withdrawn (no replica sees the entry), nothing later in the same engine call reaches the store, `fail_closed` is removed. (2) Peering `Action::Fatal { spg, why }` (driver: `fail_stop`, log `FATAL: pg <spg>: <why>`, mark down, exit 1): emitted by the replica for an undecodable or protocol-violating message from its primary after the PG may have diverged: repop / ULM / EC sub-write bad entries or txn or version not increasing (a duplicate stays a silent discard), EC sub-write naming another shard, push data/data_included mismatch, activation `merge_log` without overlap, divergent rewind below the tail, log head != last_update after merge, and an activation info from the primary while this stray is behind (classic asserts in `Stray::react(MInfoRec)`; before, the primary waited in activating until the next interval). Stale input (wrong state / sender, older interval) stays a discard. Tests: osd xcore_tests `a_primary_refusing_its_own_txn_fail_stops_without_sending_the_repop` (cfg(test) knob `PgEnv::refuse_own` = `PgHost::refuse_next`); peering/tests/hardening.rs `replica_fail_stops_on_undecodable_repop`, `stray_behind_on_activation_info_fail_stops` (sim kills the OSD on `Action::Fatal`). Closes the open point of the Consequences (OQ 23).
Amendment am. 5 (2026-11-03, device window, adr 0643-device-admission-fifo): the data backlog also holds writes waiting for the device admission window. Admission: a txn with data is `Busy` only while the backlog waits for the shard's own queue room (`Stop::Queue`); data waiting for the window does not refuse the txn. Stat `adm_waits` counts window waits, `backlog_writes` queue waits.
