# 0055 Observability completion: histograms, kernel health probe, ifaces, scrub findings, OSD-level scrub, waiting ops
Status: accepted
Date: 2026-10-11
Context: doc/70-rollout-readiness.md observability rows left after adr 0035 (+0034 for devicehealth). Extends them; no earlier decision changes.
Decision:
- `perf histogram dump|schema [logger] [counter]`: four 2-D histograms of logger `osd` as classic (`op_r_latency_out_bytes_histogram`, `op_w_latency_in_bytes_histogram`, `op_rw_latency_in_bytes_histogram`, `op_rw_latency_out_bytes_histogram`). Axes: `Latency (usec)` log2 min 0 quant 100000 ns, `Request size (bytes)` log2 min 0 quant 512, 32 buckets each (bucket 0 below min = never hit, bucket 1 = `[0,q)`, bucket i>=2 = `[q*2^(i-2), q*2^(i-1))`, last open-ended). Dump = `{"osd":{name:{"axes":[{name,min,quant_size,buckets,scale_type,ranges[{min,max}]}x2],"values":[[u64;32];32]}}}`. Counted on the owning core with the other `OpPerf` fields (one `bucket()` = a division + `ilog2`, plain add; the `OpPerf` snapshot shipped per second grows by 4 x 8 KiB, merged/`perf reset` like the counters). NOT in MMgrReport (HISTOGRAM type is filtered, as before). No process-latency histograms (classic has none we need).
- Kernel health probe: `file:/dev/nvmeXnY` (lab/dev tier) gets identity + SMART through `NVME_IOCTL_ADMIN_CMD` (Identify Controller, Get Log Page 0x02; `nvme::kprobe`, Linux only, background thread) into the same `nvme::health` cell as SPDK; `smart [devid]` / `list_devices` / `device_ids` then work on kernel-owned NVMe. Regular files / virtio: no identity, silent. Device name = kernel node name.
- Metadata: `front_iface`/`back_iface` = kernel interface carrying the public/cluster IP (knet tier, `getifaddrs`), `--vdev-iface` name (af_packet/af_xdp), or `dpdk:<pci>` of the `--eal-arg -a <pci>` NIC (NVMe address excluded); via `OsdConfig.sys_metadata` (driver-provided keys win over the empty default). The `bluestore_bdev_access_mode/support_discard` and `bluestore_dedicated_db/wal` keys were dropped again (no consumer); only `bluestore_bdev_dev_node` is set (adr 0034).
- `rados list-inconsistent-obj|snapset`: pg op SCRUBLS (0x1507) on the primary: arg `scrub_ls_arg_t` (interval, get_snapsets, start_after name/nspace/snap, max_return), reply `scrub_ls_result_t{interval, vals}` of `inconsistent_obj_wrapper` (struct_v 2) / `inconsistent_snapset_wrapper` (struct_v 2) with the rados `err_t`/`obj_err_t`/`inconsistent_snapset_t` bit values (`peering::scrubls`, local scrub bits mapped). Source = the findings of the last finished scrub of the PG instance (`Pg::sp.found`, memory only; classic persists them in a scrub store: a restart answers ENOENT = "no scrub information" until the next scrub). EAGAIN when `interval` != `same_interval_since` (client restarts the listing). Pagination by position of `start_after` in hobject order (unknown cursor = empty page). Per-shard info: size, data/omap digests, `selected_oi` (auth), `primary`, all shards that returned the object; attrs not kept (rados prints no object_info/snapset detail); snapset `ss_bl` empty. Clone findings (missing clone, extra clone, headless, size mismatch) fold into the head's snapset record, not into the object list.
- `pg repair` path unchanged (mon -> MOSDScrub2 repair=true, peering tests `replica_corruption_is_found_and_repaired`, `primary_corruption_pulled_from_replica`, `missing_object_on_replica_repaired`).
- OSD-level scrub: `tell osd.N scrub|deep-scrub|repair [pgid]` (classic registers `scrub`/`deep-scrub` with an optional pgid); without pgid = every PG this OSD is primary for. Implemented as an `MOSDScrub2` to ourselves (broadcast to all cores); `MOSDScrub2` with an EMPTY pg list now means the same (classic semantics), so `ceph osd scrub|deep-scrub|repair N` works from the mon too. Passive (EC) pools skipped as before; the answer is a text (`instructing all pgs on osd.N to scrub`), PG existence is not checked (other cores own them).
- `dump_ops_in_flight` / `ops` / `dump_blocked_ops` also list the ops parked for a map, the OSD to become active or their PG (`pg.parked`), flag point/event `waiting for map|waiting for osd to be active|waiting for pg`, `initiated_at` = first wait; they were already in `op_wip` and SLOW_OPS.
Consequences: + dashboard "OSD histogram", devicehealth on lab kernel NVMe, `rados list-inconsistent-*`, `ceph osd scrub`, no invisible waiting ops; - scrub findings not persisted across restart; - histogram cost ~ 1 division per client op on the hot path (negligible next to the reply path; measured nowhere yet).
Alternatives: histograms behind a config flag (extra branch for no gain), persisting findings in the PG meta object (format change; revisit when a restart scenario matters), faking `selected_oi` attrs (needs the scrub map attrs kept per object: memory).
Verified: unit tests (`osd::perf`, `nvme::kprobe`, `peering::scrubls` + `scrub_primary` tests, `osd` tell/boot/parked tests). NOT verified live: ceph CLI `rados list-inconsistent-obj` JSON output against real shard data, `perf histogram dump` in the mgr dashboard, kernel probe on a real `/dev/nvme*`, iface strings on a VF host.
