# 0249 C ABI kernel worker and peer policy
Status: accepted
Date: 2026-10-15
Context: C cluster/ioctx handles may be used by multiple foreign threads. Native client deliberately !Send, owns per-session state and event selector. Pin defaults prefer Secure for monitors and CRC for OSDs; sharing one policy would silently change configuration semantics.
Decision: initially one sleeping owner thread per C cluster, constructing/dropping native owner on that thread. Bounded64 command channel; native Waker signals submissions, AtomicBool+wake stops independently of channel pressure; pending synchronous responses settle on result or shutdown. No polling loop while idle, no unsafe Send wrapper for client. Capture ioctx byte namespace/locator and owned request input before enqueue; return owned results to caller for buffer copies. Add CRC-first allowed-mode policy and explicit NativeSessions OSD-policy constructor; existing constructors retain shared-policy behavior. Default C monitor/OSD order remains independent. Async callbacks require separate executor before exported asynchronous I/O, to permit callback->sync calls without owner deadlock.
Consequences: legacy adapter adds thread/handoff/locks/copies; no performance gain assumed. Many-cluster shared-worker consolidation/long-idle/resource qualification remain gates; native group reactor unchanged. Generic legacy config/foreign contexts/full ABI still open. Compatibility credit/backpressure must not replace original semantics silently; qualify incrementally.
Alternatives: unsafe Send+Mutex around native owner rejected; independent native identity per calling thread breaks cluster identity/order; global spinning worker violates idle requirement; original-library forwarding prohibited.
