# ADR0287: Removed default TMAP C contracts, no legacy subsystem
Status: accepted. Date: 2026-10-16.
Context: remaining inventory includes rados_tmap_get/put/update. Exact pin default symbols introduced14.2.0 return EOPNOTSUPP unconditionally. Historical base symbols implement old TMAP behavior but are not the current default API. User explicitly requires only compatibility-needed behavior, no unnecessary legacy internals.
Decision: three default unversioned C names return Linux EOPNOTSUPP(-95), read/write no pointers, post no work, leave buffers unchanged. Do not add TMAP codecs/storage/client protocol operations or cache-tier support. This completes those current default contracts only; historical ELF symbol versions remain unqualified and are not claimed. Own NULL/sentinel tests and unchanged original-linked offline consumer resolve default symbols from actual original library with symbol manifest evidence. No new dependency/thread/runtime state.
Source audit: pin b6f98ed07f44274e393138ffbae442b7a3f7ec84, librados_c.cc2121..2197 distinguishes LIBRADOS_C_API_BASE_F vs DEFAULT_F and tags default14.2.0. Own spec172 before implementation. No reference code copied; unconditional unsupported contracts are public API behavior.
