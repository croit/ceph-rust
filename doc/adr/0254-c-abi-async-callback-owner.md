# 0254 C async owner and callback delivery
Status: accepted
Date: 2026-10-15
Context: RC121 completion lifetime substrate is implemented; C synchronous owner is sleeping and thread-affine. Async C consumers require callbacks that may issue synchronous I/O on the same cluster. Executing them on native owner deadlocks.
Decision: native owner handles admission, output copies and terminal publication; one sleeping callback executor per connected cluster handles configured foreign callbacks. Async submission waits only for native admission acknowledgement; accepted operation owns completion/ioctx independently, admission failure rolls back claim without callbacks. Convert ioctx raw ownership to Arc. Separate terminal publication from callback invocation while retaining existing completion wait semantics. Shutdown joins owner first, drains callback executor, and skips joining executor from itself.
Legacy resource policy: bounded native requests/input mailbox remain. Completed callback jobs contain already-retained completion/ioctx and no retained network/result buffers; queue metadata may grow with application outstanding completions. Do not block native progress on callback consumption: a callback may synchronously wait for native work. Qualify/measure stalled-callback memory before release; no production resource-bound claim. Revisit intrusive preallocated completion linkage only with measurements.
Consequences: extra legacy adapter thread and queue/handoff overhead; no speedup assumed. Native Rust reactor unchanged. API caller controls outstanding completions. Full async family/flush/cancel/compound/resource/fault/platform gates remain open.
Alternatives: owner callbacks deadlock reentrant I/O; thread per request has excessive thread cost; finite callback queue blocking owner recreates the deadlock; forwarding original library violates independent replacement goal.
