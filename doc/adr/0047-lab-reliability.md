# 0047 Lab reliability: shared lib, heartbeat, trim-on-free, interleaved A/B
Status: accepted
Date: 2026-10-11
Context: Incidents: VM disk filled 3x (lab store files only grow; classic file-backed bluestore never discards), a 24 h soak hung 6 h silently (unbounded docker/ceph calls), HEALTH_ERR logged as ok, an agent died mid-run without evidence, bare-metal day drift (+-10%) faked a regression.
Decision:
- `lab/lib/common.sh` sourced by all docker suites (via docker/lib.sh) and ab.sh: sizing from VM disk (all devices < 55%), disk_guard (fail < 15% free), log rotation opts, bounded calls `t()` (also shell functions; evidence on timeout; `wait_for` probes bounded), strict health (any code fails except HEALTH_IGNORE), evidence bundle on every FAIL/timeout (rate-limited), ok/bad/summary.
- Heartbeat `$OUT/status.json` (+ symlink in /var/tmp/croit-flashstore-lab-status) written by every suite/soak at each step; EXIT trap marks a dying run failed; `lab/status.sh` (Mac) shows one line per VM from `$LAB_HOSTS_FILE` (template lab/hosts.txt.example), STALE after 15 min.
- FileDev (feature `lab`, Linux): deallocate = fallocate(PUNCH_HOLE|KEEP_SIZE). Superseded by adr 0642: every tier (FileDev included) deallocates freed blocks through one paced path that holds the blocks until the completion (`BlockDev::trims_freed` removed).
- Classic BlueStore on files cannot discard: KernelDevice discards only via BLKDISCARD (verified in src/blk/kernel/KernelDevice.cc), a regular file gets no device name (support_discard=false). `bdev_enable_discard`/`bdev_async_discard_threads` are set in up.sh but only act on block devices. Bound = OSD_SIZE from sizing.
- `lab/baremetal/ab.sh`: A B A B ... N rounds, unique RUNP, median/min/max, delta%, noise flag (measured run half-range, no fixed floor; see am. 1).
Consequences: + no unbounded waits, evidence on every failure, visible stuck runs, lab files shrink for croit-flashstore-osd; - classic OSD files still grow to OSD_SIZE (bounded, not shrinking); C/R now default to 120 s per call (CT/DT to change); trim path in the shard is dead code unless a device opts in.
Alternatives: loop devices for classic OSDs (privileged, risky on shared VMs); trim in the store for all devices (ordering vs reuse on real NVMe, perf risk); zabbix-style external monitoring (overkill).

## Fast lab profile + case timing (live-suite wall time)
Decision: live suites run `LAB_PROFILE=fast` by default (`real` = stock timers for final gates / timing-sensitive measurements). The profile is CENTRAL config (`ceph config set`, marker config-key `lab/profile`, applied idempotently by `lab_profile_ensure` at every case start; `real` removes the keys): osd_heartbeat_interval 1 / grace 6, mon_osd_report_timeout 30 with osd_beacon_report_interval 10 (stock ratio 3:1, am. 2), mon_osd_down_out_interval 60 (> longest intentional outage of any case, so recovery cases stay log-recovery, not backfill), mon_osd_adjust_heartbeat_grace false, paxos_propose_interval 0.25, mgr_stats_period 1, mgr_tick_period 1, target_max_misplaced_ratio 1.0, pg_autoscaler sleep_interval 5, mclock override + skip_benchmark, osd_max_backfills 8, recovery_max_active 8/16, recovery sleeps 0, scrub load threshold 100 + scrub during recovery, mds_beacon_grace 8. croit-flashstore-osd honours the same names (services/osd/osd/src/config.rs layering). Cases whose assertion needs stock throttles (mixed 09 revoke, 10 reservation contention: osd_max_backfills 1, recovery sleeps) call `case_slow_recovery` (restored by `case_end`). Timer-dependent proofs (nodown/noup/noout dwell windows in mixed 05, stale-process dwell in 06) shrink their dwell with the profile (`nap REAL FAST`) but keep it >= 2x the profile grace.
Waits: `wait_for` polls every `WAIT_POLL` (1 s fast, 2 s real); fixed sleeps became events (load progress `load_warm`, `up_from` change `wait_restarted`, deep-scrub stamps `wait_deep_scrub`/`deep_scrub_pool`, pg_num reached, loadgen done files instead of `pgrep -f`). Remaining fixed sleeps are `nap` (booked, stimulus/dwell only).
Timing: `tm_scope` buckets wait/nap/load/other per case -> `$RES/timing.tsv`, `timing:` line per case, table at end of mixed run-all; `waited Ns: <desc>` lines for waits >= 5 s.
Consequences: + >= 3x shorter dev runs, attribution of wall time; - fast profile is not what operators run: final gates use `LAB_PROFILE=real`; a cluster-wide profile changes timers of every suite sharing that mon (one agent per lab).

## Amendment 1 (2026-10-28): reference gates are noise-based, never a fixed loss band
Decision: croit-flashstore-osd must be >= BlueStore and rustyrados >= stock librados in every cell. Every gate or table that compares a candidate with a reference (BlueStore, stock librados, main, the other A/B arm) uses one rule, `lab/lib/gate-noise.awk`: PASS when candidate >= reference (lower-is-better metrics: <=), or when the deficit is within the MEASURED noise of that cell; else FAIL. Noise = relative half-range `(max - min) / 2 / median` of the repeats (rounds, turns, reps) of the candidate and of the reference, the larger of both. An arm with fewer than 2 samples has no noise estimate: noise 0, strict comparison, reported as "single sample, no noise estimate" (`*`, `n`). No fixed percentage band (the former 3 % / 5 % / 10 % / 0.95 / 0.97 / 1.02 / 1.10 tolerances are removed). Every output carries the noise used (`noise_pct`, `n`). Scripts: kvnme-gate, read4m-qd1-gate, knet-wake-gate, knet-dial-gate, op-cpu-gate, op-trace-gate, scoreboard-report (WIN beyond noise / TIE within noise / LOSE), cstate/score-sum, omapx-ab, omapx-arms-sum, omapx-recheck-sum (single sample, strict), compression-gate (omap-w4k-8x64 baseline = mean of the two recorded runs less their half-range), elastic-bench, ab.sh. Selftest: `lab/baremetal/gate-noise-selftest.sh`.
Consequences: + a loss hidden by a tolerance band fails; a cell inside the noise is re-run with at most 3 repeats per arm (AGENTS.md Tests); - ROUNDS=1 gates are strict and fail on any deficit; a feature that costs instructions beyond the repeat spread fails op-cpu-gate (no allowance for opt-in costs).

## Amendment 2 (2026-10-29): fast profile beacons every 10 s
Decision: the fast profile sets `osd osd_beacon_report_interval 10` next to `mon_osd_report_timeout 30` (stock 300 / 900: the same 1:3 ratio).
Rationale: a newly elected leader starts its beacon bookkeeping empty and times each up OSD out after `mon_osd_report_timeout` until that OSD's next beacon (the per-OSD allowance of twice the reported interval applies only after a beacon). OSDs beacon at once only on a new mon session; one whose session survived the election beaconed after the stock 300 s and was marked down 30 s after the leader's warm-up ("marked down after no beacon for 30 s"; classic and croit-flashstore-osd alike). Seen in mixed case 23 right after case 25's mon teardown, on main and branch builds.
Consequences: + no spurious down marks after elections in fast runs; - one beacon per OSD per 10 s to the mon (lab scale); `real` keeps the stock pair.
