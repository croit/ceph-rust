# 0175 One process memory envelope from osd_memory_target
Status: accepted, amended (am. 4) (2026-10-19)
Date: 2026-10-19
Context: external review P2: caches (adr 0062), ingress windows (adr 0084), msgr2 frame assembly, checkpoint arena and replay retention each had a bound, none summed to a process bound; 8 shards alone permitted ~1 GiB of ingress outside `osd_memory_target`. "Hundreds of clients" needs an aggregate.
Decision:
1. ONE knob: `osd_memory_target` T. Shares derived in `osd::memory::Envelope`: ingress `I = max(T/16, 256 MiB)` split in two equal pools (client `I/2`, peer `I/2`); caches `= max(T - osd_memory_base - I, osd_memory_cache_min)` (adr 0062 point 1 now subtracts I too: default 3328 -> 3072 MiB); base stays `osd_memory_base`. No separate config for any share.
2. Enforcement in `crates/ingress`: `IngressCredits::partitioned(groups)`; windows of a group share a byte pool; a reservation that would exceed the pool is refused (existing hold/backpressure path: input retained, transport paused). Client and peer data are separate pools (adr 0084 am. 2: a shared pool re-creates the PG hang). An empty pool admits one oversized input (liveness; the op layer rejects > `osd_max_write_size`). Retained frame bytes (`retain_frame`) count too. Lock-free (atomics), no allocation on the hot path (adr 0006); one extra `fetch_add` per reservation and per release.
3. Accounting: `dump_mempools` `envelope` (target/base/ingress/caches, pools `used/limit/stalls`) and pools `ingress_client|peer|held`.
4. Not enforced, listed with a plan in doc/design/memory-envelope.md and OQ 60: G1 memory before reservation (frame assembly + one held decoded input per connection: needs header-time admission in msgr2 and the three transports), G2 checkpoint arena atop the caches (store config), G3/G4 PG log and recovery pushes (inside base, estimates). No health warning: the mon takes only classic daemon health metrics.
5. Pressure gate: `lab/docker/mixed/20-memory-envelope.sh` asserts VmHWM <= T + fixed overhead under 300 concurrent large writes.
Consequences: + ingress bounded by T independent of shard count/ core count; + operator sees pool occupancy and stalls; - default caches 7.7 % smaller; - the process bound is complete only after G1 (until then bounded by pools + connections x 2 x op size, measured in the gate).
Alternatives: per-window limits only (rejected: sum grows with shards); one shared pool (rejected: PG hang); RSS enforcement via cgroup/mallopt (rejected, adr 0062 point 3); separate knob (rejected: one-knob rule, KISS).
Tests: `ingress` pool unit tests (sum bound, group independence, oversized alone, retained frames), `memory::tests`, osd `mempools_shape`, `mem_target_tests`, lab case 20.

## Amendment 1 (2026-10-19): reservation at the frame header, soft target, arena inside the caches
Context: user + coordinator: `osd_memory_target` is a SOFT target (as in Ceph); operation never stalls, brakes smoothly, fair across hundreds of connections; G1 (memory before reservation) must close.
Decision:
1. Point 2 is replaced: a MESSAGE frame reserves its length from the client (public messenger) or peer (cluster messenger) pool when its preamble is parsed, before any body byte is consumed (one choke point: the shared msgr2 `Decoder`; `ingress` frame windows, `FrameGate`). The reservation travels with the message (`Incoming.ingress`) and replaces the later shard-window step; cut-through takes it over.
2. SOFT pool: admit while `used < limit` (overshoot <= one frame per concurrent admitter); no "empty pool" rule. A full pool parks the connection at the header; `Osd::input_ready` is false so knet and the own stack leave the socket unread (TCP backpressure; no drop, no timer). Parked links retry strictly FIFO per core via `resume_inputs`; while a connection waits newcomers queue behind it (`Pool::waiters`): no starvation, no head-of-line PG hang (client and peer pools stay separate, adr 0084 am. 2).
3. G2: the checkpoint arena is part of the cache unit (`CACHE_UNIT_BYTES` = pages + soft-dirty arena + point cache + delta cap = 168 MiB per 16384 pages, was 152): `caches = target - base - ingress` now includes it; the hard-dirty mark (3/8) stays an overload stall level that may overshoot. Page cache share of the caches 84 % -> 76 %.
4. Gate criteria (lab case 20) follow the soft target: VmHWM <= target + 25 % with the overshoot reported, no op latency outlier (max/avg), 300 real connections.
Consequences: + frame assembly and held inputs are inside the envelope (G1 closed); - page cache 9 % smaller at equal target (measured against BlueStore on the kernel tier, doc/perf/memory-envelope.md); open: G3 (PG log), G4 (recovery pushes), G5 (byte-relay pipes), health warning (needs the mon).
Siblings checked: knet and the own stack (AF_XDP; DPDK parked, compiles) share `Osd::input_ready` and the decoder; kernel-NVMe / SPDK share the same `Osd`; replicated and EC reserve per message; crc and secure both gate at the preamble (`secure_want` is 0 while parked).
Tests: `ingress` frame-gate/soft-limit unit tests, `msgr2/tests/gate.rs` (v2.0 + v2.1 header parking, retry, reservation lifetime), store `for_memory_scales_caches`, lab case 20 (300 connections).
5. knet (found by the 300-connection gate, 2026-10-19): a link parked at a message header must not drain its socket into the shared hold storage (`Driver::rx_parked`: in-flight chunks go to the decoder, the link is then paused). Held chunks pinned the receive buffers of the whole core; ~100 parked links stalled every connection (handshakes, mon, peers) for good. Perf doc: doc/perf/memory-envelope.md.

## Amendment 2 (2026-10-29): `osd_memory_target` from the mon config db
Context: the envelope came from the local `--set` config only, and `croit-flashstore-osd run` did not forward the conf file's memory options: a target set with `ceph config set` (mon config db, authoritative for classic OSDs) or in ceph.conf never applied (lab 2026-10-28: 8 GB in the mon db, the OSD ran with 4 GiB; doc/perf/osd-rss-growth-20261029.md).
Decision:
1. Per option (`osd_memory_target`, `osd_memory_base`, `osd_memory_cache_min`): local (command line `--set`, conf file) > mon config db > Ceph default, as in Ceph (file above mon). `croit-flashstore-osd run` forwards the conf file's memory options (`config::forwarded`).
2. Bootstrap as a classic OSD before it starts: `croit-flashstore-osd run` with a prepared OSD dir opens one short mon session as `osd.N` (key of the dir's keyring; mon host, hostname, `ms_mon_client_mode` as the daemon session) and takes the first MConfig (`osd::monboot::fetch_config`). Bound 10 s (the daemon's own first-config wait); on expiry a `WARNING TIMEOUT` line and the start continues on local config + defaults. No OSD dir (direct lab starts): no bootstrap.
3. Sizes in Ceph's size grammar (`memory::parse_size`, doc/spec/osd-lifecycle.md 2.7).
4. The envelope is sized once before the stores mount: a later change of the effective target (MConfig, `config set`) logs once per value `osd_memory_target X MiB differs from the active Y MiB: applies at the next start`. Classic applies it live (cache autotuner); live store cache resizing is open (doc/90-open-questions.md).
5. Startup line `memory envelope: osd_memory_target X MiB (local|mon|default), ...: caches, ingress`.
Consequences: + `ceph config set osd osd_memory_target` and ceph.conf take effect at the next start, as the operator expects from classic; - one extra short mon session at start (as classic); - a runtime change needs a restart (logged, documented difference).
Siblings checked: every daemon flavor (kernel tier, own stack, dev driver) sizes through `set_memory_target` with the same bootstrap map; SPDK and kernel NVMe share it; replicated/EC and crc/secure: not affected (sizing only).
Tests: `memory::tests::{sizes_in_ceph_grammar, restart_note_once_per_value}`, `nvmestore::mem_target_tests` (mon layer, precedence), `monboot::tests` (OSD session settings, timeout without a mon), `run::tests::conf_memory_options_are_forwarded_and_the_dir_returned`.

## Amendment 3 (2026-11-06): oversized MESSAGEs admitted alone; oversized writes refused unadmitted
Context: amendment 1 point 1/2 plus the decoder frame cap faulted a MESSAGE above the pool or above `osd_client_message_size_cap` at the preamble, so the client reconnected and resent instead of seeing the op error; classic admits one message above its byte-throttle max whenever the throttle is not over it and only the op fails (spec msgr2.md 8.2; doc/90-open-questions.md, decided 2026-11-06).
Decision:
1. A MESSAGE larger than its pool or larger than `osd_client_message_size_cap` is never faulted for size. It waits until nothing else of the pool is in flight (no reservation outstanding, no older frame waiting), is then admitted as the pool's single oversize reservation (the pool overshoots to the frame size) and keeps every other frame of the pool waiting until it completes; it is processed normally. Only the wire shape (`Limits`, spec msgr2.md 4.1, 16 C7) faults.
2. A public-link MOSDOp whose front alone classifies `may_write` (NOSNAP, no `call` whose class method would decide WR, no pg op, uncompressed) and whose declared data segment is above `osd_max_write_size` never has that segment admitted: the data segment is consumed unadmitted (crc still verified, secure plaintext decrypted/authenticated and dropped), never buffered and never charged, and the op carries its declared length through the unchanged pipeline, where rule 14 answers -EMSGSIZE in classic's reply shape before anything executes, at once or after a park. Every other front (non-write, `call`, non-NOSNAP, pg op, compressed) keeps its data segment and is decided as classic. Spec client-ops.md 5.4.1, msgr2.md 8.2.
3. (Point 3's front-only charge with a later data join is superseded by adr 0688-split-frame-memory-reservation: the preamble reserves the whole declared frame, a refused segment is given back.) One admission decision per frame, at its preamble (amendment 1 point 1 with the split removed): whether a frame is alone is decided there, on its whole declared size (all segments, the `sum(seg1..3)` and `wire` numbers above), never at a segment boundary. An alone frame waits (FIFO, like any frame) until the pool holds nothing, takes the pool as its single reservation (`ingress::ALONE`) with its front and keeps it until it drops; an ordinary frame's front is admitted under the soft rule. After the probe, a data segment the frame keeps joins that reservation unconditionally: no pool limit check, no window byte-cap check, no FIFO turn, no waiter, never a second refusal (the counters still add up exactly, an alone lease keeps its tag); the segment of a refused frame is consumed crc-only, never buffered and never charged. So the pool holds a frame's front from its preamble on and its data segment from the front's completion on (no payload is ever buffered uncharged), the bound stays amendment 1's (admitted while `used < limit`, overshoot <= one frame per concurrent admitter), and a frame waits only at its header.
Consequences: + no client reconnect/hang for an op classic rejects; + oversized write bodies are never buffered and never charged; + no frame holds a front while waiting for its data (removes the two hold-and-wait deadlocks of split admission: two fronts waiting for each other's pool to empty, and a data segment queued behind a waiting oversized frame); - an oversize non-write frame still overshoots its pool to its declared size while it is in flight (classic holds the same bytes in memory); - intake classifies the op after the front, so an oversized write's reply waits for its frame's pool turn.
Siblings checked: knet, AF_XDP (compile only), DPDK (parked) share the decoder gate; SPDK/kernel NVMe and replicated/EC are not affected (ingress only); crc and secure mode both keep their frame checks (the crc path charges the front and joins the admitted data segment, the secure path charges the whole frame at its preamble and gives a refused segment back).
Open questions: OQ 140 (ungated receive path) is not on this path: an admitted frame carries its gate reservation, so gated links never charge an oversize frame to the input lease (see the OQ entry).
Tests: `msgr2::tests::gate::{a_frame_above_the_pool_capacity_is_admitted_alone, a_message_above_the_link_cap_is_admitted_alone, the_link_cap_counts_segments_after_the_header, the_link_cap_is_message_only_and_needs_no_gate, a_refused_data_segment_is_consumed_and_the_stream_continues, a_damaged_refused_data_segment_still_faults, a_split_frames_data_segment_is_reserved_with_its_front, an_alone_frame_is_decided_at_its_preamble, two_split_frames_above_the_pool_complete_in_turn, a_data_segment_does_not_queue_behind_a_waiting_frame, a_refused_data_segment_is_visible_to_borrowed_delivery, a_split_frame_above_the_pool_completes_alone, the_secure_path_reserves_the_whole_frame_with_its_data_segment}`, `ingress::tests::{a_frame_above_the_pool_capacity_is_admitted_alone, an_alone_frame_keeps_the_pool_until_it_drops, an_alone_input_keeps_the_pool_as_its_single_reservation, shrinking_an_alone_lease_keeps_the_pool_exclusive, no_ordinary_admission_passes_an_alone_lease_under_contention}`, `osd::xcore_tests::oversize::{an_oversized_write_is_refused_unadmitted_and_the_link_keeps_working, an_oversize_non_write_message_is_processed}`, `osd::tests::client_message_size_cap_reaches_public_links_and_new_connections`.

## Amendment 4 (2026-11-06): DMA budget of the SPDK tier
Context: e9455 2026-11-06 (build 74095729ab, SPDK tier, 30 OSDs, EC 2+2, 4M seqread 3x16 jobs, `--cores 6 --mem 2048`): `spdk_dma_malloc(262144)` returned NULL, `assert!` at crates/nvme/src/spdk.rs:480 panicked core4, crash loop ~5 s after PGs went active (recovery + client reads). Store DMA buffers had no bound against the EAL heap: parking up to 256 MiB per store core (1.5 GiB at 6 cores) beside an SPDK share of ~1 GiB (the other half of `--mem` is the payload budget, adr 0076 am. 3), read pipelines (pf + rolling + data cache, ~96 MiB per shard), shared reply data in transit unbounded; on a NULL only the failing core's pool drained. Same build at `flashstore_hugepages_mb` 4096: no panic, but EC 2+2 reads at 7-60 % of the kernel tier (p99 0.25-1.5 s) while rep3 reads were at parity: on the SPDK tier payloads and store DMA share one EAL heap without a joint bound, EC reads hold more DMA for longer (prefetch of queued sub-reads, local shard data held for the peers' round trip, shard replies and assembly >= 128 KiB in the payload heap), so heap refusals and drains of every pool (memset under the DPDK heap lock on all cores) recur on the blocking EC read path. doc/perf/spdk-dma-budget-20261106.md.
Decision:
1. One store DMA budget D per process (`nvme::dmapool::DmaBudget`): every block DMA buffers hold from the DPDK heap (live, parked, in a return inbox, in transit) counts. SPDK tier with the DPDK EAL: D = EAL heap free once SPDK and every device queue are up + blocks held already - what the payload budget may still take (`kprod::store_dma_budget`); D = 0 ends the start ("raise flashstore_hugepages_mb"). Startup line `store DMA budget`.
2. Every store allocation is refusable; a refusal is backpressure that the caller retries from a loop that polls completions, never a blocking wait on a reactor. Two kinds:
   - K1, deferrable (`BlockDev::try_alloc_buf_uninit`: pf, rolling and defrag reads, the fused copy+crc of a write or pre-write run): admitted while everything held stays within the read gate 3/4 D. Refused: reads resume at a later pump (an unfinished rolling read no longer expires after `PF_TTL_NS`); a write run takes its crcs over the source and is staged as a deferred copy (`CopyRun`: the payload `Bytes`, a heap copy only for borrowed input); staging never fails for memory.
   - K2, in-flight IO (`BlockDev::try_alloc_io_uninit`: allocated right before a submit, freed at its completion: WAL images, built at submit; tree pages; checkpoint and root; olsm run reads and writes; defrag split copies; lending table; `sio` jobs of mount, replay and fsck; synchronous reads; deferred write copies, taken when they reach the device backlog front, at most one run each): admitted within the full D. Refused: postponed in order and retried at the next shard poll (an olsm read takes the buffers of all its parts or none and keeps the shard busy while unsent; `sio` idles and retries). A K2 buffer leaves zero-copy (`into_shared`) only while held <= 3/4 D, else as a heap copy.
   - tools and tests (`DmaBuf::new_uninit`): counted; an empty heap panics naming the hugepages (never on a store core).
   Start is refused on the SPDK tier with a budget when `--store-shards` > store cores, or when D/4 < the largest K2 hold of one request before its submit (max(max transfer, 256 KiB) + one WAL pad block, each at its allocator class size `dmapool::alloc_len`; every multi-part K2 request, e.g. an olsm read longer than one transfer, takes and submits its buffers one part at a time and assembles landed parts in ordinary memory); the error names the `flashstore_cores` / `flashstore_hugepages_mb` value to set.
3. Shared reply data in transit (`IoBuf::into_shared`) holds at most D/2 zero-copy; beyond, it leaves as a heap copy (`share_copies`; retained prefetch runs that went out shared count until dropped). Gate - share >= D/4: the store's read pipeline progresses whatever the network and EC peers hold (no cross-OSD hold-and-wait).
4. Parked memory: a refused data request records its size as `want` (the largest one waiting). Every store sweep (`BlockDev::release_pooled`, each core, every `SWEEP_NS`) adopts its return inbox and gives back parked blocks while held + want > 3/4 D (`Pool::trim`), and no pool parks while held + want > 3/4 D; `want` clears once a request of that size is admitted or the gate has room for it. A refusal at the gate thus frees other cores' parked memory within one sweep; the refused core first trades its own parked blocks, largest first, only as many as it needs. A drain of every pool (pressure epoch) follows only a heap refusal within the budget (fragmentation, another heap user; `pressure_drains`, expected 0).
5. Why no reactor can deadlock on DMA memory: (a) nothing sleeps on memory: every refusal returns to a loop that polls the core's completions (pump, shard poll, store sweep, `sio` drive); (b) invariant: memory held without IO in flight <= 3/4 D, because every path that leaves memory so held checks the gate (K1 admission, parking, K2 -> shared); K2 is held only between submit and completion; (c) hence a refused K2 request (<= D/4, checked at start) implies K2 IO in flight, which completes on its shard's core and frees its buffer; (d) staging never waits for memory (deferred copies), a blocking wait (synchronous read, commit, checkpoint, `sio`) waits only for K2 and polls its own shard, and shards <= cores (checked at start) means no sibling shard on the same core depends on it; (e) memory held without IO is released without the waiter: shared data <= D/2 drains with the network (the cap breaks the cross-OSD EC cycle), prefetch runs expire after 200 ms, parked blocks go back through `want` (4). A long wait warns `WARNING TIMEOUT` once per 30 s and keeps waiting (backpressure, never a failed op); a blocking store wait fails only with device IO in flight and nothing completed or submitted for 30 s (a device stall).
6. Counters (`flashstore_dma_pool`): `budget_bytes`, `held_bytes`, `held_peak_bytes`, `shared_bytes`, `shared_peak_bytes`, `data_short`, `io_short`, `heap_short`, `share_copies`, `want_bytes`, `pressure_drains`; store: `deferred_copy_bytes` (object stats), `backlog_dma` (shard stats).
Consequences: + DMA exhaustion never ends the process and never blocks a reactor; reads and writes back off; EC/recovery read peaks bounded; + payload use cannot empty the store's share of the heap (D excludes the payload budget), budget pressure costs one sweep of parked blocks (no cross-core drain storm); - shared reply data beyond D/2 costs a copy; - a refused write copy keeps the payload (or a heap copy of borrowed input) until its submit, then copies once into a K2 buffer (the non-fused crc pass costs CPU); - SPDK with a budget needs shards <= cores; - a pool miss does one CAS on `held`, a shared read two more atomics; - the DPDK-networking tier (`prod.rs`, parked) and SPDK builds without the dpdk feature run without a budget (D = 0: heap-limited, still no panic, IO backs off on NULL).
Siblings checked: kernel NVMe tier not affected (store buffers come from the process heap or the kdev arena, which falls back to the heap; payloads fall back on a budget miss; the refusable calls never refuse there). Replicated/EC and recovery/client share the store read and write paths (covered). crc/secure: no DMA allocation. knet/AF_XDP: payloads have their own budget (adr 0076); DPDK networking: no-panic and back-off only.
Tests: dmapool unit tests (gate, share cap, release, trade largest first and only as needed, no parking above the gate, a refusal makes another core's sweep give back its parked blocks, in-flight IO within D, io buffers shared above the gate copy), `nvme/tests/dma_budget.rs` (EAL without hugepages, 64 MiB heap: refusal not panic and no drain, in-flight IO served beyond the gate, an io buffer above the gate copies, own-pool trade, remote parked blocks given back after a refusal (core A parks, core B refused, A's sweep frees), share copy, empty heap = refusal), store `obj::{refused_dma_buffers_postpone_reads_and_never_fail_them, refused_write_copies_are_deferred_to_the_submit, refused_io_buffers_postpone_wal_pages_checkpoints_and_reads}`, `sio::tests::refused_buffers_wait_for_memory_and_never_fail`, `shard_olsm::tests::{olsm_read_refused_dma_memory_is_sent_by_a_later_poll, olsm_read_longer_than_the_budget_admits_completes_part_by_part}`, `obj::shardio::tests::{a_stalled_wait_fails_only_with_device_io_in_flight, a_submit_after_a_refused_stretch_is_progress}` (SimDev refusals). Gate: `lab/dma-budget-tests.sh` (runner), `lab/spdkpool-check.sh` (build host, spdk).
