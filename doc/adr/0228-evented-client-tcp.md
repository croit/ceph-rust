# 0228: lab event-driven TCP adapter for the shared client owner
Status: accepted
Date: 2026-10-15
Context: user requires efficient default idle; pinned reference already sleeps cheaply. [ADR: client efficient idle default](0402-client-efficient-idle-default.md) accepts kernel TCP as the production client default direction; production implementation and qualification remain incomplete. Existing TcpOwner engine boundary can be driven by kernel readiness without Probe or another protocol stack.
Decision: add kernel-lab feature (depends on lab), latest permissive Mio with net/os-poll, static KernelTcp<TcpOwner>. Fixed connection/event/buffer/work bounds, nonblocking TCP/readiness, partial-output preservation, earliest owner timer wait, Arc<Waker> for external scheduler notification. Logical streams remain owner-defined; selector tokens never reused. Conservative TcpOwner::can_sleep default false; known idle owner overrides only with no unprocessed work. Unknown/custom owners cannot silently lose internal progress by sleeping. No automatic kernel fallback or production transport/default change.
Consequences: explicit lab path for idle/readiness/close/clock/resource qualification, reusable engine unchanged. First quiescence hints permit no-outstanding-work idle; control/watch/pending-operation efficient waiting and shared multi-client reactor/mailbox require further implementation/qualification before production. No dedicated-thread requirement or submission mailbox is introduced by a Waker alone. DPDK path remains separate and unchanged.
Alternatives: sleep in existing busy loop (periodic wake overhead and latency, no readiness proof); copy Probe kernel driver (duplicates protocol ownership); raw epoll/eventfd FFI (unnecessary platform API surface); assume progress()==Ok implies quiescence (unsafe under bounded work). Required own real-socket wake/timer/budget/partial-write/stale-token/close tests; native classic CRC/Secure and idle CPU qualification follow. Full W/N not complete.
