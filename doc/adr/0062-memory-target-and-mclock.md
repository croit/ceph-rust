# 0062 osd_memory_target as store cache budget; mclock accepted and ignored
Status: accepted
Date: 2026-10-11
Context: classic OSD autotunes BlueStore/RocksDB caches to `osd_memory_target` (default 4 GiB; `osd_memory_base`, `osd_memory_cache_min`). croit-flashstore-osd had the options but used fixed per-shard cache sizes (ShardCfg default 16384 tree pages x 8 KiB = 128 MiB per shard, point cache 32768 entries, delta cap 16 MiB; 32 shards = ~4+ GiB regardless of config). Operators size hosts by osd_memory_target (several OSDs per host).
Decision:
1. Budget = clamp(osd_memory_target - osd_memory_base, osd_memory_cache_min, ...) bytes for the store caches of the whole process; split evenly over all shards of the device. Per shard: `cache_pages = budget / shards / 8 KiB` (min 4096 pages = 32 MiB: a txn budget is half the cache and a 10 MiB dirfrag batch needs 2-4k pages), `dirty_soft = cache/8`, `dirty_hard = cache*3/8`, `point_cache` and `delta_cap_bytes` scaled by cache/16384 (floors 1024 entries, 1 MiB). Defaults (4 GiB, 768 MiB base) reproduce today's per-shard values about 20% below (the base is subtracted).
2. Read ONCE at start from the local config (conf file / `--set osd_memory_target=...`), before mount, via a process-wide setting (`osd::nvmestore::set_memory_target`). Not autotuned, no runtime resize: `ceph config set osd osd_memory_target` (mon config db) arrives after mount and takes effect at the next restart (documented in doc/ops/deploy.md). Size suffixes K/M/G/T accepted.
3. We do not enforce RSS: hugepage/DPDK/SPDK memory, net buffers and PG state are outside the budget; the target only sizes the store caches. `perf`/`status` do not claim autotune. Operators lowering the target below ~1.5 GiB x shards/32 get the floor.
4. mclock: `osd_op_queue`, `osd_mclock_profile`, `osd_mclock_*`, `osd_mclock_max_capacity_iops_*` are ACCEPTED and IGNORED (no scheduler: PG-per-core ownership, recovery/scrub limited by osd_max_backfills, osd_recovery_max_active*, sleeps; adr 0006). Exception (adr 0031 am. 10): like classic with mclock, `osd_max_backfills` / `osd_recovery_max_active*` set at mon/runtime level are removed with a WARN unless `osd_mclock_override_recovery_settings`. No boot benchmark, so nothing writes `osd_mclock_max_capacity_iops_*`. `ceph tell osd.N bench` (WP-T) answers measured throughput for operator sanity only.
Consequences: + memory sized like classic; - no dynamic autotune, restart needed.
Alternatives: runtime resize (rejected: cache shrink needs eviction passes on every core; no demand); enforce RSS via mallopt/cgroup (rejected, not our allocator).
Tests: store `for_memory_*` unit tests.

## Amendment 1 (2026-10-12): budget covers pages + point cache + delta cap; accounting in dump_mempools
Finding (doc/perf/memory.md): RSS of a loaded OSD reached 3.9 GiB at the default target (4 GiB), no leak. The cache budget was spent on tree pages only; point cache (~214 B/entry) and leaf-delta cap came on top (+19% at the default). Fix: per cache scale unit (16384 pages = 128 MiB) the shard share is pages 128 + point cache 8 (32768 entries x 256 B) + delta cap 16 MiB; `pages = share/8 KiB x 128/152` (`StoreCfg::for_memory`). Not covered (the base, `osd_memory_base`): PG log (~1 KB per entry in RAM; trimmed to the min when clean, up to osd_max_pg_log_entries x PGs when degraded), checkpoint arena (transient copy of the dirty pages, <= dirty_hard = 3/8 of the cache), alloc bitmaps (4 bits per 4 KiB block of the device), msgr/net buffers.
`dump_mempools` reports every consumer: classic pool names where one exists (`osd_pglog` items+bytes, `buffer_anon` = parked op bytes, `osdmap`) plus `nvme_tree_pages`, `nvme_point_cache`, `nvme_delta_chains`, `nvme_alloc_bitmaps`, `nvme_ckpt_arena`, `nvme_free_lists`, `nvme_wal_units`, and `process` (VmRSS/VmHWM/RssAnon from /proc/self/status).
Review (2026-10-12): (a) touch logs: first fix shrank a clean page's log to 128 B (`shrink_to`); every re-dirtied leaf then reallocated its log on the write path (adr 0006) and the accounting walked the whole slab. Now clean and free pages hold NO log buffer: a leaf that starts tracking takes a `psz/4` buffer from a per-tree pool (`Tree::touch_room`), freeze/settle/retire/evict return it (`touch_release`; pool <= `cache_pages/8` buffers, rest freed). Durability: the log is cleared at exactly the same points as before (freeze image written / delta entry built / page dropped), its content is never altered, capacity is never read by the delta logic; proven by `tests/delta.rs::redirtied_leaves_with_pooled_touch_logs_survive_crashes` (same leaves dirty -> delta/image -> dirty again under crashes; catches a dropped log, checked by mutation) + soak. (b) `dump_mempools` work on a data core is O(1)/O(sample): `Tree::mem` from counters (`touch_bytes`, free list), `PointCache` keeps a running heap estimate, `IndexedLog::mem_bytes` samples <= 32 entries/dups; debug builds assert the counters against a full walk. (c) `for_memory` floor: 4096 pages per shard wins below ~38 MiB per shard: at the minimum target (budget = `osd_memory_cache_min` 128 MiB) a 32-shard OSD sizes ~1.2 GiB of caches (pages 1 GiB + point cache + delta cap), i.e. small targets are not honoured on big (32-shard) devices; kept (txn page budget = half the cache), documented in doc/ops/deploy.md.

## Amendment 2 (2026-10-19): the target also carries the ingress pools
`caches = target - osd_memory_base - ingress` (ingress = max(target/16, 256 MiB), client + peer pools); adr 0175-memory-envelope, doc/design/memory-envelope.md. Point 3 ("we do not enforce RSS") stays for hugepage/net memory; the ingress share is enforced.

## Amendment 3 (2026-11-04): the tree page budget follows demand across the device's shards
Context: the even split (point 1) left a hot omap object's shard with 1/shards of the tree page budget while idle shards held theirs unused: on the 6-shard e9455 OSD one hot object's shard cached ~9 % of its leaves (86 % of deletes, 74 % of merges missed). BlueStore runs one block cache per OSD, so its hot collection uses all of it.
Decision:
1. `for_memory` still sizes every shard's share (`cache_pages`); the shares of one device form one budget (`store::pagepool::PagePool`, one per process in the daemon: `osd::nvmestore` static, like the run pool and the device idle table). A shard joins at mount with its share as credits and holds `cap` of them: the budget its CLOCK evicts to (`Tree::set_cap`). Credits move only through the pool's atomic free count, so `sum(caps) + free = sum(shares)`: the device total never grows, memory stays at the even split's maximum.
2. The exchange approximates one CLOCK over all pages of the device (BlueStore's single cache): budget moves from a shard whose hand turns slowly (its evictions are older pages) to the shard whose hand turns fastest, until the paces match. Per store sweep (`SWEEP_NS` = 1 ms, the existing cadence at which a store visits every shard, idle ones included; a deep-idle core sleeps at most that long) each shard on its own core, between operations: want = point page loads since the last exchange + pages over cap, while full (granularity = its misses: one exchange grows it as a cache with free room grows); hand period = interval x slots / hand steps. A shard that wants nothing or is slower than the fastest short shard gives, up to the others' outstanding want less the free count and never below its floor, first its unfilled cap, then the pages its hand evicts when advanced at the fastest shard's pace (`Tree::age`, same protections as eviction). The fastest short shard takes up to its want from the free count. Lock-free: per-shard slots (want, period) written only by their core, one atomic free count; no hot-path work (the exchange reads n slots per ms).
3. Floor = `obj::MIN_CACHE_PAGES` (4096, the point 1 minimum: txn budget is half the cache), at most the share. The txn page budget, protect window, walk bound and readahead stay derived from the share (`ShardCfg::cache_pages`), so a shard's write path behaves as before at any cap.
4. Free slab slots keep page buffers up to `tree::buffer_mark(cap)` = cap + cap/32 (the bounded overshoot `Shard::poll` already allows before it shrinks); `Tree::set_cap` releases the buffers above it (adr 0633 open question 2: a shrunk tree gives its memory back to the data cache). The data cache lends `cap - held buffers` (adr 0633 point 1).
5. A shard leaving holding less than its share leaves the pool in debt; shards above their share repay it at their next exchange. Soft (adr 0175): pages that cannot be evicted (dirty, in flight, pinned) may hold a tree over its cap as before; no op waits for credits.
6. `perf dump` per store logger: `tree_cache_cap_pages` (gauge, sum over the core's shards), `tree_cache_taken_pages`, `tree_cache_given_pages`, `tree_cache_aged_pages`, `tree_hand_steps` (counters).
Consequences: + a hot shard holds up to `shards x share - (shards-1) x floor` pages (store test `tests/pagepool.rs`: 4 shards, a working set of ~19k pages at 8192 per share: last-pass loads per key 0.69 even split -> 0.00 pooled); + equally hot shards stay even; + an eviction costs no more on the grown cache (the protect window and dirty pages the hand skips stay the share's size); - like one shared cache, a thrashing shard (working set above the device budget) also evicts other shards' pages reused more slowly than its hand turns; - a cooled formerly hot shard keeps its newest share/2 loads protected (install-order protect window) until it loads again, then ages them at the hot shard's pace.
Alternatives: split by miss counts (rejected: misses of a thrashing shard grow without bound, a shard whose set fits shows none, no equilibrium); ghost lists / utility-curve partitioning (rejected: more per-page state and a second structure for what one hand pace comparison gives); one shared slab across cores (rejected: locks or cross-core page ownership on the hot path, adr 0006).
Tests: `store::pagepool` unit tests (hot shard grows to most of the budget, cold shards shrink to the floor, recovery when the hot shard cools, debt repaid, conservation under concurrent exchanges, a faster-reused set kept against a thrashing shard); `tests/pagepool.rs` (misses drop on a store; CLOCK steps per eviction do not grow with the cache). Lab A/B: `lab/baremetal/omap-c1-ab.sh` (omap phase-1 cells at QD1, main vs fix; marks cells whose client connection placement differs between the arms). Measurements: doc/perf/tree-cache-demand-20261104.md.

## Amendment 4 (2026-11-08): no silent no-effect options
Decision: point 4 options and the other op-queue inputs croit-flashstore-osd has no mechanism for (`config::NO_EFFECT`: `osd_mclock_profile`, `osd_op_queue_cut_off`, `osd_op_num_shards`, `osd_op_num_threads_per_shard`, `osd_client_op_priority`, `osd_recovery_max_single_start`, `osd_snap_trim_priority`, `osd_snap_trim_cost`, `ms_crc_header`, `osd_skip_data_digest`) stay shown by `config get/show/diff`; a non-default value from any source logs one `WARNING config: <name> = <value> has no effect on croit-flashstore-osd: <why>` line (log + cluster log, control core, once per value). The reporting observer tracks no option, so startup options keep classic's runtime refusal. `osd_skip_data_digest` reports `true` (what the daemon does, spec client-ops.md 7.4 D1). Classic-runtime options with a contained mechanism are honoured instead: `osd_deep_scrub_stride`, `osd_deep_scrub_keys`, `osd_backfill_scan_min/_max`, `osd_map_cache_size`, `osd_map_share_max_epochs` (with `osd_map_message_max`, newest epochs kept), `osd_fast_shutdown` (false = always tell the mon). `osd_recovery_op_priority` is honoured like classic: with `osd_op_queue` other than `mclock_scheduler` it (or a positive pool `recovery_op_priority`) is the header priority of the recovery messages this OSD sends; under mclock the recovery state classes apply (spec replication.md 6.1). Client-vs-recovery shares under load stay open (doc/90-open-questions.md OQ 164).
Rationale: an option that `config get` reports but that changes nothing misleads the operator tuning latency or recovery; a warning costs nothing on the hot path.
Tests: osd `config::tests::no_effect_options_warn_once_per_non_default_value`, `tellx::honoured_options_reach_every_core_and_no_effect_options_warn`, `core_tests::full_shutdown_always_notifies_the_mon`, `pgs::map_share_tests`; peering `backfill_scan_digest_follows_osd_backfill_scan_max`, `tests/old_maps.rs::map_cache_size_sets_the_epochs_kept_in_memory`; storeadapt `tests/scrub.rs::deep_scrub_stride_sets_the_read_size`, `tests/omap_push.rs::deep_scrub_keys_sets_the_omap_page`.
