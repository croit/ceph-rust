# 0082 Parked store transactions: phase A shard FIFO
Status: accepted, amended (am. 1, am. 2, am. 3, am. 4)
Date: 2026-10-13
Context: Performance review finding 1. Cold staging, allocation pressure and WAL admission previously waited inside Store::queue, preventing the owning core from polling network, mesh and its other store shards. The decided phase A contract retains strict shard-wide order; collection lanes are deferred.

Decision:
- Each shard has one FIFO. Only its head may translate, stage and submit. Miss/Busy/WalFull/allocation pressure retains the transaction and returns Pending(token); later queue calls append without staging. Tokens are distinct from LSNs: only successful Shard::submit assigns an LSN and changes tree/WAL state. Retain a prepared transaction across submission backpressure; release its reservations exactly once on rejection/timeout/device error.
- Retain adapter input only on the parked path, including Bytes owners and the accepted compression settings. The store owns its builder, so shared-store metadata commits can drain it without an adapter callback or a second owner map. Stage/build read sessions and nonblocking flags are isolated from the client executor and its retained copy reads.
- Fence canonical source and destination object names of pending input. Before translation identifies names, fence the PG and temp collections. Nonblocking reads/stages return WouldBlock through take_blocked; a visibility fence counts as progress for the executor fallback budget. Offline blocking reads drain the FIFO. Already submitted writes retain their existing durability fence.
- Retry after device completion, allocator free-space movement or retained-read release, at most eight attempts per poll and a 100 us budget checked between attempts. No device wait on normal queue/parked retries. The head's own reads (stage/build sessions) never wait for a retained-read session slot (am. 3). A head without progress of its own for 30 s (`Store::head_progress`: where it stops, its own reads, the pages it waits for, CPU-sliced preparation, durable LSN, free blocks, run memory; never other requests' reads) completes its token with an IO error on its next try (am. 3). Queue limits are 128 retained transactions and 1 GiB payload/encoded metadata per shard; one prepared head has a separate 1 GiB limit. Allocation overhead, caches, transport buffers and already submitted IO are outside these limits.
- Admission stops before the hard limits, reserving eight entries and 768 MiB at the default byte limit (a maximum 512 MiB messenger frame plus metadata/continuation headroom). Pause client/replica transport input and executor/replica retries; temporary capacity pressure cannot use the cold-read forced fallback. Held replica replay yields after a persist, and the driver rechecks capacity between batches; PG lease/control timers continue without starting another apply batch. Kernel TCP retains provided-buffer leases and cancels/rearms only affected receives; own TCP retains socket input; mesh retains its bounded inbox. Store completions, other shards and output continue. Heartbeat/monitor links remain exempt from application admission.
- No shard write gate (am. 2): a write (client, copy chunk, replica apply) whose PG and objects no parked txn names queues behind the shard's parked txns; only a big txn's exact size pre-flight waits for an empty FIFO, refused non-blocking (`WriteErr::Blocked`, adr 0021 am. 77). A received copy reply waits in its existing pending slot while its PG log head is not ready, and registers for store wakeups even without an outstanding chunk write. Resume committed replica replay from its completion event; capacity-paused replay has no immediate retry timer.
- Structural operations, migration/placement and shared metadata commits drain earlier queued transactions before changing state. The first actually compressed transaction is a FIFO feature barrier: earlier submissions finish before the existing superblock update; later FIFO entries remain fenced. Persist FEAT_COMPRESSION before submitting compressed data. Keep the existing cold blocking feature/superblock path and failure fallback.
- Durable completion remains the existing WAL commit path. A queued no-op waits for the durable prefix. Deferred errors report the original token before applying a later entry in that poll; generic store callers may handle the error and poll again. The PG adapter retains ADR 0066 fail-stop, since its actor log has already advanced. Never ack a failed/parked transaction. A parked transaction has no replay record.
- Do not run namespace compaction or defrag between preparation and submission of a parked head. Ordinary WAL/checkpoint/reader-epoch progress continues. On-disk, WAL, replay and wire encodings are unchanged.

Consequences: cold writes yield the core; shard FIFO intentionally holds later transactions on other PGs of that shard. Retaining one prepared head bounds repeated copies during WAL/device backpressure. Cold structural and feature barriers can still wait; a poll time budget cannot interrupt a single large CPU staging operation. Deadline failure is fail-stop in the OSD. Hardware throughput qualification is outside this local-only change.

Alternatives: per-collection lanes (phase B, not authorized); adapter-owned callbacks (shared metadata barriers cannot drive them); restage on every poll (repeated copies/reservations and core spin).

Validation: parked FIFO/LSN/read fencing, independent shard progress, caps, WAL/allocation pressure, errors and timeout cleanup, collection/shared-store barriers, no-op completion order, executor admission, kernel receive pause/resume, every-event parked crash matrix. Required full affected debug suites and release staging soaks are recorded with measurements in `perf/codex-perf-2026-10-13.md`.

Amendment 1 (2026-10-13, review): the hard count/byte cap never refuses a PG adapter txn. Admission headroom does not bound one admitted event (an osdmap from the exempt mon link persists every PG of a shard); a refusal is ADR 0066 fail-stop. On `WouldBlock` from the cap the adapter drains the FIFO as a cold barrier and queues once more. Regression: `storeadapt/tests/parked.rs::full_shard_fifo_blocks_instead_of_rejecting_a_logged_pg_txn`.

Amendment 2 (2026-11-02, w4m-gap): the shard write gate (a PG log-head probe refused while the shard FIFO held any txn) is removed. It guarded the size pre-flight from draining the FIFO on the PG core, which adr 0021 am. 77 made non-blocking; since every txn > 256 KiB parks, it held each write and replica apply of every PG of a busy shard and released them one per empty-FIFO instant in probe-per-wake order, the dominant 4 MiB write tail (doc/perf/w4m-gap-20261102.md). Same-PG / same-object order stays with the visibility fences. Regression: `storeadapt/tests/parked.rs::writes_of_other_pgs_queue_behind_a_pending_shard_fifo`.

Amendment 3 (2026-11-02, omap-held-stall): (a) the FIFO head's own reads are exempt from the shard's rolling-read session cap (`ROLLING_READS` = 4 request sessions; the head adds at most its two sessions): executor requests keep their completed rolling reads while they wait at the visibility fence for the head, so four of them (lab case 36, `ceph_test_rados` with omap on rep3) held every slot and the head's read-modify-write read was refused forever (375k refusals in 300 s); replica writes held behind it timed out in peering (`replica write wait for store loads`). Scrub media reads get their own session namespace (`MEDIA_SESSION`; they shared the stage namespace). (b) The stall deadline runs from the head's first blocked try and restarts only on its own progress; it restarted on every try after any store progress, so a head livelocked by other requests' read churn never failed. Diagnostics: `tell dump_pgs` per PG `held_head`, store_diag `head[blocked=<tries> at=<phase>:<cause> stalled_since=..]`. Evidence: doc/perf/omap-held-stall-20261102.md. Regressions: `store/tests/obj.rs::fifo_head_read_is_admitted_while_fenced_requests_hold_every_slot`, `::parked_head_without_own_progress_fails_despite_unrelated_reads`.

Amendment 4 (2026-11-03, e9455 tails F4): a PG's own parked txn fences its pgmeta, so the log-head probe (`warm_log`) refuses every write of that PG until the txn submits; the refusal names no wake token and every FIFO pop wakes all. The client gate scan (`opexec::Engine::retry`) probes the log head once per scan: after a write's probe found it not ready (`Cold::Log`: pgmeta page, this PG's parked txn or admission), the scan's later writes stay unprobed and unnamed (probed on the next wake) and do not count against the probe bound; reads still probe and run. Was: up to `RETRY_PROBES` (64) refused log probes per PG on every wake and every op arrival, enough to saturate the most loaded core under a closed-loop load and pile the in-flight ops there (doc/perf/e9455-tails-20261103.md F4). Replica / EC shard applies probe only the held head of a PG (adr 0021 am. 25): not affected. Regression: `opexec/tests/wake.rs::a_cold_log_head_costs_one_probe_per_scan`.
