# 0096 Bounded messenger and packet descriptor work

Status: accepted
Date: 2026-10-14
Context: performance audit F06–F10. Lossless messenger receive encoded standalone acknowledgements before the application could queue a reply. CRC receive copied large fragments and reread them for their checksum. Packet and messenger segment descriptors allocated on ordinary output/receive. The eight-flow GRO table evicted round-robin traffic before its next packet could merge.

Decision:
- Encode queued messages and owed messenger ACKs when the transport polls output. After receive processing, notify output readiness without encoding the ACK. `has_output`, late output registration and the existing readiness recovery sweep recognize queued messages and owed ACKs. A response queued before that poll piggybacks the received sequence; one-way input still wakes output and gets its ACK without a timer or additional receive. Authentication, transport ordering, replay retention and negotiated wire formats are unchanged.
- On x86-64, CRC receive appends of at least 32 KiB use the existing fused copy/CRC kernel. First checksum any pending small prefix, then continue from that seed while copying the new fragment. Smaller fragments retain the existing batching; other architectures retain it too, since their current copy/CRC implementation uses separate passes. No checksum is omitted. Transport direct receive keeps its existing checksum validation.
- For a known large secure frame in a Ready connection, cancel multishot receive before lending the existing initialized BytesMut allocation to the transport. The owned SecureRxBuffer exposes only the exact remaining frame slice and a bounded commit. The decoder retains its parsed preamble and GCM state while the connection slot owns the allocation; it cannot parse the placeholder or authenticate a preamble twice. Receive in bounded 256 KiB single-shot pieces with receive flags zero, preserving pause/resume and keeping the allocation alive until the final completion. Both CRC and secure direct receive refresh activity after every positive completion through a Ready/owned-session-gated progress hook, without authentication, dispatch or nonce advancement. MSG_WAITALL would hide continuously arriving bytes until the requested piece fills and could incorrectly expire a slow live stream. Silent partial peers still expire. Return only a complete matching allocation, then authenticate every remaining tag through the existing decoder before any delivery. A failed, superseded or closed connection cannot dispatch a late loan. No provided-ring memory is retained and no scatter decrypt or new nonce region is introduced. Small/unknown secure frames retain their existing paths.
- Use safe SmallVec payload descriptors: one inline chunk per TCP/GSO frame. Fragmented packet payloads spill normally; no fragment-count limit or payload coalescing copy is introduced. Payload ownership and retransmission references remain unchanged. This changes internal Rust field types, not wire bytes. The lockfile pins smallvec 1.16.3.
- Preallocate 64 GRO flow slots, enough for the current production NIC receive burst. Each socket slab slot stores the index of its active run. Swap removal clears the removed index and repairs the moved one; killing a socket discards its pending run before slot reuse. Larger bursts retain bounded eviction. Independent flows may be delivered in a different order within a burst; each TCP stream retains its order. Runs still flush at burst end or when a nonmergeable same-flow packet arrives. No latency-extending cross-burst aggregation is introduced.

Validation: pending ACK/reply regression checks a single CRC response carrying the ACK, late queue registration, readiness recovery and one-way ACK delivery. Secure response length and authenticated delivery prove the separate 96-byte ACK region is absent. Mixed short/large CRC feeds verify every payload byte and corruption rejection. Descriptor tests exercise inline and spilled gather storage, original payload pointers and retransmit gathering. Messenger segment vectors remain Vec: a measured four-inline-Bytes variant reduced allocations but regressed small-frame CPU cost, so it was reverted. GRO tests cover 9/32/64/65 interleaved flows, merged-run counts, exact stream bytes, index cleanup and socket-generation reuse. Existing captured/frozen frames, reconnect replay, CRC/secure framing, loss/reorder/duplicate simulations and software/hardware TSO tests remain required.

Secure-loan validation includes both messenger revisions, inline and extended headers, pointer retention, partial receive commits, retained plaintext immutability, following-frame nonce progression, tag failures, incomplete/foreign loans, concurrent-feed rejection and late completion after a fault. A short-idle regression exercises positive partial-loan progress for CRC and secure modes, verifies no early delivery or nonce advancement, then verifies silent expiry. Kernel-tier loopback tests cover paused loans, the next frame and partial EOF with a subsequent healthy connection. Emulated Linux/x86_64 direct CRC and secure-loan suites also pass; this establishes x86 branch correctness, not hardware performance.

Limits: these changes eliminate specific redundant work; they do not establish production throughput or latency improvements. Large known secure frames remove transport staging after the copied prefix when kernel direct receive is enabled. DPDK/AF_XDP, small secure frames, unparsed prefixes and forwarded raw streams retain their staging copies. A single-shot secure loan initializes newly grown storage as before; removing that clear needs a separate proof. Segment payload buffers still allocate; inline descriptors do not constitute a total allocation-free or RSS-bounded network path. Real DPDK NIC behavior and Ceph mixed-cluster performance require hardware qualification.

Performance decision: identical native ARM fixtures against baseline ccb3230a use release LTO=fat/codegen-units=1, warmed workloads and alternating samples. Four inline messenger segments measured 4→3 allocations but 307→334 ns per 4 KiB frame (seven samples, 200,000 frames each), so that change is excluded. Packet descriptors retain a one-inline-chunk representation: measured TCP output allocations fall 8,000→0 for 8,000 packets, software GSO 10,000→0. A separate uninstrumented five-sample/80,000-packet probe measured median 176→178 ns TCP and 132→132 ns software GSO; no CPU speedup is established. Exact ACK bytes and merged-flow counts improve; all local/emulated timings and hardware limits are recorded in the performance evidence, not treated as production qualification.

Secure ingress work-count experiment (real Linux loopback, current binary with direct receive disabled vs enabled, final receive flags zero): eight 1 MiB frames copy 8,390,016→1,024 bytes through Decoder.feed, with receive CQEs 145→92. Eight 4 MiB frames copy 33,555,840→1,024 bytes, with CQEs 531→239. The client deliberately separates each 128-byte prefix and coordinates frame discovery/loan, so this measures an exposed large-frame path, not typical production prefix sizes. Loan mode receives remaining ciphertext directly into initialized decoder storage. Both runs authenticate and check every payload; wall timing includes polling-client coordination and establishes no general latency, CPU or interrupt improvement. Earlier MSG_WAITALL CQE counts are superseded; final raw evidence and validation are in doc/perf/probes/runtime-results.txt.
