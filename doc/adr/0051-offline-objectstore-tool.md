# 0051 Offline object store tool: `croit-flashstore-tool objectstore`, classic PG export format
Status: accepted
Date: 2026-10-11
Context: operators recover with `ceph-objectstore-tool` (incomplete PGs, moving a PG, repairing a damaged object, replacing a map). It cannot open an croit-flashstore-osd store; clusters of only croit-flashstore-osd (adr 0013) need the same capability, and mixed clusters need PGs to move between classic and croit-flashstore-osd OSDs.
Decision:
- New crate `ostool` (generic over the device, tested on SimDisk), thin CLI `croit-flashstore-tool objectstore` (`--dev | --id | --data-path`). Classic option and op names; behaviour per doc/spec/objectstore-tool.md; operator guide doc/ops/objectstore-tool.md. Offline only: the store is opened exclusively (WAL replay at mount); a running OSD is refused (admin socket for `--id`; `file:` devices `flock`ed by `AnyCtrl::open_exclusive`, now also used by the daemon and `fsck`; `spdk:` devices: SPDK's own PCI claim lock is taken in `SpdkCtrlr::attach_pci` BEFORE DPDK maps the device (nvme::pcilock): on uio hosts a losing second SPDK process otherwise clears bus mastering of the owner's device on exit, verified on the lab VM; vfio alone would refuse, uio does not). Export files are fsynced before `Export successful` / `export-remove`.
- PG export/import use the CLASSIC container byte for byte (version 2: super header, sections, `pg_begin`, metadata with the OSDMap at the PG epoch, objects with data/attrs/omap). Verified with the real tool both ways (lab/docker/ostool/interop.sh).
- No private store access: PG state is read with `storeadapt::meta::load` and written with `PgStoreOps` ops (`PutInfo`, `LogAppend`, `Missing`, `SnapMap`, ...), objects with ordinary `OTxn`s, so the daemon's own invariants and key formats cannot diverge. The SnapMapper is rebuilt from each head's SnapSet (not part of the export).
- Crash safety of import: collection + `_remove` marker first (the PG is garbage to every reader and swept at mount), objects in batches, PG state, last atomic txn writes `_info` and deletes the marker. Failure -> the tool removes the PG again.
- Safety rules: mutations only by naming the op; `remove` needs `--force` (or use `export-remove`), `reset-last-complete` needs `--force`, new map epochs need `--force`, `--dry-run` everywhere a mutation exists; tool txns are system class (work on a full device); checkpoint after mutations.
- Out of scope (documented, fail loudly): BlueStore specific ops (mkfs, repair, fuse, dup), pool exports, pre-nautilus exports, (`update-mon-db` refused with the alternatives, see am. 1).
Consequences: + DR parity for the common cases; a PG can be rescued from/to classic OSDs; no new on-disk format. - import split/merge clash check uses only pg_num at export vs now (no per-change history); JSON key order differs (alphabetical).
Alternatives: link the classic tool against croit-flashstore-osd (license, huge); reuse the daemon with a `--maintenance` mode (needs the network stack); fuse-style mount (not needed).

## Amendment 1 (WP-O): object surgery, list-slow-omap, update-mon-db
- Implemented from the classic semantics (spec sec 4, 8, 9): `set-size` (+`corrupt-size`), `clear-data-digest`, `clear-snapset` (variants), `remove-clone-metadata`, `list-slow-omap`. Each mutation is one store txn (attrs + truncate together), `--dry-run` supported, system class, checkpoint after. No `--force` (classic has none), except `remove-clone-metadata` (incomplete clone metadata). Deviations (improvements): variant of `clear-snapset` optional; `remove-clone-metadata` also drops `clone_snaps[id]` (a stale entry would look like an inconsistent SnapSet to scrub).
- `list-slow-omap`: the B-tree omap has no tombstone slowness; the op measures for real and normally returns empty.
- `update-mon-db`: REFUSED. The classic op fills a RocksDB mon store; croit-flashstore-osd has no RocksDB (adr 0021) and linking one for an operator DR path is not KISS. The refusal names what the store can give (`dump-super`, `get-osdmap`/`get-inc-osdmap`, keyring). Mons are classic (charter), so a mon rebuild uses classic tooling; if it ever becomes a real need: `--op dump-maps DIR` (every full + inc map as files) plus a mon-side import, or a pure Rust RocksDB-format writer (large).
