# 0461 E2E harness: throwaway QEMU/KVM clusters on CI runners
Status: accepted
Status note: Partly superseded by adr/0682-remove-afxdp-dpdk-networking.md (2026-11-06): AF_XDP/DPDK e2e cells is history; the rest stays valid.
Date: 2026-10-19
Context: functional suites (lab/docker/*) run on a few long-lived shared lab VMs (one agent per lab, manual redeploy), croit-flashstore-osd there runs the lab tier (FileDev, kernel-probe/knet); the production path (SPDK store, vfio, systemd units, prep, knet/AF_XDP after adr 0005 am. 2) is exercised only on bare metal. No CI. User 2026-10-19: CI runners are large and support nested virtualization; wants a modern multi-node e2e setup.
Decision:
- `lab/e2e/`: one run = fresh cluster of QEMU/KVM VMs on one runner (bash + jq, no Python, no cephadm/teuthology/k8s), scenarios, results, teardown. Declarative topology files (`topo/*.sh`: roles mon|croit-flashstore-osd|classic per VM), scenarios (`scenario/*.sh`), network tier per run (`-n knet|afxdp`) = the sibling cells of AGENTS.md as a CI matrix.
- Images (`lab/e2e/image/docker-bake.hcl`, croit's shared buildkit daemons, as croit.io/application): dev (lab/devcontainer, DPDK + SPDK; layers also cached in the registry), prod binaries (build host profile `prod` cargo lines, in dev, cargo target + registry as daemon cache mounts), host (runner image: QEMU & co. + buildx; e2e job image), node-disk (guest: pinned Ceph image userspace with native Ceph + sshd + croit-flashstore-osd units/prep of `lab/deploy/systemd` + Debian trixie kernel/initrd -> ext4 -> qcow2). Nothing is installed or provisioned at job or boot time; base images pinned by digest; node image fetched once per content hash per runner host (runner cache).
- Guest boot: direct kernel boot of the node image, per-run qcow2 overlays, per-VM identity via QEMU fw_cfg (hostname, NICs by MAC, addresses, ssh key; `e2e-node.service`), no cloud-init.
- Production path inside the VMs: `prod` binaries (CI artifact, or `--sha` from the build host), q35 + intel-iommu, emulated NVMe (4K LBA) -> vfio-pci via `croit-flashstore-prep@`, `croit-flashstore-tool prepare`, `croit-flashstore-osd@` as user ceph (Type=notify, enabled: comes back at boot). Unit files and prep script are the ones in `lab/deploy/systemd` (no copies). Classic mon/mgr/OSD = Ceph's own `ceph-mon@`/`ceph-mgr@`/`ceph-osd@` units of the pinned image (user ceph), BlueStore on a real (emulated) block device.
- Isolation: per-run bridge without uplink (TEST-NET-2), taps, per-run ssh key, slirp mgmt with loopback-only hostfwd; parallel runs on one runner share only the node image cache (flock). Root/sudo only for bridge/taps (+ an iptables ACCEPT for the own bridge when br_netfilter is loaded, removed at teardown). Processes are stopped by exact PID with run-id-checked cmdline; VMs live in run.sh's process group.
- Fault model v1: QEMU SIGKILL = node power loss with PLP semantics (completed device writes survive). Checker v1 = `guest/objio.sh` (acked-write log with sha256, read-back) + deep-scrub inconsistency check. QEMU reports VWC -> `--allow-vwc` (FUA path, lab only, adr 0008).
- Results: results.jsonl per check, junit.xml, summary.json (stable fields, README), loud timeouts (tmo.sh contract, count in summary), evidence bundle per FAIL. Exit 0/1/2/3, 130 interrupted (an unfinished run never passes). Offline selftest `lab/e2e/selftest.sh`.
- CI (`.gitlab-ci.yml`): pipelines only on schedule/web/api with `E2E=1` or on MRs (build manual there); instance runner tag `docker` (privileged containers with /dev/kvm, the fleet croit.io/application runs its QEMU e2e on); jobs: build (bake dev host prod node-disk) -> selftest + e2e matrix {nv3, mixed} x {knet, afxdp} in the host image.
Evidence: first live CI run 2026-10-19 (`docker` runner, nested KVM): {nv3, mixed} x {knet, afxdp}, smoke + powercut, all pass (36/37 checks per cell, 0 timeouts, every acked write read back intact after the power cut); SPDK runs unmodified on the emulated NVMe via vfio-pci under intel-iommu; AF_XDP runs on virtio-net in the guest.
Consequences: + every MR can get a production-path multi-node gate in ~30 min without shared lab state; + power-loss tests of the SPDK store become routine; + the docker suites stay (fast lab tier, kernel-probe/FileDev). - emulated NVMe/virtio = functional, not performance (bare metal stays the perf tier); - PLP-less (volatile cache loss) and network partition faults not yet modelled; - the node image is ~1 GB per content hash per runner host (fetched from the buildkit daemons).
Alternatives: teuthology (Python, own infra, cephadm-based install), cephadm/Rook-on-kind (excluded: no cephadm, no k8s; both assume ceph-osd + kernel net), NixOS VM tests (Python driver, Nix), Firecracker/Cloud Hypervisor (no emulated NVMe controller -> no SPDK path), testcontainers-rs (container tier only, which bash already covers), multicast/VDE socket networking (unprivileged but no fault injection, loopback multicast fragile).
Backlog (90-open-questions): Rust history checker (linearizability per object, Jepsen-style) replacing objio.sh; network faults (QMP `set_link`, tc netem on taps); docker provider behind the same topology/scenario interface (port `lab/docker/mixed` cases); classic-node power cut; SPDK vfio-user target for device-level fault injection (error/delay bdev, VWC=0); aarch64 runners (virt + SMMUv3); deterministic simulation of peering/recovery (separate ADR).
