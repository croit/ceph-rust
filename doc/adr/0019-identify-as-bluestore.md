# 0019 Metadata: report osd_objectstore=bluestore
Status: accepted
Date: 2026-10-09
Context: mon gates features on OSD metadata `osd_objectstore == "bluestore"` (e.g. allow_ec_overwrites: OSDMonitor is_pool_currently_all_bluestore); mgr modules (prometheus, telemetry) branch on it. Classic sends no osd_type.
Upstream TODO: upstream-todos.md A1-A3. Decision: MOSDBoot metadata reports `osd_objectstore=bluestore`, no `osd_type` key (classic omits it; mon logs an error for any non-crimson value; am. 2026-10-13), device class nvme keys (bluestore_bdev_dev_node only, read by mgr prometheus; other bluefs/bluestore_bdev_* keys dropped 2026-10-12). Identify ourselves via extra keys `flashstore_version`, `flashstore_build`. Feature bits (osd_features, msgr features) = same as classic ceph-osd of target release.
Consequences: + max compat with mon/mgr/tooling. - operators distinguish via `ceph osd metadata | flashstore_version`.
Reconfirmed 2026-10-12 (user): `bluestore` is a compat value for mon/mgr feature gates, not a product name; keep it. Own identity only via extra metadata keys, logs and docs. A store name of our own (`nvmestore`) only becomes possible together with a mon/mgr patch that treats it like `bluestore`.
Amendment 2026-11-06 (adr 0674): startup option `flashstore_report_objectstore` = `bluestore` (default, unchanged behaviour) or `flashstore` (patched mons only). `flashstore` renames every BlueStore-identity name toward mon/mgr/CLI: `osd_objectstore` metadata and default, `bluestore_bdev_*` -> `flashstore_bdev_*`, perf logger `bluestore` -> `flashstore`, `bluestore ...` tell/asok commands -> `flashstore ...` (renamed, not aliased), `BLUESTORE_*` health codes -> `FLASHSTORE_*`. Ceph config option names (`bluestore_compression_*`, `bluestore_log_op_age`, `bluestore_slow_ops_*`) stay in both modes. Code: services/osd/osd/src/storeid.rs.
