# 0177 rustyrados bounded explicit read retry
Status: accepted
Date: 2026-10-14
Context: next read prototype increment after ADR 0176; implement stable logical identity before mutation retry. Wire facts audited and written in RC-RRETRY before implementation.
Decision: add bounded opt-in explicit read retries with immutable TID/incarnation/context and monotonically checked attempts. Defaults remain one attempt. Retargeting is driver-supplied validated placement; no automatic retry/error classification/backoff or write guarantee. Lab-only explicit reconnect proves same-identity resend with two attempts and one pending request. Contract: RC-RRETRY (doc not in the source snapshot).
Consequences: read engine can preserve identity/credit through loss/remap; old reply cannot complete new attempt. HEAD reads may observe new data on retry. Driver must enforce time/identity/capability policy; unknown mutation outcome and general dedup-retention audit remain open. Historical ADR 0176 single-attempt restriction is superseded only for this opt-in subset.
Alternatives: fresh TID per resend (loses logical identity); automatic unlimited retry (unbounded resource/time policy); writes first (dedup/durable/fence contracts still open).

## Amendment (2026-10-20): native client resends writes with their request id (am. 1)
Context: RDMA fault campaign (doc/perf/rdma-faults-20261020.md): after a lost primary, an OSD restart or a primary change every write in flight ended `PossiblySent`, because `ObjectClient` never resent writes. OSD side verified (xcore tests `resend_tests.rs`, peering `classic_dup_records_merge_and_answer_resends`): croit-flashstore-osd answers a resent write (same client entity, tid, incarnation) from its PG log or dup records (client-ops 5.6, pglog 7.4) after a session reset, a lost reply, a crash restart, a trim into dup records, and on a new primary that got the entry by replication or by peering (backfill log with dups, classic `pg_log_dup_t` decodes); classic OSDs do the same.
Decision: rados-rt `ObjectClient` enables RC-MRETRY mutation retries at construction. Writes (WRITE/WRITEFULL/APPEND, mutation compounds) are redriven exactly like reads: on a recoverable loss of their session and once per new map epoch when their PG's acting primary moved; same request id, ops, input bytes, mtime, snap context and absolute deadline; `retry_attempt` + 1; bounded by `RequestLimits::attempts` (total sends). Control ops (watch/notify) stay excluded. Resends of one target leave in submission order (an older unsent resend of the same object holds the newer one). `PossiblySent` remains only where the outcome is unknown: attempts used up, unrecoverable identity loss, cancel after dispatch; `Deadline { possibly_sent: true }` at the deadline.
Rationale: librados semantics (Objecter resends with the same reqid); the OSD's finite dup history (osd_pg_log_dups_tracked, default 3000 per PG, persisted, carried by peering) makes the resend safe within it.
Consequences: a graceful OSD restart or a lost primary no longer fails writes when attempts > 1. A resend after its PG trimmed the request out of the dup history (> 3000 newer writes of that PG during the outage) is applied again: Ceph's finite-history contract, not exactly-once forever. Default attempts stays 1 (no resend of reads or writes); callers opt in with `attempts`.
Open questions: default attempt budget of the C ABI (resolved in am. 2).

## Amendment (2026-10-20): C ABI resends like librados, until rados_osd_op_timeout (am. 2)
Context: user decision "100% Ceph compatible". librados resends reads and writes on every session loss and primary move until the op timeout; the C ABI sent once (attempts = 1) and returned errors after an OSD restart.
Decision: rados-ffi sets `RequestLimits::attempts = rados_rt::UNBOUNDED_ATTEMPTS` (i32::MAX, the largest budget the engine accepts); the op deadline is the only bound. Deadline = `rados_osd_op_timeout` seconds from submission (0 = none, the clock limit), already wired through rados_conf_set / conf file / env; the result at the deadline is -ETIMEDOUT. Resends stay once per session loss / per primary-moving epoch with unchanged request id and per-object order. Watch/notify unchanged. Native API default stays 1 total send: native callers choose their budget and deadline explicitly (library tools, tests, lab fault injection rely on deterministic single sends); `RequestLimits { attempts: UNBOUNDED_ATTEMPTS, .. }` gives the librados behaviour. Contract: RC-MRETRY (22-mutation-retry.md).
Rationale: wire/app compatibility is mandatory for the C ABI (adr 0256); native default is policy, not ABI.
Consequences: a resend after the dup history trimmed the request applies a write again (finite-history contract, am. 1). A dead PG with timeout 0 blocks the op forever, as in librados.
Open questions: none.

## Amendment (2026-10-21): resend on any new PG interval in any epoch since the send (am. 3)
Context: doc/perf/tcp-loss-20261020.md: the native client compared only the newest map's acting primary with the op's target, once per step. The OSD drops an op older than the PG's primary/split/force-resend epochs without a reply (client-ops 5.2), so a primary that moved and came back between two checks, a pg split, a set change with the same primary, a pool force-resend epoch or a target down/up flap left the op waiting for its deadline: forever in the C ABI without rados_osd_op_timeout. User: an op that can hang forever is a bug even if Ceph had it (adr 0256: no reference bugs).
Decision: RC-MRETRY interval resend rule (22-mutation-retry.md). A sent request is resent when, over every map epoch in (send epoch, newest]: its PG started a new interval (up/acting set or primary, size/min_size, split/merge incl. pg_num_pending, SORTBITWISE/RECOVERY_DELETES, pool gone; a missed epoch counts); its pool's last_force_op_resend > send epoch; or its target OSD is down or has up_from > send epoch. Mechanism: `osdmap::PgWatch` in the monitor client follows the PGs of sent requests (refcounted, tracked at send, released at resend/completion), maps each once per applied epoch (inside one MOSDMap too) and keeps its last interval start; ObjectClient checks one lookup per sent request per new epoch. Request id, attempt accounting, deadline and per-object order unchanged; the target is recomputed from the newest map. Resend causes counted per client (`ObjectClient::resend_counts`: session_loss, interval_change, force_resend, osd_down, backoff, eagain, redirect, plus retired with feature `rdma-placement`; sum = recovery_sends), reported in rdma-bench records (`resends`). The C ABI has no perf dump; nothing exposed there.
Rationale: the per-epoch check is the only way to see transient intervals the newest map hides; following only PGs with sent requests bounds the map-path cost to one CRUSH mapping per followed PG per epoch, nothing on the send path (lazy baseline).
Consequences: resends become a superset of the OSD's drop conditions (any interval change, not only a primary change): a few extra resends answered from the PG log / dup records (writes) or re-read (reads); no hang without a deadline from a dropped op. Watch/notify unchanged.
Open questions: none.
