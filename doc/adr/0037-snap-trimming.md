# 0037 snap trimming (SnapMapper, trimmer, purged_snaps)
Status: accepted, amended (am. 1)
Date: 2026-10-10
Context: removed RBD/CephFS snaps never freed space (no trimmer, mon queue never pruned). Spec: spec/snaptrim.md (own words). Constraints: PG owned by one core, no locks, mixed acting sets with classic OSDs, never crash on inconsistent snap metadata, every PG (incl. empty) must report purged snaps.
Decision:
1. SnapMapper = per-PG index in ONE pgmeta-like object of the PG collection (empty name, snapid SNAPDIR; storeadapt/snapmap.rs). Omap keys in `peering::snaps`: reverse `c|mkey(clone)` -> (hobject, snaps), forward `s|snap BE8|mkey(clone)` -> hobject. mkey = 0|denc(hobject) (<=200 B) else 1|hash|128-bit digest (store key limit). Object is not listed/counted/scrubbed/backfilled; deleted by `remove_pg`; copied by core migration (queued before pgmeta); carved by split (entries of matching hash copied to child, parent copy dropped at the same step as the object copies, idempotent) and merged into the target. `StoreOp::SnapMap(Vec<MapOp>)`, `MapOp::{Set,Remove}` (add == update).
2. Maintenance is explicit in the PG machinery (same StoreTxn as the object change, every replica incl. primary): `append_log` with a txn derives ops from entries (CLONE/PROMOTE/MODIFY/REPLACE with non-empty snaps -> Set, DELETE -> Remove, heads ignored, log-only entries (empty txn / update_log_missing) skipped); push completion of a clone -> Remove + Set from the head SnapSet carried in `recovery_info.ss` (stores fill `ss` of a clone from its HEAD); `RemoveObject` of a clone -> Remove (recovery delete, backfill remove, divergent). Empty snaps on receive: tolerated, old mapping kept.
3. PG side (`peering/snaptrim.rs`): `snap_trimq` = map `removed_snaps_queue[pool]` - `info.purged_snaps`, `purged &= queue`, recomputed (simplified idempotent rule, spec 2.2) at activation and on every map advance of an active primary; purged change -> `share_pg_info`. Gate: primary, active+clean, no PREMERGE, no scrub pending, no NOSNAPTRIM, no error in this epoch. Slot: `osd_max_trimming_pgs` per PgSet (per core: divided like osd_max_scrubs; deviation from the global counter in spec 7.4, no shared atomic), FIFO queue. State bits SNAPTRIM_WAIT/SNAPTRIM/SNAPTRIM_ERROR in pg_stat; `snaptrimq_len`, first 512 intervals of `purged_snaps`, `objects_trimmed`, `snaptrim_duration`. A scrub does not start while the PG trims (retry 10 s); trimmer waits for scrub; any event re-kicks (`Action::SnapTrimKick`). A snap without clones (empty PG) is purged in the same run without a new slot; info shared once per run end.
4. Trim steps (`opexec/trim.rs` planner + `Engine` driver): per spec 5 (two log versions, clone DELETE (snaps = empty set blob) or MODIFY (non-empty), head MODIFY or DELETE of a whiteout head with its last clone, overlap intersect, shrink by ALL queued snaps, seq unchanged). One MOSDRepOp per step, `max_concurrent` steps per round (osd_pg_max_concurrent_snap_trims), pacing `osd_snap_trim_sleep` (ssd variant when 0). Steps pipeline on the object like writes (cached state), bypass client admission (pool-full exempt). Errors (no clone_snaps, empty, seq 0, clone/head missing, not in clones) -> clog error, SNAPTRIM_ERROR, stop, no retry before the next map epoch. Deviation (spec 11 option): mapper entry whose clone object is absent AND not in the head SnapSet is dropped locally and the trim continues.
5. Snap filtering of client writes / snap reads uses queue + pool.removed_snaps (`Env::removed_snaps`).
6. Scrub: each finished chunk (primary and every replica, locally) checks the mapper of the chunk's clones against head SnapSets and repairs silently (clog error). Not a scrub error on the wire.
7. Batched MOSDRepOp (several steps in one repop), mgr-less pruning: not built (`scrub_purged_snaps` + snap_trimq_repeat: built, parity.md) (spec 12 optional). EC pools: PG refuses -> no trimming, no reports.
Consequences: + removed snaps free space on all-croit-flashstore-osd and mixed acting sets; mon queue prunes. + replicas stay consistent without parsing SnapSets. - `osd_max_trimming_pgs` is one OSD-wide budget kept by core 0 (adr 0031 am. 9). - `pg_stat.num_object_clones` still 0 (needs incremental counters). - one repop per clone: rate bounded by repop RTT x concurrency per PG, scale by PGs/cores (batching = future).
Alternatives: mapper keys inside pgmeta omap (rejected: `meta::load` reads all pgmeta omap); mapper derived from log hooks inside the store translator (rejected: cannot tell log-only entries); trimmer in peering (rejected: needs object state cache + write ordering of the op engine).

## Amendment 1 (CS-5566): release the trim slot per snap; a scheduled scrub interleaves between snaps

Decision: `trim_snap_done` releases the trim slot and clears SNAPTRIM after every finished snap (spec snaptrim.md 7.3) instead of staying in the run; the next snap re-reserves through WaitReservation. A scheduled scrub may start while the PG is only in SNAPTRIM_WAIT (between snaps), never while SNAPTRIM; operator scrubs keep the classic deferral under both bits (spec scrub.md 12.1.7). Supersedes decision 3's "a snap without clones is purged in the same run without a new slot".

Rationale: a PG with a long snap trim queue held the OSD-wide trim slot and SNAPTRIM for the whole queue, so a due scrub never started until the queue drained (CS-5566: "PGs in snaptrim never scrub", thousands "not scrubbed in time"). Releasing the slot per snap round-robins the trim budget and lets a due scheduled scrub interleave; classic holds the slot for the whole queue and starves it.
