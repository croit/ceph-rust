# 0043 Read path CPU: async data prefetch, store-derived data crc, no per-op O(PGs)

Status: accepted, amended (am. 14, am. 15, am. 17, am. 18, am. 19, am. 21, am. 22)
Date: 2026-10-10
Consolidated 2026-10-19; full pre-consolidation text: `git show 60868596d:doc/adr/0043-read-path-cpu.md`. Measurements and incidents: doc/perf/adr-0043-history.md (doc not in the source snapshot).

## Context

A read must never block the PG core: one device wait per read caps a core at ~12k IOPS and stalls NIC rx and all other PGs. Per-op work must not scale with PG/engine count, CRUSH runs once per PG per epoch, and large reads must not zero-fill or crc the payload twice. Baseline: history (Origin).

## Decision

### Prefetch (no wire/on-disk change)
- After `Store::warm` (tree pages resident) the op gate probes `Store::warm_data`: committed device runs of the range are read into a per-shard table (`ShardStore::pf`, key = first device block, <= `PF_MAX` 1024 entries / `PF_MAX_BLOCKS` 8192 blocks, split at the transfer limit). `false` = reads in flight; the op parks at the PG gate and a completion wakes it.
- `read_runs_into` consumes ready entries (copy fused with block crc); it falls back to the blocking path only for runs never prefetched (busy queue, partial overlap, write-after-read hazard, unflushed writes of the object, ops > table or > 1024 runs). A full table or full device queue never falls back to a blocking read: the op waits.
- Admission (`pf_admit`) is all-or-nothing in first-denial order (`pf_q`): reserves table entries, table blocks and device queue commands (one per run; `queue_space - keep`, keep = depth/16 min 8 for WAL writes). Waiters expire after 50 ms without re-probe; ops needing more than `depth - keep` commands skip prefetch. A refused submit after admission waits for the next completion. Any completion wakes waiters while the queue is non-empty; freed capacity wakes via `pf_freed`.
- Safety: an entry holds its reader pin (`Shard::reads` epoch) until consumed or expired (`PF_TTL_NS` 200 ms, swept by `Store::poll`); COW data never changes in place; the real read re-resolves extents, so an overwrite just misses. Device error = entry failed (counts as ready; blocking read reports, adr 0042). Token bit 55 (`PF_TOKEN | first block`) marks prefetch reads. Prefetch submits only when the object's newest write is durable.
- Block crcs at completion (am. 14): a run's block crcs (`Pf::crcs`) are computed in `pf_done` when its device read completes, while the core waits for the rest of the op's commands; `pf_serve` takes them over (shared pieces: no pass at all; copied pieces: plain copy). The same blocks verify against the same stored crcs. Rolling reads already did this at completion (`rolling_done`). Numbers: history.
- Tail blocks (am. 19): the last block of a run a txn writes, when it is the partial last block of its object, enters the data cache at submit (`Txn::tails`, `ShardStore::tail_blocks` / `cache_tails`: a 4 KiB copy, its block crc comes from the staging pass). The next APPEND (or any partial write at the end) onto it hits `Engine::cold`'s `warm_data(size, 1)` in the cache: no device read, no park. Validity is the data cache's (COW, `forget_freed` at every free); durability gating is unchanged (`wlsn_pending`). Replicas and EC shards stage the same way. Numbers: history.
- Data cache (am. 15): a run that served a read whole leaves the table (its reader pin goes) and moves into the shard's data cache (`ShardStore::dc`, `obj/datacache.rs`; `ShardCfg::pf_retain`, config `flashstore_store_pf_retain`, default on): bytes (shared, no copy) + block crcs, keyed by device block, disjoint runs. No pin and no expiry: committed data is never written in place, so the bytes at an address change only after a free, and every txn submit drops the freed ranges first (`ShardStore::forget_freed`, with the decompressed-chunk cache, before the allocator can reuse them; prefetch runs still out are marked `freed` and never cached). Probes (`pf_state`, `warm_data`, the non-blocking read check) count cached ranges as ready; reads serve them first (`serve_ready`: a whole run or a block slice by reference, crcs known). Capacity, memory and eviction: adr 0633-data-cache-envelope (shared floor `PF_MAX_BLOCKS` per shard plus the unallocated tree page budget; segmented LRU); an admission evicts cache blocks first, so the cache never denies a prefetch. Media (scrub) reads bypass it. Compressed chunks are cached once, decoded, by the decompressed-chunk cache (adr 0059 am. 5): a prefetched chunk consumed in place (`pf_with`) leaves no physical copy here. `perf dump` (store section): `data_cache_blocks`, `data_cache_cap_blocks`, `data_cache_hits/inserts/evictions/forgets/promotions/demotions`.
- Non-read-only ops probe data too (`Engine::cold`): READ/SPARSE_READ/CMPEXT/CHECKSUM their range (cap 4 MiB), WRITE/ZERO the unaligned head and tail block, TRUNCATE the block of the new size; all probes in one pass; staging serves them from the table. EC pools: no data probes for non-read-only ops (`ec_wait` covers EC reads). `Stage::warm_data` returns `WouldBlock` while the object has committed blocks and `wlsn_pending` (`wl_wait`; next durable advance wakes). `wait_durable` remains the safety net.
- Residual synchronous waits: cls `ov_read`, clone/rollback sources, scrub, WRITESAME, second RMW of the same block in one txn (entries are single use; `eff_read` always reads the committed block).
- Data probe details (`Engine::cold`): head and tail probes `warm_data(off, 1)` / `warm_data(end-1, 1)` (one probe when both fall in one block) are issued in one pass, no short circuit; the op parks until all are in. Interval change/teardown: `reset` re-queues parked ops; orphaned entries expire and release pins. A read refused for durability keeps its gate place; 1 ms sweep is the backstop.
- The data cache saves the device re-read of the EC legacy stash (`clone_range` of the old chunk into the generation object = store copy = read): the primary's stash probe (`ec_own_ready`) and each shard's sub-write (`ec_write_must_wait`) hit it. Every serve passes the reader's check against the stored crcs.
- Prefetch layer is shared by all NVMe backends (`BlockDev` contract incl. the sim device), `shardio` (rolling read + `pf_*` table), `Stage::warm_data`; replicated and EC reads. `Skip` = admission result of ops that never prefetch (above).
- Rolling reads: `rolling_progress` fills the queue-room window greedily, oldest read first; `wtoks` collects the wake tokens of whole reads; `pf_done` pushes the run/batch token on the last completion.
- Fragmented objects (all NVMe backends, rep and EC): a rolling read (more runs than queue room) wakes its op once, when whole (`RollingRead::waiting`), under its own token (`cause_pf(runs[0].pba)`); prefetch commands carry a batch (`Pf::batch`/`pf_batch`), one token pushed by the last completion; `warm_data` returns at once when a rolling read of the same runs exists (`rolling_resumes`). `RollingRead` entries are served oldest first (`Vec::remove`, never `swap_remove`); a release wakes only if a slot waiter was refused (`rolling_wait`); each read keeps `by_pba` (runs sorted by block) for `rolling_covers` binary search.
- Residency leases (am. 18): an op that waits for its loads outside the client gate (held replica write / EC sub-write / sub-read head: `held::LoadWait`; EC primary own-shard stash and read: `EcWrite`/`EcRd::own_lease`) opens a lease at its first cold verdict (`PgStoreOps::lease_open`); its later probes run under it (`lease_use`). The store pins the tree pages they miss (`Tree::pins`, `shrink` skips them) and holds the prefetch runs they find or submit (`Pf::holders`: no TTL expiry, a read by anyone keeps the run; a held ready run counts in `pf_leased`, not against `PF_MAX`/`PF_MAX_BLOCKS`, so a held op never blocks another's admission: no hold-and-wait). Its refused admission keeps its `pf_q` place (never aged out by `PF_WAIT_NS`) and `pf_freed` wakes it. Released on consume (the apply / generate / local read in the same step), when the op ends, at an interval change or merge quiesce (`lease_release_pg`) and at PG removal. Liveness without a time or retry bound (adr 0021 am. 73): each failed probe pins what it missed; the op's set is finite. Lazy open: warm ops pay nothing. Memory: bounded by held ops (one per PG head, EC front write, own-shard reads), outside the envelope (soft). Client gate ops (opexec) do not lease yet (OQ below).

### Gate order and wakes
- Order is per object (arrival order of one object's ops), not per PG. Invariant: inflight < waiters | parked < gate (except pure reads past a write gate, am. 22). `Engine::retry` scans the whole gate, <= 64 cold probes per call (`RETRY_PROBES`), resumed next iteration (`retry_from`, am. 23): an op runs unless cold or an earlier gated op of the same object (hash, oid, nspace, key; key == oid = empty key) orders before it: two pure reads (`pure_read`: read-only ops, no RWORDERED) never do, of any sessions (spec client-ops 5.5, 5.7 step 9, 5.12; am. 21); PG-level ops (empty oid) never pass. `on_op` lets a warm op bypass a non-empty gate only when `cold_only` (PG active + readable, no `parked_obj`, no live backoff, gate <= 64) and no gated op orders before it. Otherwise strict gate order.
- The parked-ops pass re-inserts an object's later parked ops right behind the re-gated op, ahead of the object's ops already in the gate; its EC warm shortcut is not taken while older ops of the object wait behind in-flight writes; `drain_obj` moves remaining waiters to parked when an op of the object parks again (pure reads past a write gate stay). Failsafe full drops write-ordered ops, RWORDERED reads included.
- Write-only gates (am. 22): while an object's first parked op waits only at a write gate (not started: degraded / backfilling on a peer, scrub write block), pure reads pass it and the object's later parked ops; they still wait for writes in flight and their own gates. Rule and gate table: spec client-ops 5.12, `Parked::write_gate`.
- Wakes carry tokens (u64: tree page (shard, addr) or prefetch run (shard, pba), `store::toks`). Probe side: `Store::cause_begin`/`cause_take`; `Tree::lookup` logs missed pages (`Tree::mlog`, bound 8), `pf_state`/`pf_submit` log the run. Wake side: `Shard::poll` emits `Event::Page(addr)`; generic `Event::Wake` for the rest; `Store::take_wake_set(toks, all)`; `take_wake()` (bool) unchanged. Overflow (cause > 8, batch > 32) = unnamed / `all`.
- Op side (`peering::wake`, `opexec::Engine`): `waits: (conn, tid) -> Cause` + token index (`Waits`). `retry_woken(&WakeSet)` skips ops whose cause the wake does not name; an EC read waits for the shard read covering it (`ec_rd_tok`) or the object's write (`ec_tok`); unnamed ops and `all` (state change, EC wake, 1 s tick, overflow, other store wakes) probe as before. `on_op` probes only the new op (+ unnamed). `pg_post` passes the accumulated `WakeSet` (`PgHost::wake`, `PgHost::store_woke`). Counters `Counters::{wake_probes, wake_skips, wake_all}`. Tokens are the only path (`NV_WAKE_ALL` removed).
- No lost wake-up: an entry is dropped whenever the gate loop cannot probe it while its wake is consumed (not active/readable/admission, beyond probe bound, behind same-object op, deferred by scan batch); `reset`, blocklist drop, full gate remove entries; non-page/pf wakes are `all` (resident-without-completion, `pump_wants`); the 1 s tick wakes everything (`wake_all` must stay 0 rescues in sim).
- Unindexed (unnamed, probed every wake): shard Busy, dirty-hard, WAL full, admission, EC/peer waits.
- Warm probes (`Store::warm`, `warm_data`, `warm_rm`, `warm_omap`, `warm_clone_src`) never latch the run refusal: `Store::parked_on` is a pure check (a stale `blocked` / `rm_progress` flag dropped the re-run: history am. 8). `visibility` (executor reads) sets refusal + flags; `take_blocked` means "a read of THIS run was refused".
- The object state load of an execution (`load_state`: `_` + `snapset`) runs non-blocking like the run (am. 16): a cold onode / attribute page refuses the load, the op re-gates named by that page (`Engine::refused`, shared with a refused run, same `MAX_SCAN_TRIES` bound). `Store::warm` probes `snapset` too. Rationale and numbers: history am. 16.
- Wake diagnostics: `wake_diag` (lab) must report 0 tick rescues in sim runs; lab `NV_PHASE=1` prints `phase_ms`, `phase_long_ms`, `xmsg`, `op_lat`, `store_sync` at exit and a ~1/s `sendq:` connection trace.

### Store crc, buffers
- Stored per-block crc32c (seed = block address) are combined into the crc32c (seed !0) of the returned bytes without touching data (`crc::crc32c_blocks`). `Store::read_crc` returns it when the range is whole blocks, fully verified, no overlay. Carried as `CrcHint` on `OsdOp::outdata` (pointer+length checked, excluded from equality), `MOSDOpReply::data_crc_hint` (single data-carrying op), `msgr2::Message::data_crc`, used by `encode_message_zc` (crc mode, zero-copy segment only; secure mode and small data unchanged).
- A read result buffer is not zero-filled: `read_committed` writes every byte into `MaybeUninit` (`crc32c_copy_uninit`); the same for scrub, extent values and the deep-check run reader.
- Read data by reference (am. 13): client reads (`READ`, `SPARSE_READ`) use `Store::read_shared` -> `Stage::read_eff_shared`: the result is pieces `(Bytes, crc)` in order. Every device command buffer (sync or rolling read) and every prefetch run served whole becomes a piece as is (`IoBuf::into_shared`: the DMA buffer is the `Bytes` owner, immutable by type); its block crcs are computed in place (`crc32c`, no copy) and verified against the stored crcs like the copy path (mismatch = `Eio`, `crc_errors`). A prefetch run covering a command only partly is copied into a piece of its own. Holes are zero pieces; an unaligned start / tail is a slice (crc unknown). A cached run shares its bytes with the reply that filled it and every later read. Copy path (one piece) for compressed chunks, inline objects, a txn overlay, planning, and layouts whose device pieces average < `SHARE_MIN_AVG` (64 KiB; candidate `msgr2::ZC_MIN` = 8 KiB pending the knet A/B with fragmented objects, `lab/baremetal/read4m-ab.sh`; revert = the constant; many small iovec entries per frame on knet not measured end to end): the encoder copies a segment below 8 KiB into the frame anyway. Shared buffers held by reply queues / sends / the data cache are counted: `nvme::shared_pinned()`, `dump_mempools` pool `read_shared`. Numbers: history am. 13.
- Small reads of cached data (am. 17): a read below `SHARE_MIN_AVG` whose range is one plain device piece held whole by the data cache goes by reference too (a slice of the cached run, block crcs from the cache, verified against the stored ones as on every read): the encoder copies a segment below `msgr2::ZC_MIN` into the frame anyway, so the store copy and its buffer were a second copy of the same bytes. Other small reads keep the copy path, which reuses the extents the share check resolved (no second lookup). The probe (`warm_data`) of such a read leaves its resolved piece (object id, size, piece with crcs) in a single-use per-shard hand-over (`HotProbe`) that the read right after it takes instead of repeating the name lookup and the extent scan; it is valid only for the same collection / object / offset / length and only while the shard has submitted no txn since (`next_lsn` unchanged): every change of extents, frees and removes goes through a submit. Numbers: history am. 17.
- The pieces travel by reference to the wire: `OsdOp::{outdata, outdata_more}` (`set_outdata_parts`; writes flatten in `Exec::finish`, they may be logged), `MOSDOpReply::encode_parts` -> `msgr2::Message::{data, data_crc, data_more}` (crc mode rev 2.1: by reference, segment crc joined from the piece crcs; secure / rev 2.0: pieces copied straight into the frame). Sparse read: the 24-byte header is a piece in front of the data pieces.
- Pooled device buffers dropped by another core (the reply's sender) return to the allocating thread through a lock-free per-owner inbox (`nvme::shelf`: one stack head per owner thread, MPSC, the owner takes the whole chain at its next allocation and hands it to its own pool, which applies its byte cap; no slot or byte limit in the inbox; list link and pool key live in the parked block; a retired owner refuses pushes and the dropper pools or frees). kdev arena keyed by bin; SPDK keyed like `dmapool` (exact bin <= 1 MiB, large class up to 128 MiB); drained with the pools on memory pressure. RDMA registration of payload memory: adr 0469.

### No per-op O(PGs)
- `peering::PgMap` keeps an ordered per-PG deadline index (`next_deadline`/`due`) refreshed only for PGs mutably accessed since the last query, and a touched-PG list for engine sync. The OSD keeps `eng_parked` (engines with parked work) and `eng_due` (engine deadlines, ordered), updated by `PgHost::eng_note` after every engine run.
- `RealMap` (per epoch, from an immutable `OsdMap`) memoizes `pg_mapping` per PG; a new epoch / pool / pg_num is a new `RealMap` (invalidation by construction); bounded by the PG count. Every outbound PG message is still validated (`spg_violation`) against the memo. One path for rep and EC. OSD per-op callers use `pgs::cur_mapping` (CRUSH when the asked epoch differs); full-pool scans use `pg_to_up_acting`. `MapHandle` = `Rc` (per core, memo in `RefCell`). Debug builds assert each memo hit against a fresh CRUSH run.

### Hashing, clock
- Hot maps use `foldhash::fast::RandomState` (opexec `FastMap`: engine `objs`/`by_reqid`, backoff conns, storeadapt `inflight`, osd engines, peers, links, peering reply cache). The store's engine-generated address maps keep `FxHasher` (keys not attacker controlled).
- One clock read per loop iteration: `store::fastclock::Mono` (TSC, origin resolved once; replaces vDSO `clock_gettime`) in `MonoClock` (`Store::poll` every iteration), `core_loop`, `pg_core`; `rt` re-exports `fastclock`.

### EC RMW (legacy plan)
- Warm sub-reads (always on; the `ec_rmw_warm` switch was removed, am. 20): our stash blocks are prefetched with the read; shards the direct read does not ask (parity) get a `MOSDECSubOpRead` of the same shard range, reply dropped (`warm_tids`; forgotten when a map shows the peer down or restarted or its session is lost, adr 0049 am. 9), only to known croit-flashstore-osd peers (`Pg::nv_peers`, `PgSet::set_flashstore_peers`); degraded reads warm nothing. Stash probes use `warm_clone_src` (stash shares blocks, adr 0021 am. 38).
- Covered-chunk skip (always on; the `ec_rmw_skip_covered` switch was removed, am. 20): a legacy write whose txn holds only plain writes + attr ops (`write_cover`) asks (`ec_start_reads`, `ec_rmw_want`) only the data shards whose chunk is not fully covered in some stripe of the span, only when every shard is up at its member; old stripes are rebuilt chunk-wise with unread chunks zero (`rmw_interleave`, direct plans); a shard failing mid-read turns it into a whole-stripe read. Wire unchanged.

## Rationale

A read as park-at-gate + prefetch keeps the object layer synchronous for callers (the park protocol existed for tree pages, adr 0021 am. 8). Token wakes and per-object order bound CPU per wake to the ops actually resolved. Numbers: history (doc not in the source snapshot).

## Consequences

- + Reads never block the core: throughput is CPU bound and QD-scalable; per-op CPU independent of PG count; 4M read drops one memset and one crc pass.
- - Up to 8192 blocks (32 MiB) DMA memory per shard held by prefetch + data cache; a prefetched run is read before its op executes (extra read if the op is dropped, bounded by TTL).
- + Re-reads of recently read blocks (one hot object, EC stash) need no device read, no prefetch round trip and no gate wait (history am. 15).
- - Cache coherence rests on one rule: every free of data blocks passes `forget_freed` at txn submit (store.rs submit paths, defrag). A new path that frees data blocks must call it.
- - The crc hint is only as good as the stored block checksums (verified in the same pass).
- - EC RMW warm costs one extra sub-read + reply per small RMW to croit-flashstore-osd parity shards.
- + Plain reads need no CPU copy of the payload on the OSD (am. 13): one in-place crc pass per byte (verification), DMA buffer -> wire by reference.
- - Read DMA buffers stay out of their pool until the reply is sent (before: the result buffer); many concurrent large reads can exhaust the kdev arena (fallback: heap buffers, functional).
- - Not done: engine-level batching of tree walks (warm + read walk twice), per-link loops in `Osd::pump`/`next_timer` (O(links), ~6 ns/link/op), O(G) gate walk of the hit op.

## Alternatives

- async/await or continuation-style store `read`: every caller of the object layer would change.
- Prefetch into a per-op buffer handed to the read: ties lifetime to the engine.
- Pointer-keyed global crc side table: stale-address hazard.
- Merging nearby runs across gaps (`pf_merge`): measured neutral on random overwrites, removed.
- Lab switch `NV_WAKE_ALL`: A/B lost, removed.

## Open questions

- Tokens for unindexed causes (Busy, dirty-hard, WAL full, admission, EC/peer waits): one token per class instead of `all`? Not measured.
- OSD-level A/B of wake tokens on hardware (omap 8x64) not run; sim only.
- Aged r4m-q4 (concurrent fragmented reads) not measured on EC pools.
- Connection balance across cores: knet done (adr 0053 am. 1); DPDK parked (adr 0005 am. 2).
- Client gate ops (opexec `Engine`): leases for parked ops would remove the PF_WAIT_NS waiter drop and the 1 s re-probe safety net (am. 18); their refused runs keep the `MAX_SCAN_TRIES` blocking fallback (listing / range working sets can exceed the page cache: pinning is no bound there).
- Data cache capacity is the prefetch DMA cap (32 MiB/shard), not derived from `osd_memory_target` (BlueStore sizes its data cache from the target); the connection work on a hot PG's core (OQ 98, OQ 105).
