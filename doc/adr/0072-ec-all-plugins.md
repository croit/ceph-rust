# 0072 EC plugin family: every classic plugin/technique served, bit-exact
Status: accepted (2026-10-13). Extends adr 0039 (gate), 0048 (GF math), 0049 (primary role).

## Decision
- Goal: no EC pool a classic OSD of Ceph main can create stays inactive on croit-flashstore-osd (mixed clusters). The gate (`ec::evaluate`) declines only what is not implemented; every implemented plugin leaves the decline list when its vectors pass.
- One abstraction: `ec::Code` (enum, static dispatch): `Rs` (byte-wise GF(2^8) matrix: isa, jerasure reed_sol_van/r6_op w=8), `Bit` (jerasure bit-matrix XOR codes), `Lrc` (layers of `Code`, non-MDS), `Shec`, `Clay` (coupled-layer, per-stripe codewords: `Code::set_chunk`). RAW chunk indices (0..k data, k..n rest), shard mapping stays in ecback. API: `encode`, `decode_into(have, want, out)`, `read_set(want, avail)` (= minimum_to_decode, full chunks), `unit()` (chunk-length granule).
- `ecback::Backend` builds its code from the pool profile map (`EcFacts.profile`, `EcPoolInfo.profile`), plans reads through `Code::read_set` (no "any k" assumption in ecback), decodes with the set `read_set` returned.
- Gate: chunk (= stripe_width / k) must be a multiple of 32 and of `Code::unit()` (jerasure bit-matrix: w * packetsize). Optimized EC stays isa + jerasure reed_sol_van only.
- Specs (own words, from Ceph source): spec/ec.md 4, ec-jerasure-bitmatrix.md, ec-shec.md, ec-lrc.md, ec-clay.md. Impl from spec only.
- Oracle: `ceph-erasure-code-corpus` is a TEMPORARY dev oracle (`crates/ec/tests/oracle/corpus-oracle.sh <dir>`, test is #[ignore]d). Every plugin ships own frozen vectors in the repo (`crates/ec/tests/frozen_*.rs`, unit tests) that stand alone.

- am. 1 (2026-10-30): the `sc % 64 == 0` primary gate is removed. Classic <= 21.1.x wrote wrong parity for sc % 64 == 32 (spec ec-clay.md 0.2); Ceph 21.2.0 (pinned) fixed it and our encode matches classic 21.2.0 on those shapes (frozen vectors). User decision: 21.1.x was lab-only, no compat for classic 21.1.x peers, so croit-flashstore-osd is primary for those profiles.
- am. 2 (2026-10-31, EC parity, spec ec-parity.md, oracle `testdata/ec-parity/`): the gate follows what a v21.2.0 mon can create. Profile ints use the classic strtoll grammar (`k=+2`, `k=02`); `stripe_unit` is never read; plugin aliases `jerasure_*` / `shec_*` = jerasure / shec; isa k > 32 only refused for reed_sol_van (also the clay isa sub-code); shec k = 1 served; min_size literal (any value); no `chunk % 32` rule, only `chunk % Code::unit()` (codecs, ecback writes/RMW/degraded reads/hinfo verified at units 1 and 28 and against the classic liberation w=7 chunk 4144). lrc k/m/l = -1 (mon write-back) = unset: explicit-layer profiles served. shec ignores `mapping` (identity placement on primary and shard role). Mapping completion (spec 3.2: D positions then the rest, cut / identity-extended to n; no bijection = passive); legacy isa/jerasure/clay with non-identity M' run the classic literal index sequence (`ec::placed::Placed`), lrc layers may code into data positions (literal layer order); unassigned input slots are zeros (classic: uninitialised memory). Optimized pools keep mapping = placement only.

## Live recovery / backfill (2026-10-13, lab/docker/mixed/16-ec-recovery.sh, isolated cluster laba-, 3 classic + 4 croit-flashstore-osd, croit-flashstore-osd preferred primary)
Per pool lrc (k2 m2 l2), shec (k3 m2 c2), clay (k3 m2 d4): stop classic osd.0 / croit-flashstore-osd.3, write, start (log recovery); `osd out` of each (backfill onto the spare); after every step md5 of all objects + deep scrub clean. 80/80 checks, 0 classic restarts/aborts. clay: sub-chunk repair path ran (56 objects, `clay repair of shard` note). Not covered by the case: a re-map of two shard positions at once in pools with m = 1 or shec c = 1 (recovery sources exclude strays, open question 33).
Follow-ups done in this step: jerasure reed_sol_van / r6_op w=16/32 (`ec::wide`, byte-exact vs classic v21.1.1 `ceph-erasure-code-tool`, `tests/oracle/wide-oracle.sh`, `tests/frozen_wide.rs`), clay repair wired into primary recovery (`Backend::plan_repair`/`repair_shard`, single target shard, whole-chunk fallback), clay scalar shec m=2 primary (byte-exact vs classic), shard-only reasons documented, no shec-specific min_size in the mon (peering uses the code predicate).
