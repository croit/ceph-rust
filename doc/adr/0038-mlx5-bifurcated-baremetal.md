# 0038 mlx5 bifurcated PMD on bare metal (first real-PMD bring-up)
Status: superseded by adr/0682-remove-afxdp-dpdk-networking.md (was: accepted)
Date: 2026-10-10
Context: first croit-flashstore-osd on bare metal with a real PMD (ConnectX-4 100G, host icelake-6330-host2, results doc/perf/icelake-6330-host2-baremetal.md, scripts lab/baremetal/). Everything before ran on virtual PMDs / AF_XDP / VFs. mlx5 is bifurcated: the kernel mlx5_core stays bound (no vfio for the NIC, NVMe stays on vfio-pci), the PMD drives queues through verbs, the kernel keeps netdev + other traffic.
Decision:
- Build: DPDK 26.07 with `net/mlx5,common/mlx5,bus/auxiliary`, `-Dibverbs_link=shared` (static DPDK, shared rdma-core). rdma-core bundled in `/opt/croit-flashstore-osd/lib` (libibverbs, libmlx5 + provider `libmlx5-rdmav34.so`, libnl), run with `LD_LIBRARY_PATH`; nothing installed on the host. Same glibc (Debian 13) on build VM and host.
- Port = PCI address (`flashstore_port_name = flashstore_vf_pci = <bdf>`), kernel netdev only needs to be UP (no address, IPv6 off). MAC = netdev MAC. `-a <nic> -a <nvme>` allow-list (already required, adr 0034).
- RSS: mlx5 reports its redirection-table size only after `rte_eth_dev_configure` (pow2 of the queue count). `Port::start_mq` builds the `net::rss::Rss` model from the post-configure size; the shim programs the round-robin table only if the driver's differs. Verified live: `Stats::steer_syn_ok/miss` (SYN / SYN-ACK of every flow checked against the model; miss must stay 0).
- Multi-queue ARP/NDP: RSS hashes TCP only, so ARP replies land on queue 0 whichever core asked. (a) `net::neigh::SharedNeigh` (RwLock table, one per port, written on learn, read on a local miss and at the 20 ms retry) shared by all core stacks; (b) a passive SYN from an on-link peer teaches the stack the peer's MAC (source MAC of the SYN = next hop of the SYN-ACK), no ARP round trip. Replaces the static `--neigh` workaround for multi-queue.
- Non-EAL core threads call `rte_thread_register` (`net::dpdk::register_thread`) so mempool per-lcore caches work; without it every mbuf alloc/free hits the shared ring (atomic ping-pong between cores).
- Payload buffers in DPDK memory: `net::dpdk::HugeAlloc<A>` global allocator: allocations >= 128 KiB come from the EAL heap after the EAL is up (frees dispatch on the address), small ones stay in mimalloc. A heap `Bytes` that lies in EAL memory is attached to tx mbufs as an external buffer (mlx5 registers EAL memory on demand): the 4 MiB read reply is no longer copied into pool mbufs (adr 0033 open item). Heap buffers outside EAL memory keep the copy path.
- Isolated mode (several OSD processes per port, kernel keeps the rest): `NV_FLOW_IP=<our ip>` puts the port in `rte_flow_isolate` mode and installs `ETH/IPV4 dst=ip/TCP -> RSS(queues, KEY_MS)`; `NV_FLOW_ARP=1` (exactly one process per port) adds `ARP -> queue 0`. Other processes of the port set only their own `NV_FLOW_IP` and rely on SYN-learned neighbors + `--neigh` for peers they dial.
- Diagnostics (exit report per core): `busy_ms` (wall time of loop iterations that did work, no extra clock read), steer counters, `tso_super/tso_segs`, tx copy/zero-copy bytes, port xstats (per-queue packets, `rx_out_of_buffer`, `tx_phy_errors`).
Amendment (adr 0052 am. 2): the mlx5 PMD is now part of the single production binary with rdma-core linked static (adr 0052 am. 5; the am. 2 dlopen glue is gone, no bundled-lib variant); the text above is the first bring-up.
Consequences: + works on a production host without touching its NIC config; + multi-queue needs no static neighbors; - ARP-owner process per port in isolated mode (single point for ARP only); - HugeAlloc ties large allocations to EAL hugepage budget (`flashstore_hugepages_mb` must cover payload buffers in flight); - rdma-core is a runtime dependency of the production binary on mlx5 hosts.
Alternatives: vfio-pci on the CX-4 (loses kernel netdev, no sharing); DPDK secondary processes (one process owns the port: breaks per-OSD isolation); per-OSD MACs via MAC filters (needs switch/learning care, deferred); registering heap memory with `rte_extmem_register` (needs every allocation path to be registered; the allocator split is simpler).

## Amendment 2026-10-12: 802.1Q internal net, several OSDs per PF, rented 3-host bench (lab/rented/multi, NET=dpdk|afxdp)
- VLAN: no NIC offload. The stack inserts/parses the tag in software (`flashstore_vlan = VID`, `Config.vlan`; TSO/csum offload see l2_len 18); `rx-vlan-offload` must be off on the PF for AF_XDP (the kernel strips the tag before XDP otherwise), irrelevant for the mlx5 PMD (no VLAN_STRIP requested). Isolated-mode rule with a tagged net: `NV_FLOW_VLAN=VID` adds `VLAN vid` to the pattern: ETH / VLAN / IPV4 dst / TCP -> RSS (shim.c). Without it only untagged frames match.
- Per OSD: own IP on the VLAN iface; no ARP steering. The kernel owns the IP as a secondary address (`noprefixroute`, same MAC as the PF) and answers ARP/ping; TCP to it is taken by the NIC rule before the kernel sees it. ARP replies to the OSD land in the kernel, so the OSD gets static neighbors (`flashstore_neigh`: every host IP and OSD IP -> that host's MAC). Peers on the same host reach each other via NIC local loopback (same MAC, `disable_local_lb_uc` = 0 default; UNVERIFIED on the rented CX-5, check first). Kernel -> own alias IP is local (mgr/mon -> own-host OSD IP is refused; OSD -> mon/mgr of the same host needs the loopback).
- AF_XDP: XDP attaches to the whole PF, the default program redirects every frame of a bound queue. Layout: queues 0..kq-1 (kq = 2, kernel) get the default RSS (`ethtool -X equal kq`), OSD k owns queues kq+8k..kq+8k+7 = its cpus (IRQ i -> cpu CPU0-kq+i); `ethtool -X hkey KEY_MS context new start S equal 8` + `ethtool -N flow-type tcp4 dst-ip IP context C` per OSD (needs mlx5 RSS contexts in ntuple rules; fallback `XDP_SINGLEQ=1`: one queue per OSD via `action Q`). Copy mode (force_copy=1) by default: zero copy (`afxdp-zc`) crashes with several connections (doc/perf/net-tiers-baremetal.md finding 4).
- Runtime: build `MLX=1 lab/rented/build.sh build` (DPDK 26.07 with mlx5 + af_xdp, /opt/dpdk-both on build host, glibc <= 2.38), rdma-core 56.1 + libxdp + libbpf + libelf (first bring-up: bundled by a script into /opt/croit-flashstore-osd/{lib,etc}, since removed; now static in the binary, adr 0052 am. 5).

## Amendment 3 (2026-10-15): AF_XDP RSS model check, zc on CX-5, VM lab tier
- mlx5 on kernel 6.12 (icelake-6330 VMs, CX-4) does not hash like `net::rss` (Toeplitz KEY_MS, `ethtool -x` notwithstanding): 60-85 % `steer_syn_miss` with several queues per OSD, active opens die on the wrong core (links fault Io, OSDs down). Kernel 7.0 hosts: 0 misses. Rule: multi-queue AF_XDP only where `steer_syn_miss` stays 0 (the stack logs the first 8 misses per core with flow/queue/model/hash); otherwise one NIC queue per OSD (`--queues 1`). doc/perf/afxdp-20261015.md.
- Zero copy on CX-5 (striding RQ): the rented collapse showed `rx_dup` (buffers delivered twice) despite the page pool; lab scripts turn `rx_striding_rq` off for `afxdp-zc` (restored on down). Unverified on CX-5 (OQ 42).
- VM lab tier: `lab/baremetal/xdp.sh` (layouts all/ctx, NQ, IRQCPU).
